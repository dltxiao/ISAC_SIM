# 通信层语义级拓展详细设计（方案1）

> 设计对象：ISAC-SIM v0.2.0 + [通信层扩展评估](09-通信层扩展评估.md)  
> 分支：`feature/comm-layer-extension`  
> 设计日期：2026-10-27  
> 范围：语义级 5G-A 核心网（AMF/SMF/UPF/NEF/UDM/AUSF）+ 车联网业务平台（API/IAM/订阅/调度/审计）  
> 不包含：Open5GS/UERANSIM、真实协议栈、pcap/DPI、PC5 协议级、真实 V2X 平台部署

---

## 0 设计摘要

### 0.1 目标

在不破坏现有 A1–A4 剧本、500+500 评估口径和单机确定性约束的前提下，补齐“网络层”和“应用层”，使环境能够：

1. 产生可观测、可关联的核心网与平台事件；
2. 支持 A5–A10 跨域攻击链，以及 A1–A4 的“端—网—云”升级版；
3. 支持 `隔离—阻断—恢复` 的防御动作与防御时延测量；
4. 把评估从“事件级”扩展到“事件级 + 链级”；
5. 为外部检测系统提供稳定的结构化事件接口（JSONL/Parquet/Kafka/NetFlow），不承诺 pcap/DPI。

### 0.2 关键设计决策

| 决策 | 选择 | 理由 | 备选 |
|---|---|---|---|
| 核心网实现方式 | 进程内状态机 + 队列 + 消息总线 | 单机、确定性、可批量、无 root | Open5GS/UERANSIM（方案2，仅点验） |
| 事件粒度 | 1–10 Hz 事件级，不做 per-packet | 足够表达信令/会话/QoS/路由攻击，数据量可控 | 包级仿真（过重） |
| 数据契约 | `isacsim.record/2` + `truth/2`，保留 v1 读取 | 新增 `core./app./defense.` 流和 `trace_id`，不破坏旧数据 | 直接在 v1 上加字段（正则不允许） |
| 因果关联 | `trace_id` + `span_id` + `parent_span_id` + `chain_id` | 支持跨层串联和链级评估 | 仅靠时间戳（易错） |
| gNB 定位 | 先升级为 RAN 节点，再加核心网 | 避免“假 gNB 上面叠假 5GC” | 直接加 core（根基不稳） |
| 平台边界 | 只做 API/IAM/订阅/调度/审计，不做真实业务全量 | 够做 A8/A9，成本可控 | 接真实平台（依赖外部） |
| 评估 | 事件级 + 链级双轨 | 回应“攻击链识别”而非仅“事件识别” | 只做事件级（评审风险） |
| 时延 | 快路径 + 链确认双口径 | 100 ms 指标与多源凑窗分离 | 单一口径（容易被质疑） |

### 0.3 成功标准

| 编号 | 标准 | 验证方式 |
|---|---|---|
| S1 | A1–A4 的 500+500 结果不劣化 | 同种子回归，识别率/误检率/时延对比 |
| S2 | 新剧本 A5–A10 在包络内识别率 ≥99% | 每类 ≥125 事件，Wilson 95% CI |
| S3 | 新正常集误检率 ≤1% | ≥1000 正常场景，含新层难负样本 |
| S4 | 快路径 P99 ≤100 ms | 记录进入检测器到告警 |
| S5 | 每个 truth domain 都有对应流记录 | 静态/集成测试 |
| S6 | 每个新剧本覆盖 ≥3 个域 | truth 校验 |
| S7 | 数据量增加 ≤30% | 60 s/60 车基准 |
| S8 | 同种子输出可复现 | 解压后逐字节比较 |

### 1.1 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | 模拟 AMF/SMF/UPF/NEF/UDM/AUSF 的注册、鉴权、PDU 会话、QoS、切换、API 订阅等过程 |

| FR-3 | 产生 `core.*`、`app.*`、`defense.*` 观测流，字段足以支撑跨源关联 |
| FR-4 | 支持 A5–A10 新剧本，并支持 A1–A4 的端—网—云升级 |
| FR-5 | 支持防御动作：AMF 拒绝、SMF 释放、UPF 阻断、NEF 吊销、平台吊销、车辆降级 |
| FR-6 | 真值包含 nodes/domains/stages/causal_chain/chain，检测侧不可读 |
| FR-7 | 图快照包含 RAN/core/platform 节点与边 |
| FR-8 | Web 可查看核心网/平台状态、统计、链、防御动作，并可注入新攻击 |

### 1.2 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | 单机运行，不引入外部服务、真实 socket、root 依赖 |
| NFR-2 | 确定性：同种子、同配置输出一致；RNG 按 NF/流派生 |
| NFR-3 | 性能：60 s/60 车场景 ≤25 s；1000×15 s 批处理 ≤5 min |
| NFR-4 | 兼容：旧 run 可读；旧 A1–A4 结果可复现 |
| NFR-5 | 可观测：每个 NF 有队列/时延/拒绝计数；每个平台 API 有 QPS/错误率 |
| NFR-6 | 真值隔离：`isacsim/detect/` 不导入 `isacsim.truth` |
| NFR-7 | 可测试：每个过程有单元测试；每个攻击有集成测试 |
| NFR-8 | 可扩展：新增 NF/事件类型不需要改主循环 |

### 1.3 明确不做

- 不实现 NAS/NGAP/PFCP/GTP-U 的 ASN.1/二进制编码；
- 不实现 SCTP/GTP-U/TLS 协议栈；
- 不生成可用于 DPI 的 pcap；
- 不覆盖 PC5 协议级；
- 不实现真实 V2X 平台的全量业务；
- 不实现 NWDAF/RedCap/NTN/ISAC 的 5G-A 特性；
- 不把语义层替换成 Open5GS/UERANSIM。

### 2.2 单步顺序

`Simulation.step_once()` 调整为：

```text
1. sumo.step()
2. 读取车辆状态
3. scheduler.tick(ctx)        # 攻击先注册钩子/设置 extras
4. sensing.tick(ctx)
5. v2x.tick(ctx)              # PC5
6. uu.tick(ctx)               # RAN 附着/切换/会话
7. core.tick(ctx)             # 核心网过程
8. auth.tick(ctx)             # 边缘证书/指纹
9. platform.tick(ctx)         # 平台 API/订阅/调度
10. control.tick(ctx)         # 消费 sensing + platform intents
11. task.tick(ctx)
12. edge.tick(ctx)            # 分层图快照
```

顺序理由：

- 攻击调度在感知之前，保证本步钩子/参数立即生效；
- core 在 uu 之后，消费本步的 RAN 状态；
- platform 在 core 之后，消费本步的核心网/消息状态；
- control 在 sensing/platform 之后，消费被篡改的感知和云控意图；
- edge 最后，聚合本步所有状态。

## 3 领域模型与标识

### 3.1 实体 ID

| 实体 | 格式 | 示例 |
|---|---|---|
| UE/OBU | `ue:<vid>` | `ue:eastbound.4` |
| gNB | `gnb:<id>` | `gnb:GNB-01` |
| AMF | `amf:<id>` | `amf:AMF-01` |
| SMF | `smf:<id>` | `smf:SMF-01` |
| UPF | `upf:<id>` | `upf:UPF-01` |
| NEF | `nef:<id>` | `nef:NEF-01` |
| UDM | `udm:<id>` | `udm:UDM-01` |
| AUSF | `ausf:<id>` | `ausf:AUSF-01` |
| PCF | `pcf:<id>` | `pcf:PCF-01` |
| NRF | `nrf:<id>` | `nrf:NRF-01` |
| 平台 | `platform:<id>` | `platform:V2X-01` |
| 租户 | `tenant:<id>` | `tenant:city-a` |
| 令牌 | `token:<id>` | `token:tok-0001` |
| 会话 | `session:<id>` | `session:ps-0001` |
| 流 | `flow:<id>` | `flow:fl-0001` |

**规则：**

- 不用随机 UUID；用 `run_id + 计数器 + crc32` 生成稳定 ID；
- 实体 ID 进入 `Record.entity` 或 `payload.ue_id`，不写真实 SUPI/IMSI；
- `supi` 用假值（如 `00101...`），不写真名/真实号码。

### 3.2 Trace / Span / Chain

```python
@dataclass(frozen=True)
class Trace:
    trace_id: str          # 一次过程/一次攻击链
    span_id: str           # 本条消息
    parent_span_id: str | None
    chain_id: str | None   # 攻击链 ID；正常过程为 None
```

- `trace_id` 在一次注册/PDU/切换/NEF 订阅开始时生成；
- `span_id` 每条消息生成，`parent_span_id` 指向触发它的消息；
- `chain_id` 仅攻击注入的事件携带，等于 truth 的 `event_id`；
- 正常流量也可以有 `chain_id=None`，避免泄漏标签。

### 3.3 时间模型

| 字段 | 含义 |
|---|---|
| `ts_ns` | 仿真时间：`T0_NS + t * 1e9` |
| `t_wall_ns` | 记录发射的单调时钟，仅用于时延 |
| `payload.latency_ms` | 该事件在 NF/平台内部的排队+处理时延 |
| `payload.due_t` | 仅内部消息总线使用，不落盘 |

**规则：**

- 状态推进只用 `ctx.t` 和 `ctx.step_s`，不用 wall clock；
- 同一步内的事件按 `(due_t, seq)` 排序，保证确定性；
- wall clock 只进入 `Record.t_wall_ns`，不参与决策。


## 5 核心网语义模型

### 5.1 基类

```python
class NetworkFunction:
    name: str
    capacity_per_s: float
    queue_capacity: int
    base_latency_ms: float
    state: dict
    queue: deque[Message]
    metrics: NFMetrics

    def enqueue(self, msg: Message, now: float) -> bool: ...
    def tick(self, ctx, dt: float) -> None: ...
    def handle(self, msg: Message, ctx) -> None: ...
    def emit(self, ctx, stream: str, entity: str, payload: dict) -> None: ...
```

**约束：**

- `handle` 不阻塞、不 sleep、不发真实网络；
- 所有状态变化通过 `state` 和 `CoreBus.send` 完成；
- 过载时按 `queue_capacity` 丢弃并 emit `cause=...`；
- 每个 NF 有独立 `rng_for(seed, f"core:{name}")`。

### 5.2 消息总线

```python
@dataclass(order=True)
class Message:
    due_t: float
    seq: int
    src: str = field(compare=False)
    dst: str = field(compare=False)
    msg_type: str = field(compare=False)
    payload: dict = field(compare=False)
    trace: Trace = field(compare=False)
    attempt: int = field(default=0, compare=False)

class CoreBus:
    def send(self, msg: Message) -> None: ...
    def dispatch_until(self, t: float, ctx) -> int: ...
    def pending(self) -> int: ...
```

**规则：**

- `due_t = now + latency`；`latency` 由 NF 的 base + queue 计算；
- 同一 `due_t` 按 `seq` 排序；
- 投递失败（queue full）时 emit `result=reject/cause=...`，不抛异常；
- 支持 `drop`/`delay`/`duplicate`/`modify` 四种注入钩子。

### 5.3 AMF

**状态：**

```python
@dataclass
class UEContext:
    ue_id: str
    supi: str
    gnb_id: str
    state: str            # REGISTERED / CM_CONNECTED / AUTHENTICATED
    allowed_snssai: list[str]
    amf_ue_ngap_id: int
    last_seen: float
```

**过程：**

| 过程 | 输入 | 处理 | 输出 |
|---|---|---|---|
| 注册 | `registration_request` | 检查 UE 数/队列 → 调 AUSF/UDM → 建上下文 | `registration_accept` 或 `reject(cause)` |
| 服务请求 | `service_request` | 检查注册态 | `service_accept` 或 `reject` |
| 切换 | `handover_required` | 选目标 gNB → 发 `handover_request` | `handover_command` |
| 释放 | `ue_context_release` | 清理上下文 | `release_complete` |

**容量：**

```text

amf_queue = 1000
amf_base_latency_ms = 2.0
```

**过载：**

- 队列 > 80%：`registration_reject(cause=22, "congestion")`；
- 队列满：直接丢弃并计数；
- 记录 `queue_depth`、`latency_ms`、`reject_rate`。

**攻击面：**

- 注册洪泛（A5）；
- 伪 gNB 切换风暴（A11）；
- 鉴权失败放大（A4 升级）。

### 5.7 UDM / AUSF

**UDM：**

### 5.9 核心网过程时序

**注册：**

**PDU 会话：**


### 5.10 核心网数据面与 PC5 边界

- **PC5**：仍由 `V2XLayer` 建模，CBR/PER/DCC 不变；

- 默认 `transport="pc5"`；A1/A6 可以选择同时打 PC5 和 Uu，truth `domains` 包含 `v2x`/`link`/`uu`/`core`；
- 不要用核心网模型替代 PC5 模型。

## 9 攻击与防御详细设计

### 9.1 A5 信令风暴→远控失控

| 项 | 内容 |
|---|---|
| 目标 | 用大量伪造/被控 UE 的注册/服务请求打满 AMF，导致 PDU 会话失败、远控指令老化 |
| 注入点 | `AMF.enqueue` 入口；`ue:bot-*` 生成器 |
| 参数 | `bot_ues = 20 + 180a`；`rate = 200 + 1800a` req/s；`duration` |
| 阶段 | ①注册洪泛 ②AMF 队列上升 ③PDU 建立失败 ④远控指令年龄上升 ⑤任务偏差 |
| 关键记录 | `core.nas`、`core.session`、`app.control`、`task.state` |
| 证据 | 注册速率、AMF 队列、会话失败率、指令年龄 |
| 真值 | `domains=[uu,core,app,task,control]`；`nodes=[ue:bot-*,gnb,amf,platform]` |
| 防御 | AMF 限流/拒绝；SMF 释放；平台降级 PC5 |
| 包络 | `rate >= 1000/s` 或 `bot_ues >= 100` |
| 变体 | 单 gNB/多 gNB；持续/脉冲；伪造 SUPI/真实 SUPI |

**时序：**

```text
t0        bot UEs 发 registration_request
t0+0.5s   AMF queue > 500
t0+1s     registration_reject(cause=22)
t0+2s     pdu_session_establish_fail
t0+3s     app.control age > 200ms
t0+5s     task.state deviation
t1        停止注入；AMF 队列恢复
```

### 9.2 A6 切片/QoS 抢占→CPM/AEB 降级

| 项 | 内容 |
|---|---|
| 目标 | 把 V2X 关键流的 5QI/GFBR 降级或耗尽切片，导致 CPM 丢失、AEB 晚 |
| 注入点 | `NEF/PCF/SMF` 的 QoS 修改接口；`core.qos` 输出 |
| 参数 | `5qi_from=79/80`、`5qi_to=9`；`gfbr_ratio=0.1–0.5`；`slice_util=0.8–1.0` |
| 阶段 | ①策略变更 ②QoS flow 修改 ③UPF/空口排队 ④CPM 丢失 ⑤AEB 晚 |
| 关键记录 | `core.qos`、`core.session`、`link.metrics`、`v2x.cpm`、`control.command` |
| 证据 | QoS 变更无工单、切片利用率、Uu 时延、CPM 丢失 |
| 真值 | `domains=[core,app,v2x,control]` |
| 防御 | PCF/SMF 恢复 QoS；切片隔离；RAN 预留 PRB |
| 包络 | `latency_increase >= 50ms` 或 `5qi_downgrade` |
| 变体 | 只降 QoS；只耗尽切片；两者叠加 |

### 9.3 A7 UPF/N6 劫持→伪造 CPM

| 项 | 内容 |
|---|---|
| 目标 | 把平台流量改到恶意 DN，注入伪造 CPM/DENM |
| 注入点 | `UPF` 路由表；`core.upf` 输出；`app.ingest` 来源 |
| 参数 | `redirect_ratio=0.1–1.0`；`evil_dn`；`forge_rate` |
| 阶段 | ①路由变更 ②平台收到伪造消息 ③provenance 不符 ④车辆制动 |
| 关键记录 | `core.upf`、`app.ingest`、`v2x.cpm`、`control.command` |
| 证据 | 流表路由、消息来源、CPM 与 RSU 不一致 |
| 真值 | `domains=[core,app,v2x,control]` |
| 防御 | UPF 回切；平台隔离来源；车辆忽略 |
| 包络 | `redirect_ratio >= 0.1` |
| 变体 | DNS 劫持；BGP/路由；UPF 被控 |

### 9.4 A8 NEF/订阅篡改→告警抑制/错误 SPaT

| 项 | 内容 |
|---|---|
| 目标 | 退订 DENM/SPaT 或改 callback，使平台看不到危险/信号相位 |
| 注入点 | `NEF` 订阅表；`app.subscription` 输出 |
| 参数 | `unsubscribe_events`；`callback_override`；`duration` |
| 阶段 | ①订阅变更 ②平台停止收到事件 ③缺失告警/错误相位 ④路口冲突 |

| 证据 | 订阅变更无工单、事件缺失、SPaT 与 RSU 不符 |

| 防御 | 吊销 token；恢复订阅；回退本地 RSU |
| 包络 | `unsubscribe_events >= 1` |
| 变体 | 只退 DENM；只退 SPaT；改 callback |

| 动作 | 层 | 目标 | 预期效果 | 风险 |
|---|---|---|---|---|
| `amf_deny_ue` | core | 恶意 UE | 注册拒绝 | 误伤正常 UE |

| `upf_block_flow` | core | 恶意流 | 阻断 | 误阻断 |
| `upf_route_restore` | core | UPF | 回切 | 短暂抖动 |
| `nef_revoke_token` | core | NEF | 订阅失效 | 正常租户受影响 |
| `platform_revoke_token` | app | IAM | 云控失效 | 业务中断 |
| `platform_quarantine_source` | app | Ingest | 隔离伪造源 | 漏报 |
| `ran_reserve_prb` | ran | gNB | 保 QoS | 容量下降 |
| `vehicle_fallback_pc5` | edge | 车辆 | 降级通信 | 功能受限 |

**`defense.action` 示例：**

```json
{
  "action_id": "def-0001",
  "chain_id": "EVT-...-ATK001",
  "layer": "core",
  "action": "amf_rate_limit",
  "target": "amf:AMF-01",
  "params": {"limit_tps": 2000},
  "result": "applied",
  "latency_ms": 3.2,
  "collateral": {"normal_ues_affected": 0}
}
```

**状态机：**

```text
DETECTED → DECIDED → EXECUTING → VERIFIED → RECOVERED
                    └→ FAILED
```

**指标：**

- 检测→决策时延；
- 决策→执行时延；
- 恢复时间；
- 附带损伤（正常 UE/租户受影响数）。

## 10 检测与评估设计

### 10.1 新规则

| 规则 | 输入 | 条件 | 抑制误报 |
|---|---|---|---|
| `nas_registration_flood` | `core.nas` | 注册速率 > 基线 3×，且 unique SUPI 异常 | 活动/散场白名单；持续窗口 |
| `pdu_session_failure_burst` | `core.session` | 失败率 > 30%，持续 3 s | 维护窗口；单 gNB 故障排除 |
| `qos_policy_drift` | `core.qos` | 5QI/GFBR 变化无 `change_ticket` | 工单/维护窗口 |
| `upf_route_drift` | `core.upf` | 路由哈希变化，且流量突增 | 主备切换白名单 |
| `nef_subscription_drift` | `core.nef` | 订阅 diff 无工单 | 合法变更窗口 |
| `platform_token_anomaly` | `app.audit`/`app.control` | token scope/issuer/age 异常 | token 轮换窗口 |
| `cloud_control_without_hazard` | `app.control` + `control.command` + `sensing.objects` | 云控制动但无 TTC 依据 | 真实急刹/施工 |
| `audit_gap` | `app.audit` | `audit_seq` 缺口 | 审计重启/迁移 |
| `chain_correlation` | 多流 | 多源时间/因果相关 | 链级置信度阈值 |

### 10.2 链构建器

```python
@dataclass
class Chain:
    chain_id: str
    nodes: list[ChainNode]
    edges: list[ChainEdge]
    stages: list[ChainStage]
    root_cause: str | None
    confidence: float
    t0: float
    t1: float
```

**构建步骤：**

1. 按 `trace_id`/`chain_id` 聚合记录；
2. 按 `parent_span_id` 补边；
3. 按时间/因果排序；
4. 合并同实体节点；
5. 计算置信度（证据数、跨源数、时间一致性）；
6. 输出 `chain` 对象，供评估/Web。

**约束：**

- 链构建器只读观测流，不读 truth；
- 链输出可以包含“缺失证据”标记，不强行补全；
- 链级告警与事件级告警分开存储。

### 10.3 时延

| 口径 | 起点 | 终点 | 用途 |
|---|---|---|---|
| 快路径 | `t_ingest` | 单条/短窗告警 `t_decide` | 主 KPI，≤100 ms |
| 链确认 | `t_onset` | 链输出 `t_chain` | 单列，反映多源关联 |
| 防御 | `t_decide` | `defense.action` | 防御时延 |
| 恢复 | `t_defense` | `task.state` 恢复 | 恢复时间 |

**要求：**

- 快路径不得等待链窗口；
- 链确认可以 >100 ms，但必须单列；
- 报表同时给 P50/P95/P99 和样本数。

### 10.4 评估指标

**事件级：**

- 识别率 = 命中事件 / 包络内事件；
- 误检率 = 含误报的正常运行 / 正常运行；
- Wilson 95% CI。

**链级：**

```text
node_recall    = |pred_nodes ∩ truth_nodes| / |truth_nodes|
node_precision = |pred_nodes ∩ truth_nodes| / |pred_nodes|
edge_recall    = |pred_edges ∩ truth_edges| / |truth_edges|
stage_order    = LCS(pred_stages, truth_stages) / |truth_stages|
root_cause_top1 = 1 if pred_root == truth_root else 0
chain_complete = |matched_stages| / |truth_stages|
```

**报告：**

- 分类型（A5–A10）事件级/链级；
- 分域（core/app/ran）证据覆盖；
- 时延 P50/P95/P99；
- 防御动作成功率/附带损伤。

### 10.5 正常集扩展

必须加入：

| 难负样本 | 触发的规则 | 合理解释 |
|---|---|---|
| 大型活动散场 | `nas_registration_flood` | 真实用户集中接入 |
| 小区边缘切换乒乓 | `handover_storm` | 无线条件 |
| 切片重配/割接 | `qos_policy_drift` | 维护窗口 |
| UPF 主备切换 | `upf_route_drift` | 高可用切换 |
| 平台 token 轮换 | `platform_token_anomaly` | 正常轮换 |
| 授权 NEF 订阅变更 | `nef_subscription_drift` | 工单 |
| 时间同步调整 | `time_sync_spoof` | 授时漂移 |
| 消息重传/重复 | `chain_correlation` | 网络重传 |

### 10.6 包络

| 剧本 | 包络判据 |
|---|---|
| A5 | `rate >= 1000/s` 或 `bot_ues >= 100` |
| A6 | `5qi_downgrade` 或 `latency_increase >= 50ms` |
| A7 | `redirect_ratio >= 0.1` |
| A8 | `unsubscribe_events >= 1` |
| A9 | `vehicles >= 3` 或 `commands >= 5` |
| A10 | `bias >= 1.0m` 且 `signaling_rate >= 2x` |

包络外事件单列，不计入识别率分母。

## 15 风险与开放问题

### 15.1 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 新层正常行为未覆盖 | 误检率 >1% | 先补难负样本，再调规则 |
| 链级关联凑窗 | 时延超 100 ms | 快路径/链确认双口径 |
| truth 与数据不一致 | 评审/复现风险 | truth-domain 静态测试 |
| schema 不兼容 | 外部消费失败 | v2 兼容读取 |
| 图边被截断 | 核心网边丢失 | 分层采样 |
| 规则与生成器同源 | 识别率虚高 | 参考检测器只作基线；外部模型复测 |
| 防御误伤 | 业务中断 | 二次确认、附带损伤指标 |
| Web 无鉴权 | 误操作/安全风险 | token/来源限制 |

### 15.2 开放问题

1. 外部检测系统的输入契约：JSON/Kafka/NetFlow/pcap？
2. 链级指标的定义：节点/边/阶段/根因，哪个是主指标？
