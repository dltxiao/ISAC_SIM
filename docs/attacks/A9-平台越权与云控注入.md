# A9 平台越权/云控注入：代码走读与实现解析

> 代码基线：`feature/trace-watch`（v0.3.0 + A1–A10 TraceProfile），2026-11-03。
> 共享机制见 [A1 §2–§4](A1-感知篡改诱导通信拥塞.md)；本文只写 A9 的差异。
> 目标：解释“复用合法租户 token → 批量云控 → 多车制动”的代码路径，并说明它没有窃取 token、没有绕过 IAM。

## 1. 一句话概括

A9 做三件事：

1. 直接使用平台启动时签发的**合法租户 token**（`control:write` scope）；
2. 每 0.5 s 调 `platform.submit_control(...)`，一次给 3–8 辆车下发 `brake`；
3. 制动参数是 `decel = 2.5 + 1.5a`、`duration=1.2`。

它没有窃取/伪造 token，也没有利用 IAM 漏洞；IAM 校验会通过，因为 token 本来就是合法的。所谓“越权”是**滥用合法权限**，不是绕过鉴权。

## 2. 端到端调用链

```text
POST /api/attacks {type:"A9", amplitude, duration, start}
  → CampaignA9.ready(ctx)：等 platform.tenant_token_id（首个 platform.tick 后）
  → CampaignA9.start(ctx)
      ├─ n = 3 + min(5, round(5a))
      ├─ victims = 前 n 辆已装备车辆（target 命中则置于首位）
      ├─ decel = 2.5 + 1.5a
      └─ _submit(ctx)                     第一批（只发一次）
  → Pacer(2 Hz) 每 0.5 s CampaignA9.tick(ctx)
      └─ _submit(ctx)
  → _submit(ctx)
      └─ platform.submit_control(token, victims, brake decel/1.2)
```

`platform.submit_control()`（[layer.py](../../isacsim/layers/platform/layer.py:69)）走 `Dispatcher.submit()`：

```text
IAM.validate(control:write) → app.control → audit.append
  → control intents → ControlLayer._apply_intents
  → control.command (每辆车一条)
```

层序：

```text
scheduler → ... → platform → control
```

`submit_control` 在 scheduler 调用，intent 队列在 `control.tick()` 消费；所以 `control.command` 在同一 tick 或下一 tick 出现。

## 3. 选目标与参数

```python
amp = clamp(spec.amplitude)
n = 3 + min(5, int(round(5 * amp)))            # 3..8 辆
decel = 2.5 + 1.5 * amp                        # 2.5..4.0 m/s²
vehicles = [v.vid for v in sorted(...) if is_equipped(...)]
if spec.target in vehicles:                    # target 置首位，保证入选
    vehicles = [target] + [v for v in vehicles if v != target]
self.victims = vehicles[:n]
```

- 频率固定 2 Hz（`Pacer`），不用 `ctx.t - _last`：后者在浮点边界会漂成 0.55 s，
  3 s 只发 5 批；
- `params` 里**不再带 `replayed`**：它是自报标记，对判定也不起作用（`n>=3` 恒真）。

| `a` | victims 数 | decel |
|---:|---:|---:|
| 0.2 | 4 | 2.80 |
| 0.5 | 6 | 3.25 |
| 0.8 | 7 | 3.70 |
| 1.0 | 8 | 4.00 |

包络：`vehicles >= 5 且 decel >= 3.5`（旧的 `vehicles>=3` 恒真）。

## 4. 注入点

### 4.1 云控提交

```python
platform.submit_control(
    ctx, token_id=self._token, vehicle_ids=self.victims,
    command="brake", params={"decel_mps2": self.brake_decel, "duration_s": 1.2},
    ttl_s=10.0,
)
```

`Dispatcher.submit()`（[dispatch.py](../../isacsim/layers/platform/dispatch.py:17)）会：

- `IAM.validate(token, "control:write")`；
- emit `app.control`，`vehicle_ids` 是完整列表；
- `audit.append(actor=token:<id>, action=control:submit)`；
- 给每辆车 append 一个 control intent。

实测 seed=14、a=0.8：

```json
{
  "stream": "app.control",
  "payload": {
    "vehicle_ids": ["east_truck.0", "eastbound.0", "eastbound.1",
                    "eastbound.2", "northbound.0", "southbound.0",
                    "westbound.1"],
    "command": "brake",
    "params": {"decel_mps2": 3.7, "duration_s": 1.2},
    "result": "accept"
  }
}
```

### 4.2 控制面落地

`ControlLayer._apply_intents()` 对每个 intent 调 `_command()`：

```python
source = "platform:V2X-01"
reason = "cloud_control"
ttc = 99.0
decel = 调度器传入的 brake_decel
duration = 1.2
```

所以每辆车一条 `control.command`，`ttc=99`、`src=platform:V2X-01`、`reason=cloud_control`。
3 s 攻击 = 6 批（`Pacer` 2 Hz）× 7 辆 = **42 条**（旧实现首拍双发 + 0.55 s 漂移 → 49 条）。

| 规则 | 触发 |

## 8. 外部检测视角：数据支撑、`/trace` 位置与 `out/` 落点

> 本节假设判定在仿真之外完成：只看导出的观测流与日志，不读 `truth/`、不读 `ctx.extras`。可观测面清单与路径/落盘规则见 [A1 §9.1、§9.4](A1-感知篡改诱导通信拥塞.md)。

### 8.1 判定 A9 需要的数据支撑

A9 用的是平台启动时就存在的**合法租户 token**：IAM 校验会正常通过，scope 也够（`control:write`）。所以单看鉴权结果是“全绿”，判定必须靠**调用形态**：同一个 token 反复批量下发、频率高、没有危险依据、多车同步减速。

| 观测面 | 需要捕获的字段 | 在判定中的作用 | 可依赖度 |
|---|---|---|---|
| `app.auth` | `msg_type`、`token_id`、`tenant`、`scopes`、`result`、`reason` | 同一 token 在短时间内反复 `token_validate accept`；token 属于租户而非车辆 | 协议证据 |
| `app.control` | `token_id`、`vehicle_ids`、`command`、`params`、`ttl_s`、`result` | 每 0.5 s 一批、每批 ≥3 辆车；判定靠批量+频率 | 协议证据（不再依赖任何标记） |
| `app.audit` | `actor`、`action`、`resource`、`result` | `actor=token:<id>`、`action=control:submit`、`resource=vehicles:N` | 协议证据（可复核） |
| `control.command` | `src`、`reason`、`params.ttc_s`、`dst` | 每车一条 `src=platform:V2X-01`、`reason=cloud_control`、`ttc=99` | 物理/协议证据（关键） |
| `v2x.cam` / `sensing.gnss` | `spdx/spdy`、`x/y` | 多车在 ±1 s 内同时减速 | 物理证据 |
| `v2x.denm` | 是否存在 | 这条链**不保证**有 DENM；缺失不能当作否定证据 | 反证（注意） |
| `link.metrics` | `cbr`、`jam` | 不变 → 排除 A1/A2 | 反证 |

判定口径：

```text
S1 同一 token 在短窗口内多次校验通过，且调用形态与它的注册主体不符
   （例如租户 token 被用来给一批车辆逐个下发指令）。
S2 app.control 在 2 s 内出现 ≥2 次，每次 vehicle_ids>=3（频率形态，不依赖 replayed）。
S3 对应的 control.command 满足 ttc_s>=10、reason=cloud_control，且没有
   前序 CPM/DENM 危险事件。
S4 多车（>=3）在 ±1 s 内同时减速。
=> S2∧S3 判 A9；S1 用来区分“越权”与“正常批量下发”；S4 是后果证据。
```

边界：

- 不是 token 窃取、也不是 IAM 漏洞：token 合法、scope 合法；
- 同一辆车会收到多条指令（每 0.5 s 一批），不是一次性批量；
- `params` 里已经没有 `replayed`（自报标记，且对判定不起作用）；
- `v2x.denm:emergency` **现在会稳定出现**：R15 修完后 `ControlLayer.recent_brakes` 会持久到
  下一 tick 由 V2X 消费。实测 3 s 攻击产生 **14 条** `v2x.denm`（7 辆 × 2 次 / 2 s 节流）；
- A9 没有 `stop()` 清理，也不需要：token 是合法租户的（不该撤销），intent 在下一拍就被
  `ControlLayer` 消费完，没有持久全局状态。

### 8.2 对应前端 `/trace` 的位置

| 数据 | `/trace` 位置 | 看什么 |
|---|---|---|
| Token | **平台** → `平台 · V2X` 卡 → 子标签「Token」 | `tok-0002`：`subject=tenant:city-a`、`scopes` 含 `control:write`、`revoked=false` |
| 批量云控 | 平台概览 `control_sent`；右栏 `app.control` 事件 | `vehicle_ids` 一次 3–8 辆、`command=brake`（`params` 不在事件里） |
| 审计 | 右栏 `app.audit` 事件 | `actor=token:tok-0002`、`action=control:submit`、`resource=vehicles:N` |
| 指令 | 右栏 `control.command`（**每条都出，会刷屏**）；**车辆** → `Fleet · vehicles` | 每车一条 `ttc=99`、`reason=cloud_control`；`Fleet` 里多行 `AFFECTED` |
| 多车减速 | **车辆** → 各 `<vid> · state` 卡 | 各自的 `speed`、`speed_drop` |
| 告警 | **总览** → `Detector · alerts`；**底栏时间轴** | `cloud_control_burst`、`brake_without_hazard` |
| 阶段 | 顶栏 **下一步** 后的检查点横幅 | S1 复用租户 Token → S2 批量云控下发 → S3 指令到达车辆 → S4 多车减速 → S5 告警 |

不在 `/trace` 上的：完整指令序列（右栏只保留最近 120 条、显示 50 条，A9 会把它刷满）、token 的绑定关系与调用来源、每车的指令计数。

## 9. 时序

| 相对 `t0` | 事件 |
|---:|---|
| 0（首个 platform.tick 后） | `ready()` 通过；`start()` 发第一批 `app.control` + `app.audit` |
| 0 | control 消费 intents，victims 各一条 `control.command` |
| +0.05 | 第一批 `brake_without_hazard`；随后 `v2x.denm` 由制动事件产生 |
| +0.5 | 第二批提交（`Pacer` 2 Hz，不漂） |
| +3.0 | 共 6 批、`batches×victims` 条指令 |
| `t1` | 停止提交；已下发的制动按 duration 执行完 |

`start=None` 时 `ready()` 会把攻击挂到平台 token 就绪后的第一个 tick（约 t=0.05），
不再“零效果且不写真值”。

## 10. 边界与差异

1. **不是 token 窃取**：用的是平台启动时已有的合法 token；IAM 会正常通过。
2. **不是 IAM 漏洞**：没有绕过 scope 校验；`control:write` 本来就有。
3. **每 0.5 s 重复提交**：不是一次性批量；同一辆车会收到多条指令。
4. **`v2x.denm:emergency` 不保证**：control 在 v2x 之后，`brake_events` 不进同一 tick 的 v2x。
5. **`app.control` 的 `vehicle_ids` 是完整列表**；Trace 事件需要保留该字段，A9 profile 才能判断 >=3。
6. **没有 `stop()` 清理**：A9 停止后不会撤销 token，也不会取消已排队的控制 intent。

## 13. 小结

```text
tenant token（合法，平台 bootstrap 时签发）
        │
Pacer 2 Hz → platform.submit_control(3–8 vehicles, brake 2.5+1.5a)
        │
app.auth + app.control + app.audit
        │
control.command × N → v2x.denm（R15 后已闭环）
        ├─ cloud_control_burst（2 s 内 ≥2 批、每批 ≥3 车）
        └─ brake_without_hazard
```

A9 是“合法权限被滥用”的云控注入：没有 token 窃取、没有 IAM 绕过，检测重点是**一次控制多车**和**无依据制动**。
