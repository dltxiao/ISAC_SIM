# A9 平台越权/云控注入：代码走读与实现解析

> 代码基线：`feature/trace-watch`（v0.3.0 + A1–A10 TraceProfile），2026-11-03。
> 共享机制见 [A1 §2–§4](A1-感知篡改诱导通信拥塞.md)；本文只写 A9 的差异。
> 目标：解释“复用合法租户 token → 批量云控 → 多车制动”的代码路径，并说明它没有窃取 token、没有绕过 IAM。

## 1. 一句话概括

A9 做三件事：

1. 直接使用平台启动时签发的**合法租户 token**（`control:write` scope）；
2. 每 0.5 s 调 `platform.submit_control(...)`，一次给 3–8 辆车下发 `brake`；
3. 制动参数是 `decel=3.5, duration=1.2`，`params.replayed=True`。

它没有窃取/伪造 token，也没有利用 IAM 漏洞；IAM 校验会通过，因为 token 本来就是合法的。所谓“越权”是**滥用合法权限**，不是绕过鉴权。

## 2. 端到端调用链

```text
POST /api/attacks {type:"A9", amplitude, duration, start}
  → CampaignA9.start(ctx)                 campaigns.py:529
      ├─ 需要 platform
      ├─ n = 3 + min(5, round(5a))
      ├─ victims = 前 n 辆已装备车辆
      ├─ token = platform.tenant_token_id
      └─ _submit(ctx)                     第一批
  → 每 0.5 s CampaignA9.tick(ctx)         campaigns.py:560
      └─ _submit(ctx)
  → _submit(ctx)                          campaigns.py:549
      └─ platform.submit_control(token, victims, brake 3.5/1.2,
                                  params={"replayed": True})
```

`platform.submit_control()`（[layer.py](../../isacsim/layers/platform/layer.py:69)）走 `Dispatcher.submit()`：

```text
IAM.validate(control:write) → app.control → audit.append
  → control intents → ControlLayer._apply_intents
  → control.command (每辆车一条)
```

层序：

```text
scheduler → ... → platform → control
```

`submit_control` 在 scheduler 调用，intent 队列在 `control.tick()` 消费；所以 `control.command` 在同一 tick 或下一 tick 出现。

## 3. 选目标与参数

```python
n = 3 + min(5, int(round(5 * max(0.0, min(1.0, self.spec.amplitude)))))
vehicles = [v.vid for v in sorted(ctx.vehicles.values(), key=lambda x: x.vid)
            if is_equipped(v.vid, self.scene.vehicles.equipped_ratio)]
self.victims = vehicles[:n]
```

| `a` | victims 数 |
|---:|---:|
| 0.0 | 3 |
| 0.4 | 5 |
| 0.8 | 7 |
| 1.0 | 8 |

- 只选已装备车辆，按 vid 排序取前 n；
- token 是 `platform.tenant_token_id`，不是攻击者新签的；
- 每 0.5 s 重复提交，所以同一个 victim 会收到多条 `control.command`；
- `params.replayed=True` 是检测器识别云控 burst 的辅助字段。

## 4. 注入点

### 4.1 云控提交

```python
platform.submit_control(
    ctx, token_id=self._token, vehicle_ids=self.victims,
    command="brake", params={"decel_mps2": 3.5, "duration_s": 1.2,
                             "replayed": True},
    ttl_s=10.0,
)
```

`Dispatcher.submit()`（[dispatch.py](../../isacsim/layers/platform/dispatch.py:17)）会：

- `IAM.validate(token, "control:write")`；
- emit `app.control`，`vehicle_ids` 是完整列表；
- `audit.append(actor=token:<id>, action=control:submit)`；
- 给每辆车 append 一个 control intent。

实测 seed=14、a=0.8：

```json
{
  "stream": "app.control",
  "payload": {
    "vehicle_ids": ["east_truck.0", "eastbound.0", "eastbound.1",
                    "eastbound.2", "northbound.0", "southbound.0",
                    "westbound.1"],
    "command": "brake",
    "params": {"decel_mps2": 3.5, "duration_s": 1.2, "replayed": true},
    "result": "accept"
  }
}
```

### 4.2 控制面落地

`ControlLayer._apply_intents()` 对每个 intent 调 `_command()`：

```python
source = "platform:V2X-01"
reason = "cloud_control"
ttc = 99.0
decel = 3.5
duration = 1.2
```

所以每辆车一条 `control.command`，`ttc=99`、`src=platform:V2X-01`、`reason=cloud_control`。3 s 攻击、每 0.5 s 一批、7 辆车，实测 49 条。

`v2x.denm:emergency` 只在 control 产生的 `brake_events` 能被 v2x 消费时出现；当前层序下，`control` 在 `v2x` 之后，这个连锁并不稳定。不要把真值链当成必然事件。

## 7. 检测侧看到了什么

| 规则 | 触发 |
|---|---|
| `cloud_control_burst` | `app.control.result=accept` 且车辆数≥3 或 `params.replayed` |
| `brake_without_hazard` | 每条 `control.command` 的 ttc>=10 |
| `cam_position_jump` | 与 A9 无关 |

seed=14、a=0.8、3 s 攻击实测：

```text
cloud_control_burst ×3, brake_without_hazard ×21
```

（`cloud_control_burst` 1 s 内按 rule/entity 去重，所以 3 条；`brake_without_hazard` 按车辆去重，每辆车 1 条/秒。）

## 8. 时序

| 相对 `t0` | 事件 |
|---:|---|
| 0 | 取 tenant token；第一批 `app.control` + `app.audit` |
| 0 | control 消费 intents，7 辆车各一条 `control.command` |
| +0.05 | 第一批 `brake_without_hazard` |
| +0.5 | 第二批提交 |
| `t1` | 停止提交；已下发的制动按 duration 执行完 |

## 9. 边界与差异

1. **不是 token 窃取**：用的是平台启动时已有的合法 token；IAM 会正常通过。
2. **不是 IAM 漏洞**：没有绕过 scope 校验；`control:write` 本来就有。
3. **每 0.5 s 重复提交**：不是一次性批量；同一辆车会收到多条指令。
4. **`v2x.denm:emergency` 不保证**：control 在 v2x 之后，`brake_events` 不进同一 tick 的 v2x。
5. **`app.control` 的 `vehicle_ids` 是完整列表**；Trace 事件需要保留该字段，A9 profile 才能判断 >=3。
6. **没有 `stop()` 清理**：A9 停止后不会撤销 token，也不会取消已排队的控制 intent。

## 12. 小结

```text
tenant token（合法）
        │
platform.submit_control(7 vehicles, brake 3.5/1.2, replayed)
        │
app.auth + app.control + app.audit
        │
control.command × 7 → cloud_control_burst + brake_without_hazard
```

A9 是“合法权限被滥用”的云控注入：没有 token 窃取、没有 IAM 绕过，检测重点是**一次控制多车**和**无依据制动**。
