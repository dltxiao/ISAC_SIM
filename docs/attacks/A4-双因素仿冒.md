# A4 双因素仿冒：代码走读与实现解析

> 代码基线：`feature/trace-watch`（v0.3.0 + A1–A10 TraceProfile），2026-11-03。
> 共享机制见 [A1 §2–§4](A1-感知篡改诱导通信拥塞.md)；本文只写 A4 的差异。
> 目标：解释“克隆通信标识 + 复制信道指纹 + 伪标识 CAM”在代码里到底做了什么，以及为什么它不是完整的 Uu 仿冒。

## 1. 一句话概括

A4 做三件事：

1. 在 `start()` 里发一条 `auth.cert` 克隆事件（`cloned=true`）；
2. 每个伪造周期发一条 `auth.fingerprint`（复制受害车的 CFO/IQ/RSSI）；
3. 用受害车的伪标识发一条位置偏移 45 m 的 `v2x.cam`（`cloned=true`）。

当前实现**没有** `uu.attach`、没有真正复制证书链、也没有让攻击者接入核心网；`auth.cert` 是语义事件，不是密码学验证结果。

## 2. 端到端调用链

```text
POST /api/attacks {type:"A4", amplitude, duration, start}
  → CampaignA4.start(ctx)                 campaigns.py:266
      ├─ 选已装备车辆 victim
      ├─ baseline_fingerprint(victim)
      ├─ emit auth.cert(cloned=true)
      └─ spoof_rate = _level(a, 2, 20)
  → 每个 tick CampaignA4.tick(ctx)        campaigns.py:290
      └─ 到达伪造周期：
          emit v2x.cam(cloned=true, x=+45, y=+8)
          emit auth.fingerprint(cloned=true)
```

A4 不经过 HookBus；两条伪造记录都是 `ctx.emit()` 直接产生。A4 也没有控制面动作，所以不会产生 `control.command`。

## 3. 选目标与参数

```python
equipped = [v for v in sorted(ctx.vehicles)
            if is_equipped(v, self.scene.vehicles.equipped_ratio)]
self.victim = stable_pick(equipped, self.seed, "a4")
self.spoof_rate = _level(self.spec.amplitude, 2.0, 20.0)
```

- 只从已装备车辆里选 victim；
- `spoof_rate` 是**每秒伪造次数**，不是 msg/s 的物理发送速率；
- `period = 1 / max(0.5, spoof_rate)`；
- `spec.target` 不生效。

| `a` | `spoof_rate` | 周期 |
|---:|---:|---:|
| 0.0 | 2 Hz | 0.5 s |
| 0.5 | 11 Hz | 0.091 s |
| 0.8 | 16.4 Hz | 0.061 s |
| 1.0 | 20 Hz | 0.05 s |

## 4. 注入点

### 4.1 `auth.cert` 克隆

```python
ctx.emit("auth.cert", "ATK-A4", f"attacker:{self.victim}", {
    "node_id": self.victim,
    "event": "clone",
    "cert_id": f"CERT-{self.victim}-clone",
    "pseudonym": f"PN-{self.victim}",
    "status": "valid",
    "cloned": True,
})
```

只在 `start()` 发一次；`cert_id` 是拼接出来的，没有做证书签名/链验证。

### 4.2 `auth.fingerprint` 复制

```python
ctx.emit("auth.fingerprint", f"ATK-{self.victim}", f"veh:{self.victim}", {
    "node_id": self.victim,
    "cfo_ppm": self._fp["cfo_ppm"],
    "iq_gain_db": self._fp["iq_gain_db"],
    "iq_phase_deg": self._fp["iq_phase_deg"],
    "rssi_dbm": round(self._fp["rssi_base_dbm"] + 4.0, 1),
    "auth_result": "pass",
    "cloned": True,
})
```

指纹来自 `baseline_fingerprint(victim)`（[auth.py](../../isacsim/layers/auth.py:16)），是稳定哈希生成的设备偏差；A4 把同一组值复制到攻击者记录里，并给 RSSI 加 4 dB，制造“位置不符但指纹一致”的矛盾。

### 4.3 伪标识 CAM

```python
x = victim.x + 45.0
y = victim.y + 8.0
ctx.emit("v2x.cam", f"ATK-{self.victim}", f"veh:{self.victim}", {
    "sender_pseudo": self.victim,
    "pseudonym": f"PN-{self.victim}",
    "posx": round(x, 3), "posy": round(y, 3),
    "rate_hz": 10.0,
    "cert_status": "valid",
    "cloned": True,
})
```

- 伪 CAM 使用 victim 的 `sender_pseudo`，但位置偏移 45 m / 8 m；
- `cert_status=valid`，所以单看认证字段是合法的；
- `rate_hz=10.0` 是攻击者填的值，不代表实际伪造周期（周期由 `spoof_rate` 决定）；
- 真实受害车自己的 `v2x.cam` 仍在发，检测器会看到同一标识在短时间内出现在两个相距很远的位置。

## 5. 下游消费

| 消费者 | 看到什么 |
|---|---|
| ReferenceDetector | 同一 `sender_pseudo` 的位置跳变；CAM 与 GNSS 不一致 |
| Trace | `record.clone`（auth.cert/fingerprint）、`v2x.cam.clone` |
| Platform | 伪 CAM 不在 `v2x_outbox` 里，不会自动进入平台 ingest；它是直接 emit 的记录 |
| Truth | `domains=[auth,v2x]`，没有 `uu`/`control` |

A4 当前没有让平台或核心网“接受攻击者接入”，所以不能把它描述成“攻击者成功附着”。

| 规则 | 触发 |
|---|---|
| `cam_position_jump` | 同一 `sender_pseudo` 1 s 内位置跳变 >25 m |
| `cam_gnss_mismatch` | CAM 位置与 GNSS 位置差 >12 m 且时间差 <0.5 s |
| `ghost_object` | A4 不产生 |
| `brake_without_hazard` | A4 不产生（没有控制指令） |

```text

```

## 8. 外部检测视角：数据支撑、`/trace` 位置与 `out/` 落点

> 本节假设判定在仿真之外完成：只看导出的观测流与日志，不读 `truth/`、不读 `ctx.extras`。可观测面清单与路径/落盘规则见 [A1 §9.1、§9.4](A1-感知篡改诱导通信拥塞.md)。

### 8.1 判定 A4 需要的数据支撑

A4 要同时伪造**标识**（证书/伪名）和**射频指纹**，再用同一标识发位置错误的 CAM。单看认证字段全部合法（`cert_status=valid`、`auth_result=pass`），所以判定必须靠“同一身份出现在两个地方”和“指纹与位置不自洽”。

| 观测面 | 需要捕获的字段 | 在判定中的作用 | 可依赖度 |
|---|---|---|---|
| `auth.cert` | `node_id`、`event`、`cert_id`、`pseudonym`、`status` | 同一 `node_id` 出现新的 `cert_id`/`event=clone`，且没有对应的轮换周期 | `event=clone` 是标记；`cert_id` 序列不连续是协议证据 |
| `auth.fingerprint` | `node_id`、`cfo_ppm`、`iq_gain_db`、`iq_phase_deg`、`rssi_dbm` | 指纹与 victim 基线几乎完全相同（正常记录有 0.02–0.08 的抖动），但 RSSI 高 4 dB | 物理证据（关键） |
| `v2x.cam` | `sender_pseudo`、`pseudonym`、`posx/posy`、`spdx/spdy`、`msg_id`、`cert_status` | 同一伪名 1 s 内位置跳变 >25 m；`msg_id` 从 900000 起跳 | 物理/协议证据 |
| `sensing.gnss` | `node_id`、`x/y`、`hdop` | CAM 位置与 GNSS 差 >12 m（0.5 s 内） | 物理证据 |
| `sensing.objects` | 目标列表 | 不变 → 排除 A1/A2/A3 | 反证 |
| `control.command` | — | A4 不产生制动，没有控制面证据 | 反证 |

判定口径：

```text
M1 同一 sender_pseudo 的 CAM 在 1 s 内出现相距 >25 m 的两个位置 → 位置跳变。
M2 同一时刻 CAM 位置与 GNSS 位置差 >12 m → 位置不可信。
M3 同一 node_id（伪名）的射频指纹（CFO/IQ）与 victim 基线一致，但 RSSI 偏离 +4 dB
   → “同设备指纹、不同位置”，即克隆。
M4 认证字段本身全部通过（cert_status=valid、auth_result=pass），不能作为放行理由。
=> M1∨M2 判“位置异常”；再叠加 M3 判 A4（双因素仿冒）。
```

边界：

- 检测器**没有**“证书克隆/指纹复制”的专用规则，`auth.cert`/`auth.fingerprint` 目前只作为溯源证据（§7）；
- 指纹基线要按设备历史中位数估计；单条记录无法判断“像不像 victim”；
- 伪 CAM 有 `cloned=true`，真 CAM 没有——这是仿真标记，真实系统要靠 M1–M3；
- `auth.cert` 的克隆记录只在 `start()` 发一次，`auth.fingerprint` 每个伪造周期一条，二者频率不同。

### 8.2 对应前端 `/trace` 的位置

| 数据 | `/trace` 位置 | 看什么 |
|---|---|---|
| 证书克隆 | 右栏 **TRACE** 的 `record.clone` 事件 → **DETAIL** | `stream="auth.cert"` 的一条 + `stream="auth.fingerprint"` 的多条；事件不含 `cert_id`/指纹数值，全量在 `out/` |
| 指纹复制 | 右栏 `record.clone` 事件（`stream="auth.fingerprint"` 的那些） | 数值不在事件里，只能确认“有一批克隆指纹记录” |
| 伪标识 CAM | 右栏 `v2x.cam.clone` 事件 | `sender`、`pseudonym`、`posx/posy`、`msg_id`（每条伪造 CAM 一条） |
| 位置跳变 | **总览** → `Detector · alerts` 卡；**底栏时间轴**红点 | `cam_position_jump`、`cam_gnss_mismatch` |
| 车辆状态 | **车辆** → `<victim> · state` 卡 | 只有速度；`last_command` 为空（A4 不产生控制指令） |
| 阶段 | 顶栏 **下一步** 后的检查点横幅 | S1 克隆通信标识 → S2 复制信道指纹 → S3 伪标识 CAM 注入 → S4 位置跳变告警 |

不在 `/trace` 上的：认证/指纹的数值字段（没有 auth 卡片）、CAM 全量序列、`sensing.gnss`——这三样都要去 `out/`。

### 8.3 对应后端 `out/` 的位置

| 数据 | 文件 | 过滤键 / 字段 | 备注 |
|---|---|---|---|
| 证书克隆 | `auth.cert.jsonl` | `.payload.cloned==true` 或 `.payload.event=="clone"` | `cert_id` 形如 `CERT-<vid>-clone` |
| 指纹复制 | `auth.fingerprint.jsonl` | `.payload.cloned==true`；按 `node_id` 与基线比 | `rssi_dbm` 比基线高约 4 dB |
| 伪标识 CAM | `v2x.cam.jsonl` | `.payload.cloned==true`；看 `sender_pseudo/posx/posy/msg_id` | 与真 CAM 交错 |
| GNSS 对照 | `sensing.gnss.jsonl` | `.payload.node_id=="<victim>"` | 算 CAM–GNSS 距离 |
| 告警 | `alerts.jsonl` | `cam_position_jump` / `cam_gnss_mismatch` | 仅 CLI/batch |
| 真值（评估侧） | `truth/events.jsonl` | `.campaign=="A4"` | `params.fingerprint/spoof_rate` |

```bash
cd out/doc_a4/arterial-14-*
jq -c 'select(.payload.cloned==true) | {stream:"cert", node:.payload.node_id, ev:.payload.event}' auth.cert.jsonl
jq -c 'select(.payload.cloned==true) | {cam:.payload.sender_pseudo, pos:[.payload.posx,.payload.posy], id:.payload.msg_id}' v2x.cam.jsonl | head
jq -c 'select(.payload.cloned==true) | {fp:.payload.cfo_ppm, iq:.payload.iq_gain_db, rssi:.payload.rssi_dbm}' auth.fingerprint.jsonl | head -3
```

> A4 的“认证通过”不是矛盾，而是攻击设计：标志位全绿，只有位置与指纹两处对不上。判定要靠跨模态一致性，不能靠鉴权结果。

## 9. 时序

| 相对 `t0` | 事件 |
|---:|---|
| 0 | 选 victim；发 `auth.cert(clone)` |
| +0.061 | 第一条伪 CAM + `auth.fingerprint`（a=0.8） |
| +0.1 | 检测器可能出现 `cam_position_jump` |
| 每个周期 | 重复伪 CAM + 指纹 |
| `t1` | 停止；没有 `stop()` 覆写，base 只摘 hook（A4 没有 hook） |

## 10. 边界与差异

1. **不是完整双因素仿冒**：没有证书链验证、没有 Uu 附着、没有真实射频指纹。
2. **`auth.cert` 只发一次**：后续重复的是 `auth.fingerprint` 和 `v2x.cam`。
3. **伪 CAM 不进平台 outbox**：平台 ingest 不会自动消费它；它是给记录/检测器看的直接事件。
4. **`rate_hz=10.0` 是伪造值**：实际周期由 `spoof_rate` 决定。
5. **A4 没有控制面后果**：不会产生 `control.command`，truth 也不声明 control。
6. **Trace 归因**：A4 用 `victim` 字段而非 `veh_id`；当前 `TraceService` 已把 `victim` 纳入归因，事件可以带 `attack_id`。

## 13. 小结

```text
克隆 auth.cert（一次）
        │
每个伪造周期：
  v2x.cam(sender=victim, pos=+45/+8, cloned=true)
  auth.fingerprint(复制 CFO/IQ/RSSI, cloned=true)
        │
        └─ 同一标识位置跳变 / CAM-GNSS 不一致
```

A4 的“双因素”是**标识 + 信道指纹**两个语义层同时伪造；它不是密码学攻击，也不是 Uu 接入攻击。检测靠的是位置与指纹/几何的矛盾，而不是证书校验。
