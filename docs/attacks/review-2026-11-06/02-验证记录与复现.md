# 02 · 验证记录与复现

> 本文件记录审核过程中执行的测试与对照实验，作为 [01-主要发现](01-主要发现与修改建议.md) 的证据来源。所有脚本只读运行、不修改仓库文件。

## 1. 测试基线

```text
.venv/bin/python -m pytest -q
# 结果：103 项全部通过（72 + 31 个用例）
```

现有测试主要覆盖"记录是否出现 / 状态是否改变 / 固定规则是否告警"，未覆盖：取消清理、强度单调性、无标记变体、立即启动降级、首周期注入次数、跨层因果。因此"全绿"不能排除本报告列出的问题。

## 2. 实验 A：取消攻击后 hook 残留（支撑 R2）

脚本逻辑：`seed=14`，A1 `start=1, duration=3`，`t=1.5` 调用 `sim.cancel_attack`，继续步进到 `t=1.8`。

结果：

```text
cancel_t=1.5
ghost_frame_times=[1.05,1.15,1.25,1.35,1.45,1.55,1.65,1.75]
ghost_after_cancel=[1.55,1.65,1.75]
hooks_before=1, hooks_after_cancel=1
```

结论：取消后 `finished=True` 但 `sensing.objects` hook 未摘除，幽灵继续注入 3 帧。

## 3. 实验 B：A3 强度参数与实际行为对照（支撑 R8）

脚本逻辑：`seed=12`，A3 `start=8, duration=6`，`amplitude=0.1` 与 `0.9` 各跑一次，对比真值参数与实际残差/制动。

结果：

| 项 | a=0.1 | a=0.9 |
|---|---|---|
| `truth.bias_max_m` | 27.48 | 30.68 |
| `truth.apparent_lon_m` | 6.01 | 2.81 |
| 实际最小残差 `range - |pos-sensor|` | -29.242 | -29.242 |
| ADAS 最小 ttc | 2.295 | 2.295 |
| `inject_brake` 减速度 | 1.9 | 1.9 |
| `radar_range_bias` 告警数 | 4 | 4 |

结论：真值随 `amplitude` 变，实际观测与制动完全不变——`amplitude` 只改标签不改行为。

## 4. 实验 C：洪泛速率、标记依赖、首周期重复（支撑 R4/R11/R12）

脚本逻辑：`seed=3`，A5 `amplitude∈{0,1}`、A7/A9 `amplitude=0.8`，`start=1, duration=3`。

结果：

```text
A5 a=0 : truth_rate=200,  bot_nas=460,  app_control=1, control_command=1
A5 a=1 : truth_rate=2000, bot_nas=1150, app_control=1, control_command=1
A7 a=.8: forged_cpm=7, control_command=7        # 首周期双份 → 7 而非 6
A9 a=.8: app_control_batches=7, control_command=35  # 首周期双份 → 7 批
```

A5 发射节奏（`amplitude=1`）：

```text
batch_times_and_sizes = {1.05:50,1.15:50,1.25:50,...,2.1:50,2.25:50,2.4:50,...}
active_window_rate ≈ 389.8 msg/s   # 标称 2000/s，实际 ~390/s（浮点门控漂移）
```

去标记对照（同一批记录，仅移除 `core.nas.payload.bot`）：

```text
flood_alerts_with_bot    = 3
flood_alerts_without_bot = 0
```

结论：A5/A10 洪泛识别完全依赖生成器自报 `bot=true`；实际发射速率远低于标称；A7/A9 首周期重复注入。

## 5. 实验 D：雷达告警对未同步坐标的依赖（支撑 R3）

脚本逻辑：A3 跑完后，把每条 `sensing.radar.track` 的 `pos_x/pos_y` 改为由同一条回波的 `range_m+azimuth_deg` 重建，重放给一个全新的 `ReferenceDetector`。

结果：

```text
original_radar_alerts          = 4
consistent_track_radar_alerts  = 0
（brake_without_hazard 两组一致）
```

结论：`radar_range_bias` 依赖"同一 track 内 range 被改、pos 未改"的内部矛盾；一旦 pos 与 range 一致，该规则完全失效。当前 `pos_x/pos_y` 由 SUMO 真值合成，构成观测通道中的真值参照。

## 6. 实验 E：A4 标称速率与实际速率（支撑 R10）

脚本逻辑：`seed=14`，A4 `amplitude=0.8, start=2, duration=3`。

结果：

```text
truth_spoof_rate=16.4
truth_expected_n_over_3s=49
actual_cloned_cam=30
actual_rate≈10.17 Hz    # 发射间隔 0.1s
```

结论：标称 16.4 Hz 被 tick 步长（0.05s）+ 无 epsilon 浮点门控量化到 10 Hz，实际条数 30/49。

## 7. 实验 F：立即启动（`start=None`）静默降级（支撑 R1）

脚本逻辑：`seed=3`，`start=None`，A5/A6/A8/A9 各一次。

结果：

| 剧本 | finished | 实际效果 |
|---|---|---|
| A5 | True | 有洪泛/过载，**无 `control.command`**（云控未下发） |
| A6 | True | **无 `qos_flow_modify`、无制动**（`smf.sessions` 为空直接结束） |
| A8 | True | 有 NEF 退订 + 制动，**无 `app.ingest:no_subscription`**（平台未退订） |
| A9 | True | **零效果、无真值事件**（token 为空直接结束） |

结论：调度器先于 platform/core bootstrap 运行，立即注入使依赖型剧本静默失效或只执行一半。

## 8. 实验 G：A1 低强度包络外漏检（支撑 R6）

脚本逻辑：`seed=3`，A1 `amplitude=0`。

结果：

```text
truth_envelope = {in_envelope: False, criterion: "extra_load >= 250 msg/s"}
alerts = {}
```

结论：`in_envelope=False` 且 0 告警，但 `eval/metrics.py` 不读取 `in_envelope`，该事件仍会被计入识别率分母，与 [docs/03 §5](<../../03-指标测量与评估口径.md#L57-L66>) 口径冲突。

## 9. 审核边界与免责

- 未运行真实 5GC / Open5GS / UERANSIM；所有结论针对当前语义仿真实现。
- "真值泄漏"类结论指**观测通道内的结构性捷径**（R3/R4），检测器本身未导入 `truth/`（`test_detector.py:49` 静态断言通过）。
- 实验值随 SUMO 版本、路网、车流参数变化，但代码路径与字段结构不变，结论方向稳定。
- 本目录为只读审核，未修改任何被测文件。
