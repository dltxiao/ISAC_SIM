## 二、与审核意见的分歧（不改）

| 编号 | 审核建议 | 我们的处理与理由 |
|---|---|---|
| **R3-1** | 把 `track.pos` 也用被改回波重建 | **不采纳**。这正是本轮做的“让两字段同源”，但审核把它当作“修复”；实际效果是让同通道残差恒为 0、规则完全失效。我们保留“同源一致”作为建模正确性，同时把检测搬到**跨站点**，两者不矛盾 |
| **R3** 定性 | “真值泄漏/模型构造的 100%” | **部分不同意**。“零误差的位置估计”才是问题；残差检测本身是标准做法。改法应是给位置估计真实误差/换独立参考源，而不是删掉观测量 |
| **R14** 定性 | A2 的感知腿“形同虚设” | **部分不同意**。A2 本来就是三腿并行、制动由注入保底；但任务书要求“使车辆误判刹车”，所以我们按审核建议改了选择逻辑，仍保留“感知腿非必要条件”的说明 |
| **R17-1** | 真值拆 `planned/observed` 两套 schema | **降级采纳**。改为在事件内加 `observed` 块（向后兼容），不引入新 schema 版本 |

## 三、本轮未处理（建议下一轮）

- **R1** 立即启动静默失效：需要调度器与 platform/core bootstrap 对齐，属于时序架构改动；
- **R4** 检测去标记化（`bot/replayed`）：涉及新规则设计（速率+身份熵），需单独评估误检；
- **R5** 难负样本：需要批量生成器扩展与重跑 500+500；
- **R7** 阶段/根因指标：`ChainBuilder` 仍应明确标注“告警级骨架”；
- **R9–R13** A6–A9/A10 的参数与首周期问题：不在 A1–A3 范围。

## 四、由此带来的基线变化（对外引用前必须重跑）

1. `docs/03 §6.1` 的 500+500 识别率/误检率来自旧实现，**已标注待重测**；
2. A1 的链路负载改由真实 DENM 数导出，CBR/PER 数值与旧文档不可比；
3. A2 现在通常产生两条制动（ADAS + 伪指令），`brake_without_hazard` 仍只有一条；
4. A3 的 `radar_range_bias` 命中率受“目标是否被 ≥2 站看到”限制（实测 2/3），
   单站场景需靠控制面证据。
