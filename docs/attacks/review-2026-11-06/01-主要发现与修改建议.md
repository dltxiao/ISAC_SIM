# 01 · 主要发现与修改建议

> 严重度：🔴 高（影响结论/导致失效/状态残留）｜🟠 中（口径/参数/可观测性/文档失真）｜🟡 低（可维护性）。
> "实测"表示本审核通过对照实验复现（脚本见 [02](02-验证记录与复现.md)）；"静态"表示仅由代码路径推导。
> 行号以当前工作树为准，可能随后续提交偏移。

## R1 🔴 立即启动时多类攻击静默降级或完全失效（实测）

**位置**：层序 [engine.py:145-161](<../../../isacsim/core/engine.py#L145-L161>)（`scheduler → sensing → v2x → uu → core → auth → platform → control`）；各 `start()` 的前置依赖见下文。

**证据**：
- 调度器在每 tick **最前**运行，此时 `platform._bootstrap()`（[layer.py:49-55](<../../../isacsim/layers/platform/layer.py#L49-L55>)）与 `core.smf` 会话尚未建立。
- `A9.start`：`self._token = platform.tenant_token_id or ""`，为空即 `self.finished = True; return`（[campaigns.py:725-728](<../../../isacsim/attacks/campaigns.py#L725-L728>)）。实测 `start=None` 时 A9 **零效果且不写真值事件**。
- `A6.start`：`not core.smf.sessions` 即 `finished`（[campaigns.py:785-787](<../../../isacsim/attacks/campaigns.py#L785-L787>)）。实测立即启动无 QoS、无制动。
- `A5.start`：`token` 为空 → 不下发云控（[campaigns.py:560-567](<../../../isacsim/attacks/campaigns.py#L560-L567>)）。实测有洪泛/过载，但**无 `control.command`**，而 `truth.expected_evidence` 仍含 `control.command`。
- `A8.start`：`platform.subs.subs` 为空 → 无平台退订（[campaigns.py:875-877](<../../../isacsim/attacks/campaigns.py#L875-L877>)）。实测有 NEF 退订 + 制动，但**无 `app.ingest:no_subscription`**。

**影响**：Web 端默认"立即注入"（`start` 为空时 base=ctx.t）对 A6/A9 完全无效、对 A5/A8 只执行一半；且失败是**静默的**（不写真值或真值仍声明未出现的域/证据），演示和评估都会漏掉这一事实。

**建议**：
1. 让依赖 bootstrap 的剧本在 `start` 前置校验失败时**显式抛错/写入 `attack_status=aborted` 真值**，而非 `finished=True` 静默返回；
2. 或把攻击调度延后到 `platform`/`core` 首个会话就绪之后（`start` 语义改为"平台就绪后的最早可用时刻"）；
3. Web 注入时对依赖型剧本给出最低 `start`（如 ≥1 个 bootstrap tick）。

## R2 🔴 `cancel` 不摘 hook、不清全局状态（实测）

**位置**：[scheduler.py:77-82](<../../../isacsim/attacks/scheduler.py#L77-L82>)；`AttackInstance.stop()` 才清理 hook（[base.py:116-120](<../../../isacsim/attacks/base.py#L116-L120>)）。

**证据**：
```python
def cancel(self, attack_id):
    for inst in self.instances:
        if inst.id == attack_id and not inst.finished:
            inst.finished = True   # 未调用 inst.stop(ctx)
            return True
```
实测 A1（`start=1, duration=3`）在 `t=1.5` 取消后，`sensing.objects` hook 仍挂在 `HookBus` 上，`t=1.55/1.65/1.75` 三帧继续追加幽灵。

**影响**：
- A1/A2/A3/A10 的 hook 持续注入直到 run 结束；
- A5 的 AMF 过载、A6 的 5QI 降级、A7 的路由改向、A8 的平台退订、A10 的 AMF 负载/审计抑制在取消后**不会恢复**（它们的恢复逻辑都在 `stop()`）；
- `stats.campaign_finished()` 不调用，运行统计与实际不一致。

**建议**：`cancel` 不直接置位，而是写入 `inst.cancel_requested=True`，由 `AttackScheduler.tick(ctx)` 在下一 tick 用上下文调用 `inst.stop(ctx)`（`stop` 幂等化：hook 摘除、全局状态恢复、真值写入实际 `t_end`/`cancelled`）。`Simulation.cancel_attack` 同步暴露该状态。

## R3 🔴 `radar.track` 坐标含真值参照，`radar_range_bias` 依赖同通道不一致（实测）

**位置**：[sensing.py:146-167](<../../../isacsim/layers/sensing.py#L146-L167>)（echo→track 派生）、[sensing.py:164-165](<../../../isacsim/layers/sensing.py#L164-L165>)（`pos_x/pos_y` 用 SUMO 真值 + 0.15 m 噪声）；[reference.py:130-160](<../../../isacsim/detect/reference.py#L130-L160>)（用 `range_m` 与 `pos` 反算残差）。

**证据**：A3/A10 只篡改回波的 `range_m`/`azimuth_deg`，`pos_x/pos_y` **不随攻击重建**。于是同一条 `sensing.radar.track` 内出现"测距被拉近、笛卡尔坐标仍为真值"的自相矛盾，检测器用二者残差即可 100% 定位攻击。
实测：把 `pos_x/pos_y` 改为由被改回波按 `range+azimuth` 重建后，A3 的 `radar_range_bias` 从 **4 条 → 0 条**（其余 `brake_without_hazard` 不变）。

**影响**：这不是读取 `truth/events.jsonl`（静态断言仍通过），但属于**观测生成给检测器留下的真值代理**。若真实传感器从同一测量同时输出距离与笛卡尔位置，二者不会不一致；因此"雷达层 100% 检出"很大程度上是模型构造的，无法外推。

**建议**：
1. `pos_x/pos_y` 与 `sensing.objects` 一样，由同一条（`ctx.emit` 返回的、可能被攻击改写的）回波重建；
2. 检测改为**跨源/跨模态**残差：`echo/track` vs `objects` vs `GNSS/CAM` vs 多传感器互证，而非同一记录内部的两个字段互证；
3. 若需保留"独立航迹卡尔曼滤波"的复杂度，则显式建模一个独立滤波器，而非直接回填真值坐标。

## R4 🔴 检测规则依赖生成器自报标记，去标记即失效（实测）

**位置**：[reference.py:198-207](<../../../isacsim/detect/reference.py#L198-L207>)（`nas_registration_flood` 只看 `bot==True`）；[reference.py:245-250](<../../../isacsim/detect/reference.py#L245-L250>)（`cloud_control_burst` 依赖 `replayed` 或 `≥3 车`）。

**证据**：
- 实测 A5（`amplitude=1`）：带 `bot` 时 `nas_registration_flood ×3`；把 `core.nas` 记录的 `bot` 字段移除后重放给同一检测器，**该告警为 0**，而洪泛速率完全相同。
- A5/A10 的攻击者主动给每条注册写 `bot=True`（[campaigns.py:579-587](<../../../isacsim/attacks/campaigns.py#L579-L587>)、[campaigns.py:966-975](<../../../isacsim/attacks/campaigns.py#L966-L975>)）。
- 这与 A1 文档自述的"`forged`/`bot`/`replayed` 只能用于离线核对，不能当作外部检测依据"（[A1 §9.1](<../A1-感知篡改诱导通信拥塞.md#L831>)）直接冲突。

**影响**：A5/A10 的"识别率"高度依赖攻击者自报标记；真实攻击者不会打标，去掉标记后这两类攻击的雷达/核心网腿形同虚设。A9 的 `cloud_control_burst` 以"≥3 车"或 `replayed` 判攻击，而合法的批量云控（如车队控制、绿波调度）也会 ≥3 车，误检风险高。

**建议**：
1. `nas_registration_flood` 改为**速率 + 身份熵 + 拒绝码分布**（如 ue_id 高度可预测/重复、congestion 拒绝率异常）判定；
2. `cloud_control_burst` 去掉对 `replayed` 的依赖，改按"调用频率 + 无危险依据（无前序 CPM/DENM）+ 多车同步减速"联合判定；
3. 保持 `bot/replayed` 仅作为离线核对标记，明确其不入检测。

## R5 🔴 正常集缺少难负样本，误检率被系统性低估（静态 + 实现子代理确认）

**位置**：正常批处理 [batch/runner.py:74-77](<../../../isacsim/batch/runner.py#L74-L77>) 只是 `default_scene` 无攻击；[docs/02 §4](<../README.md>) 与 [docs/09 §240-250](<../../09-通信层扩展评估.md>)、[docs/10 §1283-1296](<../../10-通信层语义级拓展详细设计.md>) 声称的合法难负样本未在正常集实现。

**证据**：现有规则会把下列**合法运维操作**判为攻击，而正常集从不产生这些操作：
- 任意 `5qi<=9` 的 `qos_flow_modify` → `qos_downgrade`（[reference.py:214-218](<../../../isacsim/detect/reference.py#L214-L218>)）；
- 任意 `route != dn:DN-01` → `upf_route_drift`（[reference.py:209-212](<../../../isacsim/detect/reference.py#L209-L212>)）；
- 任意成功的 `revoke`/`api_unsubscribe` → `subscription_tamper`/`nef_subscription_tamper`（[reference.py:235-243](<../../../isacsim/detect/reference.py#L235-L243>)）；
- 任意 `≥3 车` 或 `replayed` 的合法云控 → `cloud_control_burst`（[reference.py:245-250](<../../../isacsim/detect/reference.py#L245-L250>)）。

**影响**：`0.20%` 的 FPR 是"正常集不含上述合法操作"的下界，不是真实误检率；一旦正常集加入 QoS 割接/UPF 主备切换/token 轮换/授权退订/批量控制，FPR 会显著上升。同种子分布声明也被违反：攻击 seed 为 `1..N`、正常 seed 为 `100001..`，非"同种子范围"。

**建议**：
1. 为正常集实现难负样本生成器（合法 QoS 变更、路由割接、订阅轮换、token 到期重签、车队批量控制、真实急刹+DENM）；
2. 检测规则对"状态变更类"事件区分"授权变更"与"越权变更"（结合 actor/token/tenant/审计链），而非"变更即攻击"；
3. 统一攻击/正常种子抽样区间。

## R6 🟠 评估未实现"包络外不计入分母"（静态 + 实测）

**位置**：[metrics.py:124-133](<../../../isacsim/eval/metrics.py#L124-L133>) 将全部 truth 计入 `attack_events`；文档口径 [docs/03 §5](<../../03-指标测量与评估口径.md#L57-L66>) 称"包络外事件单列，不计入识别率分母"。

**证据**：`evaluate_runs` 从不读取 `ev["envelope"]["in_envelope"]`。实测 A1 `amplitude=0` 时 `envelope.in_envelope=False`、0 告警，但该事件仍会被计入分母；A5 的 `envelope` 判据 `rate>=1000/s` 用的是**标称** rate（实际 ≈390/s），导致 `in_envelope` 语义与实际强度脱节。

**影响**：默认批量 `amplitude=0.8` 时全部落在包络内，500+500 的 100% 数字不受影响；但"难度曲线/包络"的诚实披露与低强度实验的口径不成立，且 A3 包络阈值在文档间不一致（[docs/03 §5](<../../03-指标测量与评估口径.md#L63>) 写 `≥3.0m`，[docs/02 A3](<../A3-跨层隐蔽攻击.md>) 写 `<1.0m` 出包络）。

**建议**：在 `evaluate_runs` 里按 `in_envelope` 分组：包络内计识别率、包络外单列；统一各文档的包络阈值；`envelope` 判据改用实际发射速率/实际偏移而非标称参数。

## R7 🟠 阶段覆盖/根因是结构性指标，不代表真正识别阶段（静态）

**位置**：[chain_metrics.py:36-55](<../../../isacsim/eval/chain_metrics.py#L36-L55>)（`stage_ratio = min(1, p_stages/t_stages)` 只比数量）；[chain.py:66-115](<../../../isacsim/detect/chain.py#L66-L115>)（每条告警变成一个 stage，首告警实体当 root）。

**证据**：阶段匹配不比对阶段名称、顺序或因果；只要预测链告警条数 ≥ 真值 stage 数，`stage_ratio` 恒为 1（"阶段覆盖 100%"）。根因 `top-1=70%` 亦来自"时间上第一条告警实体 == truth 首节点"的启发式，而非因果推理。

**影响**：链级"阶段覆盖 100%"与"根因 70%"是对构建器结构的结果，容易误读为模型具备阶段级/根因级识别能力。

**建议**：阶段按**名称 + 时间窗对齐**计命中（并披露未匹配阶段）；根因改为因果图/序列模型；在文档中把当前 `ChainBuilder` 明确标注为"告警级骨架，非因果链模型"。

## R8 🟠 A3 的 `amplitude` 只改真值、不改实际行为（实测）

**位置**：[campaigns.py:249-269](<../../../isacsim/attacks/campaigns.py#L249-L269>)（`_aim` 用 amplitude 算 `target_ttc`/`bias_max`）；[campaigns.py:349-352](<../../../isacsim/attacks/campaigns.py#L349-L352>)（hook 里固定 `lon_target = max(2.2, 1.6*closing)`，**不读 amplitude**）。

**证据**：同 seed、`amplitude=0.1` 与 `0.9` 两次运行：
| 项 | a=0.1 | a=0.9 |
|---|---|---|
| `truth.bias_max_m` | 27.48 | 30.68（不同） |
| `truth.apparent_lon_m` | 6.01 | 2.81（不同） |
| 实际最小残差 | -29.242 | -29.242（**相同**） |
| ADAS 最小 ttc | 2.295 | 2.295（**相同**） |
| 注入减速度 | 1.9 | 1.9（**相同**） |
| `radar_range_bias` | 4 | 4（相同） |

**影响**：A3 的"强度"维度是虚的——真值随 amplitude 变、实际数据完全不变。文档 [A3 §3](<../A3-跨层隐蔽攻击.md#L46-L64>) 宣称 `amplitude → 表观 TTC = 3.2 - 2.0a` 与实际不符；任何按 amplitude 分层的评估/难度曲线都无意义。

**建议**：让 hook 使用 `_aim` 算出的 `lon_end`（或 `target_ttc`），使实际偏移随 amplitude 变化；否则在文档中把 A3 声明为"固定偏移 + 幅度仅作标签"，并从难度曲线剔除。

## R9 🟠 A6/A7/A8 的 `amplitude` 完全无效（静态）

**位置**：A6 [campaigns.py:781-824](<../../../isacsim/attacks/campaigns.py#L781-L824>)、A7 [campaigns.py:637-697](<../../../isacsim/attacks/campaigns.py#L637-L697>)、A8 [campaigns.py:855-916](<../../../isacsim/attacks/campaigns.py#L855-L916>)：三者的 QoS/路由/订阅/延迟/制动均为固定值，`self.spec.amplitude` 未参与任何计算。

**证据**：文档 A6/A7/A8 各自 §10/§3 已承认"amplitude 无效"，但 [docs/02 §2.5](<../README.md>) 仍把它们列入 `amplitude∈[0.1,1]` 的参数化设计。A5/A10 也仅部分映射（A5 速率被 cap 到 ~390/s，见 R11；A10 仅 bias 随幅度变，信令/审计/制动固定）。

**影响**：UI 给 A6/A7/A8 提供强度滑块但毫无效果，用户会误以为调低了攻击强度；与"参数化"设计原则冲突。

**建议**：要么给 A6/A7/A8 定义有意义的幅度映射（如 QoS 降级档位、注入频率、退订范围），要么在 UI/API 层对这三类禁用 amplitude 控件并固定显示。

## R10 🟠 A4 标称伪造速率与实际发射速率不符（实测）

**位置**：[campaigns.py:462](<../../../isacsim/attacks/campaigns.py#L462>)（`spoof_rate = 2..20 Hz`）；[campaigns.py:476-479](<../../../isacsim/attacks/campaigns.py#L476-L479>)（`period = 1/spoof_rate`；`ctx.t - self._last < period` 门控）。

**证据**：`amplitude=0.8` → `spoof_rate=16.4 Hz`，真值预期 49 条/3s；实测 30 条、发射间隔 0.1 s（实际 10 Hz）。原因：tick 步长 0.05 s + 无 epsilon 的浮点门控，使周期被量化到 0.1 s。

**影响**：A4 文档 §3 速率表（[A4 §3](<../A4-双因素仿冒.md#L48-L53>)）与实际不符；"伪造速率"这一可观测特征被高估约 40%。

**建议**：用整数 tick 计数或 `next_due` 时间累计保证平均速率；`truth.params.spoof_rate` 记录实际发射速率。

## R11 🟠 A5/A10 实际发射速率与真值 rate 不符 + 浮点门控漂移（实测）

**位置**：[campaigns.py:557](<../../../isacsim/attacks/campaigns.py#L557>)（`rate=200..2000/s`）、[campaigns.py:574-577](<../../../isacsim/attacks/campaigns.py#L574-L577>)（`n=min(50,int(rate*0.1))`，每 0.1 s）。

**证据**：实测 `amplitude=1`（标称 2000/s）时，`core.nas` 发射间隔为 `0.1/0.15 s` 交替（浮点 `ctx.t - self._last < 0.1` 在 0.1 边界偶发不满足），实际窗口速率约 **390/s**；真值 `rate` 仍写 2000。`amplitude=0`（标称 200/s）实际约 153/s。A10 的 5 条/0.2 s 也受同样的量化影响。

**影响**：真值 `rate` 与 `envelope`（`rate>=1000/s`）基于标称值，而非实际发射强度；A5 文档已部分披露"实际最多约 500/s"，但 500 仍高于实测 390，且未说明浮点门控导致的节奏漂移。

**建议**：改为"`while ctx.t >= next_emit_t` 逐批补齐、保证平均速率"的调度；`truth.params` 记录 `actual_rate`（实测值），`envelope` 判据改用实际速率。

## R12 🟠 A7/A9 首周期重复注入（实测）

**位置**：[campaigns.py:649-657](<../../../isacsim/attacks/campaigns.py#L649-L657>)（A7 首次 tick `_done` 与 `_last=-1` 双重触发）；[campaigns.py:743-748](<../../../isacsim/attacks/campaigns.py#L743-L748>)（A9 `_last=-1` 首 tick 再 `_submit`）。

**证据**：3 s 攻击实测 A7 产生 **7** 条 `v2x.cpm`/`control.command`（首 tick 双份 + 每 0.5 s 一份），A9 产生 **7** 批 `app.control`（首 tick 双份）。文档时序均写"每 0.5 s 一次"，未披露首周期双份。

**影响**：短场景下后果量被高估约 17%；`cloud_control_burst`/`brake_without_hazard` 告警数随之偏多，评估中的"攻击行为"与"多余检测"统计失真。

**建议**：`start()` 里初始化 `_last = ctx.t`（或首 tick 跳过），使注入节奏与文档一致；同时加一个"首周期注入次数"回归测试。

## R13 🟠 `AttackSpec.target` / `params` 被忽略（静态）

**位置**：[base.py:14-31](<../../../isacsim/attacks/base.py#L14-L31>)；所有 campaign 均不读 `spec.target`（如 A1 用 `_victim_for_rsu`、A4 用 `stable_pick`），`params` 仅透传不消费。

**证据**：`spec.target` 只出现在 `snapshot()`（[base.py:147](<../../../isacsim/attacks/base.py#L147>)）与 `scheduler.submit` 的透传（[scheduler.py:33](<../../../isacsim/attacks/scheduler.py#L33>)），无任何消费点。

## R15 🟠 A1 "感知→拥塞"因果链未闭环（静态 + 文档自证）

**位置**：[campaigns.py:90-109](<../../../isacsim/attacks/campaigns.py#L90-L109>)；层序 [engine.py:145-160](<../../../isacsim/core/engine.py#L145-L160>)；真值链 [model.py:29](<../../../isacsim/truth/model.py#L29>)。

**证据**：A1 的三件事是**并行动作**——幽灵注入、全局 `extra_load` 标量（与幽灵是否被消费无关）、直接伪造 DENM。ADAS 因幽灵触发的 `brake_events`/`emergency_until` 写进每 tick 重建的 `ctx.extras`，而 `v2x.tick` 在 `control.tick` **之前**运行（[engine.py:149-160](<../../../isacsim/core/engine.py#L149-L160>)），因此这些值下一 tick 已消失，ADAS 制动**不会**产生 DENM/CAM 升频。文档 [A1 §10.2](<../A1-感知篡改诱导通信拥塞.md#L945-L967>) 已承认此点，但真值链 `["sensing.objects:inject","adas:ttc_brake","denm:flood","pc5:cbr_up"]` 与剧本标题"感知篡改**诱导**通信拥塞"仍把三者写成因果。
