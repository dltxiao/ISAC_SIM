## 3. 两个剧本的具体改法（建议本轮落地）

### 3.1 A7 · UPF/N6 劫持

1. **真因果（R16）**：`PlatformLayer.tick()` 的 ingest 不再写死 `dn:DN-01`，
   改为读 `core.upf.route_override or "dn:DN-01"`。攻击窗口内真实 CPM/SPaT/DENM
   全部带 `provenance=dn:EVIL-01`；`stop()` 恢复路由后自动回到 DN-01。
2. **幅度（R9）**：`inject_rate = 1 + 4a` Hz、`decel = 2 + 3a`、`object_count = 1 + 3a`。
3. **节奏（R12）**：`Pacer` + `start()` 里初始化，首次不再双发。
4. **target（R13）**：命中就用，否则 `pick_vehicle`。
5. **真值**：`params` 增加 `inject_rate / injected / actual_rate / route_restored`；
   包络改 `inject_rate >= 3 Hz and route_hold >= 1s`。
6. **伪 CPM 保留**：它演示“内容篡改”，但不再承担“来源异常”的全部证明。

> 可选项（不建议本轮）：让平台在路由劫持期间**完全收不到**真实消息（静默中断），
> 而不是“从 EVIL 收到”。前者更接近“N6 被切断”，但不可观测，且与文档里
> `provenance` 是“路径指纹”的说法冲突。当前选 MITM（攻击者转接）语义。

### 3.2 A8 · NEF/订阅篡改

1. **前置条件（R1）**：`ready()` 等 `platform.subs` 非空（实测 t≈0.05 就有）。
2. **撤销对象修复**（审核未提，见 §4.1）：从“第一个订阅”改为“第一个 ACTIVE 且覆盖 denm 的订阅”，
   否则第二次运行会撤销一个已经 REVOKED 的订阅，**看着成功、实际没有 dropped**。
3. **幅度（R9）**：撤销范围 `["denm"] → ["denm","spat"] → ["denm","spat","cpm"]`（a<0.4 / <0.75 / else），
   制动 `1.5 + 2a`；包络改 `revoked_event_types >= 2`。
4. **删掉 80 ms 平台延迟**（审核未提，见 §4.2）：它不是 A8 的语义，却让 A8 靠
   `ingest_latency_spike` 被“借来的规则”检出。删掉后 A8 的检测来自真实的 dropped 与订阅事件。
5. **真值**：`params` 增加 `revoked_event_types / dropped_ingests / nef_leg`（标明 NEF 腿无下游），
   `causal_chain` 去掉 `nef:*` 到受害后果的边。

### 3.3 检测侧（配合 R5，但不动剧本）

| 新规则 | 判据 | 为什么不是标记 |
|---|---|---|
| `ingest_drop_spike` | 1 s 内 `app.ingest` 且 `cause=no_subscription` ≥10 条 | 只看平台行为：合法单次退订最多掉每秒几条，且不会持续 |

## 4. 审核未提、但会直接影响 A7/A8 结论的问题

### 4.1 A8 第二次运行静默无效（实测）

`start()` 撤销的是 `subs[0]`。第一次攻击的 `stop()` 会重建一个订阅（`sub-0002`），
于是第二次攻击撤销的仍是已 REVOKED 的 `sub-0001`：`revoked` 计数 +1、
`app.subscription` 也发 `revoke/accept`，但 `active_for()` 不受影响 →
**整轮没有任何 `no_subscription`**。

实测（两个 A8 串行，1–3 s 与 4.5–6.5 s）：

```text
drops by time: {1.0..2.9: 每次 3 条}      ← 只有第一次攻击
4.5 之后：0 条
subs: [sub-0001 REVOKED, sub-0002 ACTIVE]
```

这不是“演示瑕疵”：它会让重复注入、批量评估里的 A8 样本**看起来成功但没有后果**。
修法：撤销前按 `state == ACTIVE and "denm" in event_types` 选，找不到就新建一个再撤销（模拟“先拿到当前订阅再退”）。

### 4.2 A8 的 80 ms 平台延迟与攻击语义无关

A8 的 `tick()` 每拍写 `platform_ingest_delay_ms=80`，于是 `ingest_latency_spike` 成了它的
主要告警之一（实测 9 s 双攻击里 4 条）。但 A8 的语义是“平台漏事件”，不是“平台变慢”；
这条延迟是从 A5/A6 抄过来的，属于**为了被检出而加的证据**。建议删除并把检测移到
`ingest_drop_spike`。

### 4.3 平台 ingest 不校验 token

`Ingest.ingest()` 只把 `token_id` 抄进记录，从不校验；A7 的伪 ingest 甚至用
`platform.service_token_id or "svc-rsu"`，在 `t=0` 时会写入一个不存在的 token 也照样 `accept`。
也就是说“service token”目前是标签，不是门禁。A7 的 `Q3` 判定（“同一 CPM 在空口与平台出现但来源不一致”）
不受影响，但任何想用 token 做鉴权的规则都站不住。

### 4.4 NEF token 由攻击者自助签发

`core.nef.issue_token(subject="attacker:A8", scopes=["nef:subscribe"])` 没有任何前置授权：
NEF 的签发接口对“谁”都开放。于是 A8 的第一段不是“越权”，而是“正常开户”。
要么给 `issue_token` 加调用方凭据，要么在 A8 文档里明确“本环境假设 NEF 签发未鉴权”。

### 4.5 A7/A8 的包络判据恒真

A7：`{"in_envelope": True, "criterion": "route redirect"}`；A8：`unsubscribe_events >= 1`。
和 A4 的 `spoof_rate>=2` 是同一个问题（审核 R6 提过 A5 的标称值，但没点名 A7/A8）。
改完幅度映射后一并改成由实际强度导出。

### 4.6 A7 的 `object_count` 与真值不一致

伪 CPM 固定 `object_count: 1`，但 `objects[]` 里也固定 1 个；幅度改完后要注意
`object_count == len(objects)`，否则 `schema_ok` 虽然过，但“条数”字段会自相矛盾。

1. **A7 的注入率映射到 1–5 Hz 而不是“次数”**：`Pacer` + 真值 `injected/actual_rate` 更直接，
