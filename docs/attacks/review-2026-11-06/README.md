# 跨层攻击设计与实现交叉审核报告

> 审核对象：`docs/attacks/` A1–A10 与单体原语的设计/实现、参考检测器与事件级评估口径。
> 审核基线：`feature/trace-watch` 当前工作树（含未提交修改）；2026-11-06。
> 审核方式：静态走读 + 针对性对照实验（实验记录见 [02-验证记录](02-验证记录与复现.md)）。
> 本目录**只做审核**，不修改任何攻击实现、检测器或被测文档；所有修改建议在 [01-主要发现](01-主要发现与修改建议.md) 中给出。

## 一、结论摘要

攻击剧本与实现整体结构清晰、可复现，文档对"语义级而非协议级""真值 stages 是计划"等边界也有多处主动披露。但本次审核确认存在一批**会影响"99%/1%/100ms"结论可信度、以及影响攻击语义成立性**的问题，建议在对外宣称结果或继续扩展前优先处理：

1. **多类攻击在"立即启动"（`start=None/0`）时静默降级或完全失效**——A9 零效果且不写真值、A6 直接 `finished`、A5 无云控、A8 无平台退订/漏事件。原因是调度器先于平台/核心网 bootstrap 运行（🔴 R1）。
2. **取消/提前结束不清理状态**——`cancel` 只置 `finished`，不摘 hook、不清全局状态；实测 A1 取消后幽灵仍持续注入（🔴 R2）。
3. **检测器依赖生成器自报的"金手指标记"**（`bot=true`、`replayed=true`），去掉标记后 A5/A10 洪泛告警为 0；与 A1 文档"仿真标记不能作检测依据"的自我要求直接冲突（🔴 R4）。
4. **雷达规则依赖同一通道内部不一致**：`sensing.radar.track.pos_x/pos_y` 由 SUMO 真值合成，未被回波攻击同步重建，形成检测器的"真值参照"。实测把 pos 改为由被改回波重建后，`radar_range_bias` 从 4 条降到 0（🔴 R3）。
5. **正常集缺少难负样本**：合法信令风暴/QoS 割接/UPF 主备/token 轮换/批量控制/授权退订均未出现在正常集，而现有规则对这些合法操作都会告警，误检率被系统性低估（🔴 R5）。
6. **评估未实现"包络外不计入分母"**，与 [docs/03](../../03-指标测量与评估口径.md) 口径不符；A1 低强度 `in_envelope=false` 的样本仍被计入（🟠 R6）。
7. **若干强度参数不生效或与真值不符**：A3 的 `amplitude` 只改真值不改实际行为（实测 0.1 与 0.9 的实际残差/制动完全相同）；A6/A7/A8 完全无效；A4 标称 16.4 Hz 实际 10 Hz；A5 标称 2000/s 实际约 390/s（🟠 R8–R11）。
8. **A1 的"感知篡改→通信拥塞"与 A5–A8 的"上游状态机→后果"因果链未闭环**，多数是并行动作 + 直接 `inject_brake`，`causal_chain` 中部分边没有对应实现（🟠 R15、R16）。

## 四、首要修改建议（按优先级）

1. **生命周期**：给 `AttackScheduler` 增加"待取消"队列，在下一 `tick(ctx)` 用上下文调用幂等的 `stop()`；自然结束与取消统一走 `stop()`；`Simulation.cancel_attack` 不再直接 `finished=True`。
2. **启动时序**：调度器延后到 `platform._bootstrap` / `core` 首个会话建立之后，或对依赖 bootstrap 的剧本在 `start` 校验失败时显式报错而非静默 `finished`。
3. **检测去标记化**：`nas_registration_flood` 改按速率/身份熵/拒绝码分布判定；`cloud_control_burst` 去掉 `replayed` 与"≥3 车即异常"的依赖；补合法运维难负样本。
4. **观测一致性**：`sensing.radar.track.pos_x/pos_y` 与 `sensing.objects` 一样由同一条（被攻击改写后的）回波重建，避免同通道自证；检测改为跨源/跨模态残差。
5. **评估口径**：实现 `envelope.in_envelope` 过滤并单列包络外；阶段匹配按名称/时间窗对齐而非数量；种子抽样统一。
6. **参数语义**：要么让 `amplitude`/`target`/`params` 真正生效，要么在 UI/API/文档中禁用并固定；真值记录实际发射速率与偏移量而非标称值。
