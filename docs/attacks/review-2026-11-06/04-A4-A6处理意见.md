## 3. 三个剧本的具体改法（建议本轮落地）

### A4 · 双因素仿冒（小改，约半天）

1. **节奏**：`period` 改为 `next_due += 1/rate`，每 tick `while ctx.t >= next_due` 补发（最多补 2 条防雪崩），保证平均速率；`truth.params.actual_rate` 记录实测值（= 发出条数 / 攻击窗口）。
2. **幅度语义**：现在只有“速率”随幅度变。补上**位置偏移**（`offset = 25 + 45·a` m）——这才是“仿冒被误认为真车”的核心观测量；速率上限收到 10 Hz（CAM 的物理标称），避免“伪造比真车还快”本身成为检测特征。
3. **包络**：`offset >= 20 m and actual_rate >= 8 Hz`（当前 `spoof_rate>=2` 恒真）。
4. **`target`**：`spec.target` 命中已装备车辆时作为 victim，否则回退 `stable_pick` 并在 `truth.params.target_matched=false`。
5. **载荷**：`rate_hz` 用实际值；`msg_id` 仍从 900000 起（保留“序列跳变”这一协议证据）。
6. **文档**：A4 §3 速率表按“实测速率 = 1/周期”重算，并注明 0.05 s tick 的量化上限（≤20 Hz，但物理上建议 ≤10 Hz）。

> 不建议本轮加“认证域检测规则”。A4 的认证腿目前只进证据（A4 §7 已声明），补规则属于检测域设计（见 §4.1），应单独评估误检。

### A5 · 5G-A 信令风暴（中改，约 1 天）

方案 A（推荐，真因果）：

1. 洪泛不再直接 `ctx.emit`，改为每 tick 对 N 个合成 UE 调 `core.amf.start_registration(ctx, ue_id, "GNB-01")`，让注册走 `bus.dispatch` + `AMF.accept()` 的队列/容量；`set_overload` 保留为“打满后进入过载”的显式状态（它本来就是 AMF 自己的字段，不是攻击者伪造的记录）。
2. **提速到能真的打满**：`rate = 200 + 4800·a`（tick 0.05 s、最多 50 条/批 → 上限 1000/s）。要不要打满 5000 tps 的容量由 `amplitude` 决定；不到容量时只有“过载标志”生效，这一点写进文档。
3. **受害车 PDU 失败**走 `smf`（会话表真的少一条），而不是 emit 一条 `pdu_session_establish_reject`。
4. **云控腿**：`start` 时若 token 未就绪，不静默跳过，而是挂起到第一个 token 可用的 tick 再提交（仍属“立即注入”）。
5. **速率记账**：`next_due` 补发；`truth.params.actual_rate`；`envelope: actual_rate >= 800/s`。
6. **检测**：`nas_registration_flood` 改 `rate>=N/s` + `distinct ue_id` 熵 + `cause=congestion` 占比，去掉 `bot` 依赖。

方案 B（保守，半天）：只做 4/5/6 + `actual_rate`，洪泛仍直接 emit。这样“过半是真因果、速率与真值一致”，但 R16 的定性仍然成立。

### A6 · 切片/QoS 抢占（中改，约 1 天）

1. **幅度映射**：`a → 5QI ∈ {9,8,7,6}`、ingest 延迟 `40+160·a` ms、注入制动 `1.2+1.8·a` m/s²、伪造 CPM 丢失率 `0.3+0.6·a`。
2. **立即启动**：`ready(ctx)` = 目标 UE 已有 PDU 会话（实测需 ≥0.15 s），未就绪保持 queued，1 s 超时才 abort 并写 truth。
3. **恢复原值**：`stop()` 记住 `old_5qi/old_gfbr` 再恢复，而不是硬写 `79/1000`（并发或基线变化时会改错）。
4. **CPM 腿二选一**：
   - 真因果（+1 天）：在 `v2x` 增加“按 UE 的 CPM 接收”记录，degraded UE 的接收延迟/丢失由 `smf.degraded` 决定，替换现在这条伪造的 `lost=true`；
   - 或标注（+0.5 h）：伪造 CPM 的字段从 `lost` 改为 `injected`，文档明确“A6 的真实足迹 = 全局 ingest 延迟 + 一次注入制动，CPM 腿是示意”。
5. **文档**：删 §10.5（幅度无效）、§10.6（cancel 不恢复），补“A6 与 A5/A2 的足迹重叠”。

## 4. 审核未提、但同等重要的问题

### 4.1 A4 的“双因素”在检测侧只成立一半

检测器**没有任何认证域规则**：`auth.cert`/`auth.fingerprint` 只进 `/trace` 证据，A4 的可检测签名与“纯 CAM 位置欺骗”完全相同（都是 `cam_position_jump`/`cam_gnss_mismatch`）。实测 A4 只产生 `cam_position_jump ×3, cam_gnss_mismatch ×3`，`auth.*` 流 31 条、0 条告警。

因此“双因素仿冒”目前是**攻击侧双因素、检测侧单因素**。要么补一条不依赖 `cloned` 标记的规则（同 `node_id` 的指纹中位数 vs 单条 RSSI 偏离 >3 dB，且 CFO/IQ 与中位数一致），要么在 A4 §7 明确写“认证腿不参与检测，只用于溯源”。

### 4.2 A6 的 QoS 降级没有行为消费者

`smf.degraded` 只出现在核心网状态向量（面板/`snapshot`）里，没有任何队列、调度或 CPM 投递逻辑读它；`v2x.cpm` 是 RSU 广播，也没有“按 UE 的接收”。所以 A6 在数据面上的真实足迹只有：**全局 ingest 延迟 + 一次注入制动 + 一条伪造 CPM**——与 A5 的延迟腿、A2 的制动腿高度重叠。这是“A6 是不是独立攻击类型”的实质风险，比 amplitude 无效严重。

### 4.3 上一轮 `observed` 实现的两个洞（自查）

1. `engine` 只在**没有显式 sink** 时包 `CountingSink`；测试/嵌入方传 `sink=` 时 `stats.stream_records` 恒空 → `evidence_seen` 永远是 `[]`、`evidence_missing` 是全量。已实测。
2. `scheduler` 在 `inst.start(ctx)` **之后**才快照 `_stream_base`；`start()` 内发出的证据（A5 的 `app.control`、A4 的 `auth.cert`）被算作“攻击期间未出现”，实测 `app.control` 被误记为 missing。

修法都是一行级：engine 里无条件包 `CountingSink`；`_stream_base` 提前到 `start()` 之前。

### 4.4 A5/A6 共用 `platform_ingest_delay_ms` 单键

两者并发时，先 `stop()` 的一方会 `pop` 掉另一方的延迟（A5 每 tick 重设，只抖 1 tick；A6 的 80 ms 则可能整段丢失）。这是“把剧本状态塞进 `ctx.extras`”的典型代价，建议改成 `platform.ingest_overhead_ms` 由平台层持有、按来源取 `max()`。

1. **NF 容量必须重标定**：A5 走真实 AMF 后，5000/s 容量在单路口场景打不满，而真打满
