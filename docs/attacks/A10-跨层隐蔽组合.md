# A10 跨层隐蔽组合：代码走读与实现解析

> 代码基线：`feature/trace-watch`（v0.3.0 + A1–A10 TraceProfile），2026-11-03。
> 共享机制见 [A1 §2–§4](A1-感知篡改诱导通信拥塞.md)；本文只写 A10 的差异。
> 目标：解释“雷达渐偏 + 轻度信令 + 审计抑制 + 小制动”的组合路径，并说明哪些是隐蔽性设计、哪些只是声明。

## 1. 一句话概括

A10 做四件事：

1. 对 victim 的 `sensing.radar.echo.range_m` 做线性渐偏（`bias_max = 1 + 5.5a`，只偏**服务传感器**）；
2. 每 0.2 s 发 `1+4a` 条真实 `core.nas` 注册（5–25 条/s），并把 AMF 显示负载钉在 70%；
3. 写一条 `app.audit` 后再 `suppress(2+2a)`，制造审计序列缺口；
4. 在时长 60% 处注入两次 `inject_brake(0.8+1.2a, 0.8)`，并再制造两次审计缺口。

它比 A5 轻、比 A3 多一层信令/审计噪声；目的是让单一域看起来都不够异常。
信令是真实注册（走 AMF 队列），但 5–25 条/s 远低于洪泛阈值，所以**不会**触发
`nas_registration_flood`——这是“隐蔽”的一部分。

## 2. 端到端调用链

```text
POST /api/attacks {type:"A10", amplitude, duration, start}
  → CampaignA10.ready(ctx)：等 core/platform/有车
  → CampaignA10.start(ctx)
      ├─ victim：target 优先；否则从“当前被某传感器看到”的车里挑
      ├─ sensor：victim 的服务传感器（找不到就取最近）
      ├─ bias_max = 1 + 5.5a；signal_n = 1 + 4a；audit_n = 2 + 2a；decel = 0.8 + 1.2a
      ├─ 注册 sensing.radar.echo hook（按 sensor_id + entity 过滤）
      ├─ core.amf.set_hold(capacity×0.70)     ← 只影响显示负载/时延
      └─ audit.append(probe) + audit.suppress(audit_n)
  → 每 0.2 s CampaignA10.tick(ctx)
      ├─ signal_n 条 core.amf.start_registration(retry=False)
      └─ t >= t0 + duration×0.6 且 _audit_used<2：
          audit.append(probe) + audit.suppress(audit_n)
          control.inject_brake(decel, 0.8)
  → stop(ctx)
      └─ amf.set_hold(0)，回填 audit_suppressed / sensor
```

层序：

```text
scheduler → sensing → v2x → uu → core → auth → platform → control
```

- 雷达 hook 在 sensing 生效；
- bot `core.nas` 在 scheduler emit，core 层同一 tick 能看到 AMF 负载；
- 审计事件在 platform tick 之前 emit，平台 audit 状态直接改；
- 小制动在 scheduler 调用，同一 tick 进控制面。

## 3. 参数

| 量 | 公式 | `a=0.8` 实测 |
|---|---|---:|
| 最大偏置 | `1.0 + 5.5a` m | 5.4 m |
| 信令 | `1 + 4a` 条 / 0.2 s | 20 条/s |
| 审计抑制 | 每次 `2 + 2a` 条，共 3 次 | 12 条 |
| 制动 | `0.8 + 1.2a` m/s²，0.8 s | 1.76 |
| 包络 | `bias >= 3.0 m 且 signaling >= 15/s` | true |

`signaling_rate` 由 `signal_n×5` 派生（5–25/s），`bias_max` 随 amplitude 变；
`audit_suppressed`、`sensor`、`sensor_locked` 在 `stop()` 回填。

## 4. 注入点

### 4.1 雷达渐偏

```python
def hook(payload, _ctx):
    if payload.get("sensor_id") != self.sensor_id:     # 只偏服务传感器
        return payload
    if payload.get("entity") != entity:
        return payload
    frac = max(0.0, min(1.0, (_ctx.t - self.t0) / max(self.spec.duration, 1e-6)))
    payload["range_m"] = round(float(payload["range_m"]) + self.bias_max * frac, 3)
    return payload

self.hook(ctx, "sensing.radar.echo", hook)
```

**与 A3 不同**：A10 只改 `range_m`（不改 `azimuth_deg`），且改的是 **victim 自身回波**
（A3 已改为改前车回波 + 距离/方位联合伪造）。因此 A10 的雷达腿不会驱动 ADAS，
点迹仍由被改回波派生，目标列表位置也随测距重建。

**两个关键点（旧实现都错了）**：

1. **只偏一个站**。旧 hook 不带 `sensor_id` 过滤，所有看到 victim 的站都被加同一偏置，
   跨站位置差恒为 0 → `radar_range_bias`（要求同 entity 跨站差 >6 m）**永远不可能触发**。
   现在只偏服务传感器，跨站差 ≈ bias：a=1.0（6.5 m）实测能触发，a=0.8（5.4 m）仍不触发。
2. **服务传感器是“真的看到 victim 的站”**。启动时先用 `serving_sensor` 占位，
   然后在 tick 里按目标列表锁定第一帧真正报了该车的传感器；真值 `nodes`/`params.sensor`
   在 `stop()` 回填（旧实现写死 `RSU-01`，实测 victim 实际由 `RSU-03` 看到）。

### 4.2 轻度信令

```python
if self._pacer.due(ctx.t, max_burst=1):
    for _ in range(self.signal_n):
        core.amf.start_registration(ctx, f"a10-ue-{self._seq:04d}", "GNB-01",
                                    retry=False)
```

- 真实注册（走 AMF 队列），`retry=False` 不会在攻击结束后继续灌；
- `Pacer(5 Hz)` 每 0.2 s 触发一次，每次 `1+4a` 条 → 5–25 条/s；
- **低于洪泛阈值**（检测器要求 1 s 内 ≥300 条且拒绝占比 ≥10%），所以不会触发
  `nas_registration_flood`。旧实现写死 `bot=True` 且自报 `reject`，才“被检出”。

### 4.3 审计抑制

```python
platform.audit.append(ctx, actor="attacker:A10", action="probe",
                      resource="audit", result="accept")
platform.audit.suppress(2)
```

`AuditLog.suppress()`（[audit.py](../../isacsim/layers/platform/audit.py:47)）只推进 `seq`，不写记录：

```python
def suppress(self, n=1):
    self.seq += n
    self.suppressed += n
```

检测器看到下一条 `app.audit` 的 `audit_seq` 跳号，就报 `audit_gap`。

在 60% 处：

```python
if self._audit_n < 2 and ctx.t >= self.t0 + duration*0.6:
    self._audit_n += 1
    audit.append(probe)
    audit.suppress(1)
    control.inject_brake(1.2, 0.8)
```

因为每 tick 都满足条件，`_audit_n` 会从 0→1→2，连续两 tick 各注入一次制动；实测 `control.command` 2 条。

### 4.4 AMF 负载

```python
core.amf.set_hold(core.amf.queue_capacity * 0.70)
```

`set_hold()` 只抬 **显示负载/时延**：`load_hint=0.7`、`latency_ms` 上涨，但**不参与准入**、
`overloaded` 仍为 False，也不会 emit `amf_overload`。`core:amf` 健康度会变橙/红，
核心网其实并不忙。

## 7. 检测侧看到了什么

| 规则 | 触发 | 实测 |
|---|---|---|
| `audit_gap` | `audit_seq` 跳号 | 1 条 |
| `brake_without_hazard` | ttc>=10 | 1 条 |
| `radar_range_bias` | 同一 entity 跨站位置差 >6 m、连续 3 帧 | a=1.0 时 1 条；a=0.8 时 0 条 |
| `nas_registration_flood` | 1 s 内 ≥300 条且拒绝占比 ≥10% | **0 条**（信令是 20/s，低于阈值） |

seed=14、a=0.8、3 s 攻击实测：

```text
audit_gap ×1, brake_without_hazard ×1（雷达与洪泛都不触发）
```

a=1.0（bias 6.5 m）实测才会出现 `radar_range_bias ×1`——前提是 victim 同时被 ≥2 个站看到；
单站可见时即使 bias 很大也不会触发。“有渐偏”不等于“必然告警”。

## 8. 外部检测视角：数据支撑、`/trace` 位置与 `out/` 落点

> 本节假设判定在仿真之外完成：只看导出的观测流与日志，不读 `truth/`、不读 `ctx.extras`。可观测面清单与路径/落盘规则见 [A1 §9.1、§9.4](A1-感知篡改诱导通信拥塞.md)。

### 8.1 判定 A10 需要的数据支撑

A10 的每个动作都刻意压低强度：雷达偏 1–6.5 m（默认 5.4 m）、信令 5–25/s、审计每次吞 2–4 条、制动 0.8–2.0 m/s²。单看任何一路都只是“弱异常”，判定必须做**跨层弱证据的联合**。

| 观测面 | 需要捕获的字段 | 在判定中的作用 | 可依赖度 |
|---|---|---|---|
| `sensing.radar.echo` / `track` | `entity`、`frame_seq`、`range_m`、`pos_x/pos_y` | 残差缓增（同 A3，但更小），单帧低于常规门限 | 物理证据 |
| `core.nas` | `msg_type`、`ue_id`、`result`、`cause`、`latency_ms` | 每 0.2 s `1+4a` 条真实注册（5–25/s），**低于洪泛阈值** | 协议证据（不含任何标记） |
| `app.audit` | `audit_seq`、`prev_hash`、`hash`、`actor`、`action` | `audit_seq` 跳号（实测 1,2,5,7：缺 3/4/6）；哈希链本身仍闭合（`prev_hash` 指向上一条已写记录） | 物理证据（可验证） |
| `core:amf` 状态 | `load_hint`、`queue_depth`、`health` | `load_hint=0.7`（`set_hold` 的显示负载），但**没有** `amf_overload` 事件 | 状态证据（`out/` 无快照） |
| `control.command` | `params.decel_mps2`、`params.ttc_s` | 两条 `ttc=99`、`decel=1.2` 的小制动 | 物理/协议证据 |
| `sensing.objects` / `v2x.cam` / `sensing.gnss` | 位置、速度 | 正常 → 排除 A1/A4 | 反证 |
| `link.metrics` | `cbr`、`jam` | 不变 → 排除 A1/A2 | 反证 |

判定口径：

```text
T1 雷达残差缓增（同 A3 的 K1），默认幅度 5.4 m、单帧多低于 6 m 门限；
   跨站差 >6 m 时（a≈0.91 以上，且 victim 被 ≥2 站看到）才会被 `radar_range_bias` 命中。
T2 1 s 内注册请求 5–25 条，但远低于洪泛阈值（300 条/s）→ “轻度信令”。
T3 app.audit 的 audit_seq 出现跳号（每次缺 1–2 条），而 prev_hash/hash 链仍能闭合
   → 不是写入失败，而是“被跳过的审计”。
T4 control.command 的 ttc_s=99、decel<=1.5，共两条。
=> T1∧T2∧T3 判“跨层隐蔽组合”；T4 是动作证据。单看任一条都只能判“弱异常”。
```

边界：

- AMF 的 `load_hint/queue_depth` 由 `set_hold()` 抬升，只影响显示负载/时延、不参与准入，
  所以**没有** `amf_overload` 事件；不要拿“没有过载事件”否定；
- 审计抑制只推进 `seq`，被吞的记录不会出现在任何流里，只能靠序号缺口与平台侧 `suppressed` 计数发现；
- `signaling_rate` 由 `1+4a 条/0.2 s` 派生（5–25/s），与真值一致；
- `nodes` 里的传感器由 `stop()` 回填成**真正看到 victim 的站**（`params.sensor`、`sensor_locked`）；
- 雷达告警取决于两个条件同时满足：`bias > 6 m` **且** victim 被 ≥2 个站同时看到。
  默认 a=0.8（5.4 m）不会触发；单站可见时即使 a=1.0 也不会触发。静默不等于没有偏置。

## 9. 时序

| 相对 `t0` | 事件 |
|---:|---|
| 0 | 锁定服务传感器并挂 hook；`set_hold(70%)`；审计 append + suppress(audit_n) |
| +0.2 | 第一批 `signal_n` 条真实注册（5–25/s） |
| +1.8 | 第一次审计缺口 + 小制动（decel=0.8+1.2a） |
| +1.85 | 第二次审计缺口 + 小制动（`_audit_used=2`） |
| `t1` | `set_hold(0)`；回填 `sensor/audit_suppressed`；雷达偏置随 hook 摘除停止 |

## 10. 边界与差异

1. **`signaling_rate` 随幅度变**：5–25/s，远低于洪泛阈值，所以**不会**触发 `nas_registration_flood`。
2. **AMF 负载是展示状态**：`set_hold` 只抬 `load_hint/latency`，不参与准入、没有 `overloaded=True`。
3. **审计抑制不删除已有记录**：只推进 `audit_seq`，制造缺口（每次 2–4 条，共 3 次）。
4. **两条小制动**：60% 条件在多个 tick 都成立，`_audit_used` 限制两次；decel 0.8–2.0。
5. **`nodes`/`sensor` 是运行时锁定的真实站点**：启动时先用 serving 占位，tick 里按目标列表锁定，
   `stop()` 回填；`sensor_locked=false` 表示整段都没被任何站看到（雷达腿空转）。
6. **`stop` 只清显示负载**：审计序列不需要恢复（一次性缺口），已注入的制动按 duration 执行完。
7. **雷达规则要两个条件同时满足**：`bias > 6 m`（a≥0.91）**且** victim 被 ≥2 个站看到。
   默认 a=0.8 是 5.4 m，不触发——这是“隐蔽”的应有之义，不是缺陷。

```text
radar.echo 渐偏（1+5.5a = 1..6.5 m，只偏服务传感器）
        +
每 0.2 s 1+4a 条真实注册（5..25/s，低于洪泛阈值）
        +
audit append + suppress(2+2a)（seq 缺口）
        +
60% 处两次 inject_brake(0.8+1.2a, 0.8)
        │
        ├─ audit_gap                      ← 默认幅度下主要靠这条
        ├─ brake_without_hazard
        └─ radar_range_bias               ← 仅 a≥0.91 且多站可见
```

A10 的“隐蔽”不是单点不可见，而是把雷达、信令、审计、控制四个域的异常都控制在“单独看都不够确定”的强度；检测需要跨域关联。

**但要说清两条边界**：雷达腿默认 5.4 m，低于跨站 6 m 门槛，**当前检测器不会报**；
信令 20/s 也远低于洪泛阈值，**不会报**。默认幅度下 A10 真正能被规则抓到的是
`audit_gap` 与 `brake_without_hazard`——“四域同向”是分析口径，不是现有规则的现状。
