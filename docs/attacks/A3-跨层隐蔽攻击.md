# A3 跨层隐蔽攻击（雷达回波渐偏）：代码走读与实现解析

> 代码基线：`feature/trace-watch`（2026-11-05，A3 跨层链修订）。
> 共享机制见 [A1 §2–§4](A1-感知篡改诱导通信拥塞.md)；本文只写 A3 的差异。
> 目标：从 A3 启动开始，走完“篡改回波 → 目标列表位置偏移 → ADAS 误判制动 → 伪指令 + 掩盖”，
> 并说明哪些是代码保证、哪些依赖场景条件。

## 1. 一句话概括

A3 做三件事，**而且第一件会真的改变车辆行为**：

1. 选中“受害车 + 它前方的一辆车”，篡改那辆前车在**受害车服务传感器**上的回波
   （距离 `range_m` 与方位 `azimuth_deg` 一起改），让它看起来在 1–2 s 内被“拉近”到车前；
2. `sensing` 用“距离+方位”重建目标列表位置 → 受害车 ADAS 算出的 TTC 掉到 2.5 s 以下 →
   **触发一次本不该有的 TTC 制动**；
3. 在攻击 60% 处再注入一条**幅度随偏移递增**的伪控制指令（`reason=injected`, `ttc=99`），
   同时压低被篡改回波的 SNR/幅度并打 `masked` 标记（“掩盖”），另发一条 `telemetry.mask` 记录。

与旧版的差别：旧版只改“受害车自己的回波”（别人怎么看它），且目标列表用真值坐标，
所以偏置**没有任何下游消费者**——只能写进记录、触发检测器，不会改变任何车辆行为。
本轮修订改成“改前车 + 位置由测距重建”，跨层链才真正成立。

## 2. 端到端调用链

```text
POST /api/attacks {type:"A3", amplitude, duration, start}
  → CampaignA3.start(ctx)                    campaigns.py:272
      ├─ _pick_pair(ctx)                     选 (victim, lead, sensor)
      ├─ _aim(...)                           算表观目标距离 lon_end / 计划位移 bias_max
      └─ hook("sensing.radar.echo")          只改 sensor=受害车服务传感器 且 entity=veh:<lead>
  → 每帧 sensing._emit_frame()               sensing.py:110
      ├─ echo 生成 → hook 改写 range/azimuth/snr
      ├─ track 由“改后回波”派生（pos_x/pos_y 仍是真实位置）
      └─ objects 的位置由 range+azimuth 重建          ← 本轮新增，关键
  → 每 tick control.tick()                   control.py:60
      └─ 受害车 ADAS 读 objects → _find_hazard → TTC<2.5 → control.command(reason=ttc)
  → CampaignA3.tick(ctx)                     campaigns.py:352
      └─ 60% 处：inject_brake(decel=1.0+1.5×frac) + emit telemetry.mask
```

层序 `scheduler → sensing → v2x → uu → core → auth → platform → control`：

- hook 在 `sensing` 阶段生效，同 tick 的 `control.tick()` 就能看到被改的目标列表；
- 伪指令在 `scheduler` 阶段注入，同 tick 就产生 `control.command`。

## 3. 选目标：不是随机挑车

```python
# _pick_pair → _lead_score（campaigns.py:213）
feasible = 0 if closing >= 1.2 else 1
cand = (tier, feasible, -closing, lon, obj)
```

评分顺序：

1. **tier**：0=本车道前方 2–60 m；1=前方但横向 ≤4.5 m；2=视野内最近的其它车（兜底）
2. **feasible**：接近速度 `closing ≥ 1.2 m/s` 记 0，否则记 1
3. 再看 `-closing`（越大越优先）、`lon`（越近越优先）

为什么要看 `closing`：ADAS 只在 `TTC < 2.5 s` 时制动，而 `_find_hazard` 要求纵向距离 >2.0 m，
所以 **TTC 下限 ≈ 2.0/closing**。`closing < 0.9 m/s` 时无论把目标拉多近都不可能越过阈值——
这类样本里 A3 只能产生“回波偏置 + 伪指令”，不会产生 ADAS 误刹，真值 `bias_max_m` 会如实记 0 或很小。

选定的受害车（`veh_id`）在攻击期间**不变**；只有前车驶出视野或受害车换了服务传感器时才重选前车（`_pair_stale` / `_repick_lead`）。

## 4. 注入点

### 4.1 回波：距离 + 方位一起改

```python
lon = (lead.x - ego.x)·heading + (lead.y - ego.y)·lateral      # 真实纵向距离
closing = max(ego.speed - lead 在航向上的投影, 0.2)               # 当前接近速度
target_ttc = 3.2 - 2.0 × amplitude                               # a=0.8 → 1.6 s；>2.45 视为包络外
lon_target = max(2.2, target_ttc × closing)
if lon_target >= lon: app_lon = lon                              # 低幅度不拉近
else:                 app_lon = lon - (lon - lon_target) × frac  # frac = (t-t0)/min(2s, 0.6·duration)
p = ego.pos + heading·app_lon + lateral·lead_lat                 # 伪造后的世界点
range_m   = |p - sensor|
azimuth   = atan2(p - sensor) - sensor.yaw
```

- **为什么必须改方位**：只改距离时，路侧视角会把目标沿视线推出车道（RSU 在路边，视线与车道有 10–20° 夹角），
  重建出的位置横向偏出 2.2 m 的门限，ADAS 根本不会把它当成前方危险物；
- **为什么渐变**：`frac` 在 2 s（或 60% 时长）内线性到 1，单帧位移只有十几厘米，
  回波序列看起来像“目标在正常接近”，而不是瞬移；
- **量级**：位移 = `lon - lon_target`，实测 8–58 m（取决于跟前车的初始距离），真值 `params.bias_max_m` 记录它。

### 4.2 掩盖

```python
payload["snr_db"]   -= 3.0 × frac
payload["amplitude"] *= (1 - 0.35 × frac)
payload["masked"]    = True
```

回波被降信噪比/降幅度后，在“弱信号”解释下更不显眼；代价是更容易被 `radar_range_bias` 抓到
（该规则只看残差，不看 SNR）。

### 4.3 伪控制指令

```python
decel = round(1.0 + 1.5 × frac, 2)     # 60% 处注入 → 1.9 m/s²
control.inject_brake(ctx, victim, decel=decel, duration=0.8)
ctx.emit("telemetry.mask", ...)        # 记录掩盖动作
```

`ttc_s=99`、`src=attacker:ctl-<vid>`、`reason=injected`，与 A2 同源但幅度更小（≤2.5 m/s²）。

## 7. 检测侧看到了什么

| 规则 | 触发 | 实测（seed 3/8/12/14/21, a=0.8） |
|---|---|---|
| `radar_range_bias` | 同一 entity 在两个站点上的位置差 >6 m 且连续 3 帧 | ✅ 4–6 条 |
| `brake_without_hazard` | `ttc_s ≥ 10` | ✅ 1 条（伪指令） |
| `ghost_object` | 目标列表出现地图外静态物 | ❌ 不触发（A3 不塞幽灵，这是它比 A1/A2 隐蔽的地方） |
| `link_degraded` / `cbr_spike` | PER/CBR | ❌ 不触发 |

`radar_range_bias` 本轮从“同一 track 内 range vs pos 的残差”改为**多站点位置互证**：
A3 只篡改受害车服务传感器的回波，其他站点仍测到真实位置，二者相差数十米，
这是跨源证据，不依赖生成器回填的真值坐标（审核 R3）。

| 相对 t0 | 事件 |
|---:|---|
| 0 | 锁定受害车 eastbound.3 / 前车 / RSU-01，算 `bias_max=57.5 m` |
| 0～2 s | 回波距离与方位渐变，目标列表里的前车位置逐步靠近 |
| ~1.2 s | 表观 TTC 跌破 2.5 s → ADAS 发 `control.command(reason=ttc, ttc≈2.35, decel=3.0)` |
| ~1.2 s～ | 受害车真实减速（`vehicle.speed_drop`） |
| 3.6 s (60%) | 注入 `decel=1.9` 的伪指令 + `telemetry.mask` |
| 6 s | 摘 hook，回波恢复正常 |

## 9. 边界与前提

1. **需要“在接近”的跟驰对**：`closing < ~0.9 m/s` 时 TTC 下限也到不了 2.5 s，A3 不会触发 ADAS 误刹；
   这时它只留下回波偏置与伪指令。实测 6 个 seed 中 5 个触发，1 个（seed 17）因车流速度接近而未触发。
2. **偏置量级不小**：为了越过 2.5 s 门限，表观距离要压到 2–10 m，位移常达 20–50 m。
   “隐蔽”来自**渐变 + 压低 SNR + 不新增目标**，而不是“偏置很小”。旧文档里“0.8–3 m 小幅渐偏”的说法已作废。
3. **目标列表现在等于“测量重建值”而非真值**：这是 A3 能传导的前提，也意味着
   `sensing.objects` 与真值的偏差本身成为可用证据（对 A1/A2 无影响：幽灵是注入的，真车只是多了测距噪声）。
4. **换前车时偏置按当前进度直接生效**：`frac` 是全局进度，重选前车不会从 0 重新渐变（叙述上是“攻击者换了个目标继续”）；
   受害车在攻击期间不变。真值的 `params.lead` 记录的是**开局锁定**的前车，若中途换目标，以 `telemetry.mask.target` 与后续告警的 entity 为准。
5. **`telemetry.mask` 是记录，不是真隐瞒**：检测器仍能看到原始回波与残差。

## 12. 小结

```text
受害车服务传感器 ← 前车回波被改（距离+方位，渐变，压低 SNR）
        │
        ├─ 目标列表位置 = 测距重建 → 前车看起来被拉近
        │        └─ ADAS TTC < 2.5 → 真的误刹（control.command reason=ttc）
        │
        └─ 60% 处：inject_brake(decel=1.9) + telemetry.mask（伪造“弱信号”）
```

A3 与 A1/A2 的关键区别：**A1/A2 往目标列表里“加”东西（会被 ghost_object 抓到），
A3 改的是测量值本身——目标列表里没有新目标，只有位置错了**。所以它必须靠
“测距 vs 几何”的跨层残差来抓，而不是“多出来的目标”。
