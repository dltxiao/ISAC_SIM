## 2 关键设计

### 2.1 唯一世界状态

所有轨迹来自 SUMO。感知层只做几何反演（距离、方位、径向速度、SNR），不自行造轨迹。
这样"真值"只有一个来源，跨源一致性才有意义。

### 2.2 攻击只改发射器输出

所有记录经 `HookBus`（`isacsim/core/context.py`）后落盘。攻击原语的钩子只修改
`payload`，不触碰 SUMO 状态：

```
世界状态（干净） → 发射器 → [攻击钩子] → 记录 → 落盘/检测
```

因此"观测"可被污染，"世界"不会；真值始终来自世界侧。

### 2.3 控制闭环

`ControlLayer` 消费**被篡改后的** `sensing.objects`，计算 TTC，触发 AEB，并通过
`SumoBackend.slow_down()` 写回 SUMO。于是：

- A1 的幽灵目标 → 车辆真实制动 → DENM → CAM 升频 → CBR 上升；
- A2 的假停止牌 → 车辆急刹 → 任务偏差。

这让"感知篡改导致通信拥塞"成为可观测的因果链，而不是两件并列的事。

### 2.4 确定性

- 主种子派生每条流/每个实体的独立 RNG（`isacsim/core/rng.py`）；
- SUMO `--seed` + 固定步长；
- 同种子、同配置的输出文件逐字节一致（gzip 需解压后比较）；
- 批处理按"一场景一进程一种子"分配，不受并行度影响。

| 平台（v0.3.0） | `app.auth`、`app.ingest`、`app.subscription`、`app.control`、`app.audit` | IAM/订阅/Ingest/云控/审计；消费 CPM/DENM/SPaT，控制意图交给 ControlLayer |
| 防御（v0.3.0） | `defense.action` | AMF 限流/拒绝、SMF 释放、UPF 回切、NEF/平台 token 吊销、源隔离；含时延与附带损伤 |

## 4 数据契约

本章是数据字典：先给时间/坐标基准与统一信封，再按实体汇总产出，最后逐流解释每个字段。
生成公式与代码位置的完整说明见 [实现原理与数据生成](07-实现原理与数据生成.md)，
攻击参数与阶段见 [跨层攻击剧本目录](02-跨层攻击剧本目录.md)。

### 4.1 时间与坐标基准

| 项 | 约定 |
|---|---|
| 世界坐标 | 局部 ENU：`x` 向东、`y` 向北，单位 m；原点为路网 `(0,0)` |
| 航向 | `heading_deg`：0°=+x（东），逆时针为正；由 SUMO 的"北=0、顺时针"换算 `heading = (90 − angle) mod 360` |
| 仿真时间零点 | `T0_NS = 1730842800e9`（2024-11-05T21:40:00Z，东八区 11-06 05:40） |
| 时间戳 | `ts_ns = T0_NS + round(t·1e9)`，`t` 为仿真秒；跨流对齐只用这一列 |
| 落盘时间 | `t_wall_ns = time.monotonic_ns()`，仅用于本进程内的时延测量 |
| 物理量单位 | 距离 m、速度 m/s、角度 °、RCS dBsm、功率/信噪比 dB、时延 ms、频率 Hz |

### 4.2 记录信封

每条记录一行 JSON，所有流（v0.3.0 起含 `core.*`/`app.*`/`defense.*`）共用同一信封（`isacsim/core/records.py`）：

```json
{"schema":"isacsim.record/2","run_id":"arterial-11-1793322663","stream":"v2x.cam",
 "ts_ns":1730842800100000000,"t_wall_ns":146008713807768,
 "source":"east_truck.0","entity":"veh:east_truck.0",
 "trace_id":"tr-000123","span_id":"sp-000456","parent_span_id":"sp-000123",
 "payload":{...}}
```

| 字段 | 类型 | 含义 | 用途 |
|---|---|---|---|
| `schema` | str | 契约版本，当前 `isacsim.record/2` | 导入端做兼容判断；破坏性变更时递增 |
| `run_id` | str | `<场景>-<种子>-<Unix 秒>` | 与运行目录、`truth/manifest.json` 对齐 |
| `stream` | str | 流名（决定文件名和消费方） | 路由/过滤，不解析 `payload` 即可分流 |
| `ts_ns` | int | 仿真时间（ns） | 跨源对齐、事件匹配、窗口统计 |
| `t_wall_ns` | int | 单调时钟（ns） | 检测时延（`now − t_wall_ns`），不可跨进程比较 |
| `source` | str | 产生该记录的节点/组件（传感器 ID、车辆 ID、`MEC`、`ATK-*`、`adas:<vid>`） | 溯源；同一实体可由多个 source 描述 |
| `entity` | str | 被描述对象；v0.3.0 起增加 `ue:`/`amf:`/`smf:`/`upf:` 等 | 告警归属、跨层关联、图节点 |
| `trace_id` | str? | 一次注册/PDU/切换/NEF 订阅等过程的关联 ID | 跨层因果、链级评估 |
| `span_id` | str? | 本条消息的 span | 跨层因果、链级评估 |
| `parent_span_id` | str? | 触发本消息的上一条 span | 还原调用链 |
| `chain_id` | str? | 攻击链 ID（正常流量为空） | 链级评估/回放 |
| `payload` | object | 流特定字段（§4.4–§4.7） | 特征/检测输入 |

`trace_id`/`span_id`/`parent_span_id`/`chain_id` 是可选的；核心网/平台 snapshot 的每个节点额外带 `health`（status/score/reasons/metrics），供 Web 叠加视图着色。

`source` 与 `entity` 不是一回事：`sensing.objects` 的 `source=RSU-01`、
`entity=rsu:RSU-01`；`sensing.radar.echo` 的 `source=RSU-01`、`entity=veh:xxx`。
检测与评估按 `entity` 归属，按 `source` 追查是谁观测到的。

### 4.3 实体与数据产出总览

默认场景（`arterial`：双向三车道 + 信号路口 + 3 RSU + 1 通感基站 + 2 个静止设施）
跑 60 s 时，各实体的数据产出如下（实测值，单进程、无攻击）。车辆数由 SUMO 路网
流量决定（`vehicles.max` 只用于算力预检），同时在线 5–86 辆、均值 51。

| 实体 | `entity` 形态 | 规模 | 产生的流 | 说明 |
|---|---|---|---|---|
| 网联车 | `veh:<vid>` | 在线峰值 86、均值 51；60 s 内共出现 136 辆 | `sensing.gnss` 10 Hz；`v2x.cam` 10 Hz（装备率 90%）；`auth.cert`/`auth.fingerprint`（装备车）；`uu.attach`/`uu.handover`（装备车）；`task.state` 1 Hz；`control.command`（ADAS 车 60%，事件） | 同时作为目标出现在 `sensing.radar.*`、`sensing.objects`、`graph.snapshot` |
| 路侧单元 | `rsu:RSU-01..03` | 3 | `sensing.radar.echo/track`、`sensing.objects`、`sensing.frame` 10 Hz；`v2x.cpm` 10 Hz；`v2x.spat` 1 Hz | 图中含覆盖边（→ 车辆） |
| 通感基站 | `gnb:GNB-01` | 1 | 同感知四流，20 Hz；`gnb` 健康摘要 | 图中有节点；N2 连到 AMF |
| 核心网 NF | `amf:`/`smf:`/`upf:`/`nef:`/`udm:`/`ausf:`/`dn:` | 6 NF + DN | `core.nas`（注册/鉴权）、`core.session`（PDU）、`core.qos`、`core.handover`、`core.upf`、`core.nef` | 语义状态机，不是真实 5GC；节点 snapshot 带 `health` |
| V2X 平台 | `platform:V2X-01`、`tenant:<id>` | 1 平台 + 租户 | `app.auth`、`app.ingest`、`app.subscription`、`app.control`、`app.audit` | IAM/订阅/Ingest/云控/审计；`health` 由平台 snapshot 计算 |
| 防御动作 | `defense`（记录 `target` 指向实际节点） | 事件 | `defense.action` | 限流/释放/回切/吊销/隔离；含时延与附带损伤 |
| MEC/网络 | `net:pc5`、`net:uu`、`graph:scene` | 3 个逻辑实体 | `link.metrics` 10 Hz、`uu.session` 2 Hz、`graph.snapshot` 10 Hz | 汇聚侧指标，不对应单车 |
| 静止设施 | `obj:500`、`obj:501` | 2 | 无独立流，仅作为 `sensing.objects[].entity` 出现 | 停止牌（x=199,y=10）、障碍物（x=330,y=−5.5） |
| 攻击者 | `attacker:A1/A4`、`attacker:ctl-<vid>`、`attacker:<vid>` | 每起攻击 1 个 | 直接 emit `v2x.denm`/`v2x.cam`/`auth.cert`/`auth.fingerprint` | 记录带 `forged` 或 `cloned` 标记；伪造 CAM/指纹的 `entity` 仍写受害车，`source` 为 `ATK-*` |
| 幽灵目标 | `ghost:<oid>` | A1 每起 1–5 个 | 仅作为 `sensing.objects[]` 条目 | `object_id` 从 9000 起 |

v0.2.0 无核心网基线（60 s）共 **212,925 条 / 116.8 MB**（JSONL，未压缩），
其中感知三流占 ~68%，`graph.snapshot` 占 ~7%（单条 ~14 KB，可用 `streams.graph=false` 关闭）；
v0.3.0 的 `core.*`/`app.*`/`defense.*` 另行计数，未计入该基线。

同一辆装备车在同一时刻会出现在多条流里，但角色不同：

- `sensing.gnss`：**它自己**报的定位（加噪）；
- `v2x.cam`：**它自己**广播的位置（无噪）；
- `sensing.radar.echo/track`：RSU **看它**的回波与点迹（`entity=veh:<vid>`）；
- `sensing.objects`：RSU 汇总的目标列表里的一条；
- `graph.snapshot`：图中的一个节点；
- `task.state`/`auth.*`/`uu.*`：它自己的任务、凭证与连接状态。

跨层检测利用的正是这些"同一实体、不同来源"的差异（例如 CAM 位置 vs GNSS 定位）。

### 4.4 感知层数据

#### 4.4.1 `sensing.radar.echo`（雷达回波）

产生者：`SensingLayer`，每个传感器每帧对**每个被检出的车辆**一条。
60 s 共 68,712 条（≈1145 条/s），单条 ~463 B。

用途：A3 的作用面；点迹（track）的上游；回波级特征（RCS/SNR/相位）留给后续研究。
当前参考检测器**不直接消费**该流（见 §4.10）。

| 字段 | 类型/单位 | 含义与生成方式 | 用途 |
|---|---|---|---|
| `sensor_id` | str | 观测传感器（`RSU-01`…`GNB-01`） | 分源建模、多源融合 |
| `entity` | str | 被观测车辆 `veh:<vid>`（生成器写入的真值身份，不是检测输出） | A3 定位受害者；评估对齐；**检测不得使用** |
| `frame_seq` | int | 帧号 `round(t·rate_hz)`，同传感器内单调 | 按帧聚合、丢帧/时钟分析 |
| `target_id` | int | 传感器内航迹号，首次出现时分配，之后稳定 | 跨帧关联（距离偏置规则按它滑窗） |
| `range_m` | float, m | 站心平面距离 = 真值距离 + `bias_m` + N(0, 0.12+0.003r) | 距离量测；A3 直接改这个字段 |
| `radial_vel_mps` | float, m/s | 径向速度 `v·û`（正=远离），+N(0,0.15) | 多普勒特征；静止/运动判别 |
| `azimuth_deg` | float, ° | 相对视轴方位 `bearing − yaw`，折到 [−180,180) | 测角；与距离合成位置 |
| `elevation_deg` | float, ° | 目标（高 1.0 m）对传感器的俯仰角，向下为负 | 高程/遮挡辅助 |
| `rcs_dbsm` | float, dBsm | 卡车 12、其余 9，+N(0,0.6) | 目标分类辅助；A1 幽灵目标常配 0.6 m² 量级 |
| `snr_db` | float, dB | `32 − 0.045r` + 卡车 3 dB 处理增益 + N(0,0.8) | 检测置信度、信噪比筛选 |
| `amplitude` | float | 线性幅度 `10^(snr/20)`（用未加噪的 SNR 换算，故与 `snr_db` 有 ~0.8 dB 的随机差） | 与 SNR 冗余，便于直接做幅度域检测 |
| `phase_rad` | float, rad | 载波相位，U(0,2π)；未建模微多普勒 | 相位域方法预留位 |
| `ts_offset_ms` | float, ms | 本帧时钟偏移 = 配置 `offset_ms` + `drift_ppm·t` + N(0,0.4 ms) | 时钟同步/跨传感器对齐实验 |

#### 4.4.2 `sensing.radar.track`（点迹/航迹）

与回波一一对应，仅当回波未被攻击删除时产生。60 s 68,712 条，~454 B/条。

| 字段 | 类型/单位 | 含义与生成方式 | 用途 |
|---|---|---|---|
| `sensor_id`/`frame_seq`/`target_id`/`entity` | — | 同回波 | 关联 |
| `range_m` | float, m | 回波距离 + N(0,0.05)（跟踪平滑） | `radar_range_bias` 规则的被检量 |
| `radial_vel_mps` | float, m/s | 回波径向速度 + N(0,0.03) | 同上 |
| `azimuth_deg`/`elevation_deg` | float, ° | 直接继承回波（攻击改回波会传导） | 几何一致性 |
| `rcs_dbsm`/`snr_db` | float | 继承回波 | 置信度 |
| `confidence` | float [0,1] | `min(0.99, 0.75 + snr/200)` | 航迹质量加权 |
| `pos_x`/`pos_y` | float, m | 目标笛卡尔位置 = 世界真值 + N(0,0.15)（**不是**由 range/azimuth 反演，见 §7） | 与距离做残差；NIDD D0 |

用途：5G-A-NIDD 的 `d0.jsonl`；参考检测器的距离偏置规则；A3 的二次传导面。

#### 4.4.3 `sensing.objects`（路侧/基站目标列表）

每个传感器每帧一条，60 s 3,000 条（50 条/s），~5.4 KB/条。

记录级字段：

| 字段 | 类型 | 含义 | 用途 |
|---|---|---|---|
| `sensor_id` | str | 传感器 ID | 分源 |
| `coverage_id` | str | 覆盖区标识，默认 `<sensor_id>-COV` | 多传感器覆盖归并/去重 |
| `frame_seq` | int | 帧号 | 与 echo/frame 对齐 |
| `clock_offset_ms` | float | 本帧时钟偏移（同回波 `ts_offset_ms`） | 时间一致性 |
| `source_kind` | str | `rsu`/`gnb` | 源类型；决定融合权重 |
| `objects` | array | 目标数组，见下表 | 检测/控制的主输入 |

`objects[]` 字段：

| 字段 | 类型/单位 | 含义与生成方式 | 用途 |
|---|---|---|---|
| `object_id` | int | 车辆为航迹号；静止设施用配置 ID（500/501）；幽灵目标 9000+ | 帧内/跨帧关联；幽灵目标一眼可辨 |
| `cls` | str | `car`/`truck`/`motorcycle`/`bicycle`/`pedestrian`/`stop_sign`/`obstacle` | 分类；幽灵检测只看停止牌/障碍物 |
| `x`,`y` | float, m | 车辆真值 + N(0,0.15)；静止设施为配置值（无噪声） | 位置；几何一致性；TTC 计算 |
| `z` | float, m | 车辆 0.8；静止设施取配置（1.2/0.5） | 高程 |
| `l`,`w`,`h` | float, m | 车辆来自 SUMO 尺寸；静止设施 0.6×0.6×1.8 | 体积/遮挡/类别辅助 |
| `vx`,`vy` | float, m/s | 速度×朝向合成 + N(0,0.1)；静止为 0 | TTC 闭合速度、任务偏差 |
| `heading_deg` | float, ° | 0=+x，逆时针 | 航向一致性 |
| `confidence` | float | 车辆 `min(0.99, 0.88+N(0,0.03))`；静止 0.86 | 融合权重 |

#### 4.6.4 `auth.fingerprint`（信道指纹）

每装备车 1 Hz，60 s 2,887 条。

指纹基线由 `sha256(vid)` 确定性派生（同设备稳定、异设备可分）：
`cfo_ppm∈[−3,3]`、`iq_gain_db∈[−0.8,0.8]`、`iq_phase_deg∈[−4,4]`、`rssi∈[−70,−58] dBm`。

|---|---|---|---|

| `cfo_ppm` | float, ppm | 载波频偏 + N(0,0.03) | 设备指纹 |
| `iq_gain_db` | float, dB | IQ 增益失衡 + N(0,0.02) | 设备指纹 |
| `iq_phase_deg` | float, ° | IQ 相位失衡 + N(0,0.08) | 设备指纹 |
| `rssi_dbm` | float, dBm | 基线 + N(0,1.2) | 距离/发射功率代理 |

| `cloned` | bool | 仅 A4 出现；`rssi` 比基线高 4 dB | 攻击标记（不得作特征） |

用途：A4 的核心载体（克隆者复制 CFO/IQ，但 RSSI 因位置不同偏移）；
当前基线检测器未消费，靠 CAM/GNSS 一致性发现克隆。

### 4.8 攻击对字段的改写

攻击只改 `payload`，不新增流（除攻击者直接 emit 的记录）。逐类看：

| 攻击 | 被改/新增的记录 | 字段变化 | 可观测后果 |
|---|---|---|---|
| A1 感知篡改→拥塞 | `sensing.objects` | `objects` 追加 1–5 个幽灵（`object_id≥9000`、`entity=ghost:*`、`confidence=0.92`、`tracked_age=50`） | ADAS 触发真实制动 → `control.command(reason=ttc)` → `v2x.denm` → CAM 升频 → `link.cbr↑` |
| | `v2x.denm` | 新增 `forged=true`、`cause=obstacle_warning`，每 0.5 s 一条 | 通信负载上升 |
| | `link.metrics` | `offered_msgs_s` +150–650，`cbr`/`per`/`delay` 随之上升 | 拥塞可量化 |
| A2 物理欺骗+控制误导 | `sensing.objects` | 追加停止牌（`object_id=9100`，车前 28 m） | 目标列表出现"危险静态物" |
| | `control.command` | 新增 `reason=injected`、`src=attacker:ctl-<vid>`、`ttc_s=99`、`decel=3.0–5.5` | 车辆非必要急刹 |
| | `link.metrics` | `jam=0.05–0.4` → `cbr`/`per` 上升 | 链路恶化 |
| A3 跨层隐蔽 | `sensing.radar.echo` | `range_m` 按 0→0.8–3.0 m 线性渐偏 | 点迹继承偏差 |
| | `sensing.radar.track` | `range_m` 继承（+平滑噪声） | 距离偏置规则可检 |
| | `control.command` | 在攻击 60% 处注入 `decel=1.2`、`ttc_s=99` | 轻微减速，隐蔽 |
| | `sensing.objects` | **不变**（x/y 来自真值） | 目标列表层看不到 A3，必须下沉到回波/点迹 |
| A4 双因素仿冒 | `auth.cert` | 新增 `event=clone`、`cloned=true`、复用受害者 `cert_id/pseudonym` | 身份冲突 |
| | `v2x.cam` | 新增 `cloned=true`，`sender_pseudo=受害者`、`posx=victim.x+45`、`msg_id≥900000` | 位置跳变/与 GNSS 不一致 |
| | `auth.fingerprint` | 新增 `cloned=true`、复制 CFO/IQ、`rssi +4 dB` | 指纹侧证据 |

要点：`forged`/`cloned` 是**评估用标记**，参考检测器不读它们；否则等于泄题。

## 6 与现有系统的衔接

`isacsim/io/adapters/nidd.py` 把原生流转换为：

- `d0.jsonl`（点迹 ← `sensing.radar.track`）、`d1.jsonl`（目标列表 ← `sensing.objects`）、
  `d2.jsonl`（帧 ← `sensing.frame`）、`d3a/b/c.jsonl`（GNSS/控制/任务）；
- `cam.pcapng`（Ethernet/IPv4/UDP 封装的 CAM，纳秒时间戳 ← `v2x.cam`）；
- `labels.json` / `ground-truth.csv`（事件级真值 ← `truth/events.jsonl`）。

这样现有 5G-A-NIDD 的导入链路可直接消费；原生 schema 则保留了新增模态（信道指纹、
图快照）的扩展位。

## 7 非目标与已知边界

- 不做电磁仿真、原始 I/Q、相机图像渲染；
- 不做射频干扰硬件在环；
- 不在本环境内训练深度时序模型（无 GPU，且不应与"环境"耦合）。

数据模型层面的简化（使用数据前必须知道）：

1. **点迹位置由真值合成**：`sensing.radar.track.pos_x/pos_y` 直接取世界真值加噪声，
   不是由 `range/azimuth` 反演。因此 `radar_range_bias` 规则在生成器内部等价于
   "距离量测 vs 真值位置"的一致性检验；换到真实数据需改为多帧/多源一致性方法。
2. **遮挡只做丢弃**：被遮挡目标不输出，`objects[].occluded` 恒 `false`（预留位）。
3. **认证层不判决**：`auth_result` 恒 `pass`；A4 的发现依赖 CAM/GNSS 的位置一致性，
   认证特征（证书/指纹）目前只作证据，不进入基线规则。
4. **伪名不轮换**：`auth.cert` 每 6–12 s 轮换 `PN-<vid>-<idx>`，但 `v2x.cam.pseudonym`
   恒为 `PN-<vid>`，两者尚未打通；A4 克隆因此无法靠"伪名冲突"识别。
5. **A4 不伪造 Uu 附着**：A4 只声明实际可观测的 `auth`/`v2x` 域，攻击者注入
   `auth.cert`/`v2x.cam`/`auth.fingerprint`，没有伪造 `uu.attach`。
6. **图无认证边**：`graph.snapshot` 目前有覆盖边、`veh→gNB` 无线边、核心网/平台边，
   但没有认证边；覆盖边从 RSU 出发，无线边从 gNB 出发。
7. **任务偏差是速度代理**：`task.state.deviation_m` 计算的是 `abs(abs(vx)−15)`，不是路径偏差；
   `waypoint_idx` 是 `x//50` 的粗分段。
8. **参考检测器覆盖面有限**：不消费回波、CPM、SPaT、任务、图；核心网/平台只覆盖部分规则；
   它只是验证环境可用的基线，不是最终检测模型。
