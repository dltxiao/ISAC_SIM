## 2 关键设计

### 2.1 唯一世界状态

所有轨迹来自 SUMO。感知层只做几何反演（距离、方位、径向速度、SNR），不自行造轨迹。
这样"真值"只有一个来源，跨源一致性才有意义。

### 2.2 攻击只改发射器输出

所有记录经 `HookBus`（`isacsim/core/context.py`）后落盘。攻击原语的钩子只修改
`payload`，不触碰 SUMO 状态：

```
世界状态（干净） → 发射器 → [攻击钩子] → 记录 → 落盘/检测
```

### 2.3 控制闭环

`ControlLayer` 消费**被篡改后的** `sensing.objects`，计算 TTC，触发 AEB，并通过
`SumoBackend.slow_down()` 写回 SUMO。于是：

- A1 的幽灵目标 → 车辆真实制动 → DENM → CAM 升频 → CBR 上升；
- A2 的假停止牌 → 车辆急刹 → 任务偏差。

这让"感知篡改导致通信拥塞"成为可观测的因果链，而不是两件并列的事。

### 2.4 确定性

- 主种子派生每条流/每个实体的独立 RNG（`isacsim/core/rng.py`）；
- SUMO `--seed` + 固定步长；
- 同种子、同配置的输出文件逐字节一致（gzip 需解压后比较）；
- 批处理按"一场景一进程一种子"分配，不受并行度影响。

## 3 各层模型

| 层 | 输出流 | 模型要点 |
|---|---|---|
| 感知 | `sensing.radar.echo`、`sensing.radar.track`、`sensing.objects`、`sensing.frame`、`sensing.gnss` | 回波参数（range/doppler/az/el/rcs/phase/amplitude）→ 点迹 → 目标列表；检测概率、遮挡、时钟偏移、标定残差 |
| V2X | `v2x.cam`、`v2x.cpm`、`v2x.denm`、`v2x.spat`、`link.metrics` | 10 Hz CAM（紧急升频 20 Hz）、CPM/DENM/SPaT；CBR=负载/容量；PER=f(CBR)；DCC 降频带迟滞 |
| Uu | `uu.attach`、`uu.handover`、`uu.session` | 由 gNB 覆盖/FOV 驱动；附着、切换、会话（5QI/latency）；不再按定时器翻转小区 |
| 核心网（v0.3.0） | `core.nas`、`core.session`、`core.qos`、`core.handover`、`core.upf`、`core.nef` | AMF/SMF/UPF/NEF/UDM/AUSF 语义状态机；注册/鉴权/PDU 会话/QoS/TEID/NEF 订阅；见 [详细设计](10-通信层语义级拓展详细设计.md) |
| 平台（v0.3.0） | `app.auth`、`app.ingest`、`app.subscription`、`app.control`、`app.audit` | IAM/订阅/Ingest/云控/审计；消费 CPM/DENM/SPaT，控制意图交给 ControlLayer |
| 认证 | `auth.cert`、`auth.fingerprint` | 假名轮换、证书状态、CFO/IQ/RSSI 指纹（设备固有） |
| 控制 | `control.command` | TTC<2.5 s 触发 AEB，反应延迟 120 ms，执行器回写 SUMO |
| 任务 | `task.state` | 航路点、阶段、偏差、时限 |
| 图 | `graph.snapshot` | 100 ms 实体图（覆盖/无线/核心网/平台边）；v0.3.0 起节点带 `layer` |

## 4 数据契约

### 4.1 记录

```json
{"schema":"isacsim.record/2","run_id":"...","stream":"v2x.cam",
 "ts_ns":1730842800100000000,"t_wall_ns":123456789,
 "source":"OBU-004","entity":"veh:OBU-004",
 "trace_id":"tr-000123","span_id":"sp-000456","parent_span_id":"sp-000123",
 "payload":{...}}
```

- `ts_ns`：仿真时间（固定 T0 + t），用于跨源对齐；
- `t_wall_ns`：单调时钟，仅用于时延测量；
- `entity`：统一实体标识（`veh:`/`rsu:`/`gnb:`/`obj:`/`attacker:`，v0.3.0 起增加 `ue:`/`amf:`/`smf:`/`upf:` 等）；
- `trace_id`/`span_id`/`parent_span_id`：可选；用于跨层因果关联与链级评估。

### 4.2 文件

```
out/<run>/
  sensing.radar.echo.jsonl
  sensing.radar.track.jsonl
  sensing.objects.jsonl
  sensing.frame.jsonl
  sensing.gnss.jsonl
  v2x.cam.jsonl  v2x.cpm.jsonl  v2x.denm.jsonl  v2x.spat.jsonl
  uu.attach.jsonl  uu.handover.jsonl  uu.session.jsonl
  core.nas.jsonl  core.session.jsonl  core.qos.jsonl
  core.handover.jsonl  core.upf.jsonl  core.nef.jsonl
  app.auth.jsonl  app.ingest.jsonl  app.subscription.jsonl
  app.control.jsonl  app.audit.jsonl
  auth.cert.jsonl  auth.fingerprint.jsonl
  control.command.jsonl  task.state.jsonl  link.metrics.jsonl
  graph.snapshot.jsonl
  scenario.json  net.json  map.json
  truth/events.jsonl  truth/manifest.json
  alerts.jsonl        # 参考检测器
  meta.json           # 批处理元信息
```

`streams.gzip=true` 时后缀为 `.jsonl.gz`；`streams.parquet=true` 时写 Parquet。

## 6 与现有系统的衔接

`isacsim/io/adapters/nidd.py` 把原生流转换为：

- `d0.jsonl`（点迹）、`d1.jsonl`（目标列表）、`d2.jsonl`（帧）、`d3a/b/c.jsonl`；
- `cam.pcapng`（Ethernet/IPv4/UDP 封装的 CAM，纳秒时间戳）；
- `labels.json` / `ground-truth.csv`（事件级真值）。

这样现有 5G-A-NIDD 的导入链路可直接消费；原生 schema 则保留了新增模态（信道指纹、图快照）的扩展位。

## 7 非目标

- 不做电磁仿真、原始 I/Q、相机图像渲染；
- 不做射频干扰硬件在环；
- 不在本环境内训练深度时序模型（无 GPU，且不应与"环境"耦合）。
