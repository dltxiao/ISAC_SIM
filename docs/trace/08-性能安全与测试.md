# 08 性能、安全与测试

## 1. 数据量估算

以 60 s 默认场景、A1、10 个 target 为例：

| 数据 | 频率 | 60 s 量级 | 单条 | 备注 |
|---|---:|---:|---:|---|
| 4 个传感器 `objects` | 10–20 Hz | 3,600–4,800 帧 | 1–5 KB | 每帧 3–20 个对象 |
| 60 辆车状态 | 10 Hz | 36,000 条 | ~100 B | 只保留受影响/选中 |
| `link.metrics` | 10 Hz | 600 条 | ~200 B | 很小 |
| `control.command` | 事件 | 10–100 条 | ~300 B | 很小 |
| `v2x.denm` | 事件 | 10–50 条 | ~300 B | 很小 |
| `det:alerts` | 事件 | 10–100 条 | ~300 B | 很小 |
| `atk:*` | 事件 | <20 条 | ~1 KB | 很小 |
| `truth` | 事件 | 1–10 条 | ~1 KB | 可选 |

结论：**只订阅 10 个 target 时，60 s 数据量约 5–20 MB，完全可放内存**；不需要全量 21 万条记录。

## 2. 开销预算

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 墙钟开销 | <5% | 同场景 trace on/off 对比 |
| 仿真线程单 tick trace 耗时 | <1 ms | 计时 |
| 内存 | <50 MB（60 s A1） | RSS/对象计数 |
| SSE 带宽 | <200 KB/s | 抓包/计数 |
| 前端单帧 | <16 ms | Performance 面板 |
| 单步响应 | <2 s | API 计时 |
| 事件丢弃 | 关键事件 0；watch <1% | `dropped` 计数 |

### 2.1 开销控制

- record probe 只投影需要字段，不深拷贝整条 record；
- hook diff 只在 `trace_enabled` 且 stream 在 watch 列表时开启；
- 每个 target 每 tick 最多一帧；
- `same` 帧合并；
- 大表截断到 200 行；
- 序列化在 API/SSE 线程做，不在仿真线程做；
- 落盘异步/可选。

## 3. 背压

### 3.1 慢客户端

- Store 保留最近 N 帧；
- SSE 发送“最新帧”，跳过中间帧；
- 每次跳帧 `dropped.watch += n`；
- 关键事件（attack/alert/step/error）不跳；
- 客户端收到 `dropped` 后显示“已合并 N 帧”，并可重新拉快照。

### 3.2 慢消费/大表

- 单条 SSE 超过 256 KB → 截断 + `truncated=true`；
- 单 target 超过 200 行 → 截断；
- 前端虚拟滚动；
- 不允许一个 target 阻塞其他 target 的推送。

### 3.3 断线重连

- `Last-Event-ID`/`since`；
- 若 `since` 早于保留窗口 → 410 + 最新 `cursor`，客户端拉快照后继续；
- StepFrame 永久保留最近 200 个。

## 4. 安全

### 4.1 现有暴露面

当前控制台无登录鉴权，可启停仿真、注入攻击、下载产物（[05 文档](../05-Web控制台使用说明.md)）。新增 `/trace` 不应扩大风险：

- 默认只读；
- 控制操作（pause/step）与主控制台等价；
- 建议 `--token`、来源网段限制、反向代理鉴权；
- 不在页面展示文件系统路径/环境变量。

### 4.2 威胁与对策

| 威胁 | 对策 |
|---|---|
| 未授权启停/单步 | token/allowlist；控制权单客户端 |
| 通过 target/run 参数目录穿越 | 路径校验；只允许 `out/web/<run>` 下 |
| XSS（攻击参数/实体名） | 前端 `textContent`，不拼 HTML |
| 任意表达式/正则 DoS | 只支持枚举/精确匹配；限制长度 |
| 大 payload 拖垮浏览器 | 截断/上限/分页 |
| 真值泄露 | `demo_truth` 默认 false；独立 namespace |
| 事件伪造 | 服务端生成 seq；客户端不接受写入 |
| 日志注入 | 结构化 JSON；转义换行 |

### 4.3 真值隔离

- `TraceService` 读 truth 仅用于 `truth:*` target；
- 检测器不 import trace/truth；
- 测试断言：`isacsim/detect/` 不导入 `isacsim.trace`/`truth`；
- UI 对 truth 用紫色 + “仅演示”标签。

## 5. 可靠性

- trace 初始化失败 → 仿真继续，`/api/trace/capabilities` 返回 `enabled=false`；
- probe 异常 → 禁用该 probe，记录 `trace.error`；
- store 满 → 淘汰旧帧，计数；
- `stop`/`reset` 必须唤醒等待的 step；
- 多客户端：一个控制者，其他只读；
- 页面刷新/断线：重新拉 `targets` + 最新 frames + `since` events；
- 旧 run 回放：缺文件降级，不伪造。

## 7. 验收标准

### 7.1 P0（只读实时 watch）

- `/trace` 可打开，无需攻击；
- 4 个传感器 + fleet + PC5 + DET 更新；
- 冻结/继续可靠；
- trace 关闭时行为不变；
- 开销 <3%。

### 7.2 P1（A1 trace + 单步）

- A1 5–6 个检查点；
- before/after 正确；
- 单步与连续记录一致；
- focus/多攻击可用；
- 开销 <5%。

### 7.3 P2（回放/导出）

- 从 run 目录回放 A1；
- 前进/后退/拖动；
- 导出 zip + summary；
- 旧 run 降级可用。

## 8. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| A1 目标选择不保证 ADAS | 检查点 S2 不命中 | 页面显示“未触发”；profile 允许可选检查点 |
| `ctx.extras` 丢失 | 看不到 ADAS DENM/CAM | 以 `control.command`/速度为准；文档标注 |
| `flags` 只标 victim | 受影响车辆不全 | 从 command/速度差派生 |
| 10 Hz 数据量 | 前端卡顿 | 合并/虚拟滚动/只订阅 10 target |
| 多客户端控制 | 竞态 | 单控制者 + 409 |
| 无鉴权 | 数据/控制暴露 | token/网段限制 |
| 现有 run 缺 alerts | 回放不完整 | 在线记录 trace；缺数据标 unavailable |
| UI 过于像“监控大屏” | 讲解效果差 | 以 StepFrame/卡片为中心，不做装饰性动画 |

## 9. 开放问题

1. `StepFrame` 是否需要保存完整 before/after 值，还是只存 diff + 引用？
2. 多客户端是共享 cursor 还是各自 cursor？
3. 回放是否需要支持“从任意 tick 开始”而不只是检查点？
4. 是否需要在 CLI `run` 默认开启 trace 文件？
5. `truth` 是否允许在正式演示中显示？建议默认关闭，演示模式显式开启。
