# 06 前端设计

> **当前状态（2026-10-30）**：`/trace` 页面、watch 树、struct/table/event 卡片、事件详情、冻结/继续/tick/checkpoint、A1/A5 注入按钮已实现。
> 目标布局中的 focus/导出/跳转/基线/Xref/虚拟滚动/拖动时间轴未实现；当前是 full snapshot SSE + `requestAnimationFrame` + key 守卫。差异见 [12 当前实现状态](12-当前实现状态.md)。

## 1. 视觉定位

不是 IDA Pro 的仿制品，而是 **调试器式数据观察台**：

- 深色底、等宽数字、固定列宽、低饱和配色；
- 信息密度高，但每个区域只回答一个问题；
- 颜色只用于“变化/攻击/告警”，不用于装饰；
- 动画克制：变化高亮 600 ms 淡出，不闪烁。

参考的不是 IDA 的反汇编窗口，而是它的 **Debugger → Registers / Watch / Hex / Xrefs** 工作方式。

### 2.1 顶栏（当前）

- 会话状态、仿真时间、tick、cursor、模式（live/paused/step）；
- 主要操作：冻结、继续、下一步（检查点）、tick 步、注入 A1、注入 A5；
- 连接状态；
- “主控制台”链接；
- 没有 focus 选择、导出、跳到下一次攻击。顶栏布局与上图（目标设计）不同。

### 2.2 左栏：Watch 树

- 分组：Scene / Sensors / Vehicles / Core / Network / Platform / Defense / Detection / Attacks；
- 每项显示：名称、当前摘要（如 `6 objects / 3 ghosts`）、状态点；
- 支持搜索、点击选中；折叠/pin 未实现；
- 攻击组显示 `ATK001`、阶段、t0/t1；
- 无攻击时 Attacks 组显示“无活动攻击”。

### 2.3 中栏：卡片/寄存器

每张卡片是一个 target：

```text
┌ RSU-01 · sensing.objects ────────────────────────── ▲ 10 Hz ─┐
│ t=3.10  seq=1842  frame=31  objects=6  ghosts=3  Δ +3       │
│ ┌ object_id ─ cls ─ x ─ y ─ entity ─ flag ─────────────────┐│
│ │ 1           car   205.0 -35.1 veh:eastbound.1  —         ││
│ │ 9000        car    41.5  -8.4 ghost:9000      NEW       ││
│ │ 9001        obstacle 50.5 -8.0 ghost:9001     NEW       ││
│ │ 9002        car    59.5  -7.6 ghost:9002      NEW       ││
│ └───────────────────────────────────────────────────────────┘│
│ [显示 4/6] [原始 JSON] [设为基线]                            │
└──────────────────────────────────────────────────────────────┘
```

目标卡片类型：

| 类型 | 形态 | 例子 |
|---|---|---|
| `struct` | 2–4 列 key/value | `atk:ATK001`、`veh:eastbound.2.state`、`core:amf`、`platform:summary` |
| `table` | 表头 + 行 + diff 标记 | `sensor:*.objects`、`veh:fleet`、`core:sessions/flows`、`platform:tokens/subscriptions` |
| `event` | 事件列表 | `det:alerts`、`defense:actions` |

当前没有 `scalar`/`series` 渲染器；标量作为 `struct` 卡片显示。表格最多 40 行。

卡片头部信息：

- target label、kind、rate；
- `t/seq`、`status`（new/changed/stale/error）；
- 摘要（count/ghost/alert）；
- 操作：pin、折叠、原始 JSON、设为基线。

变化标记：

- `NEW`：新增行/字段；
- `DEL`：删除；
- `Δ`：数值变化，显示 `before → after`；
- 行背景色只闪 600 ms；之后保留左侧色条；
- 颜色语义固定：灰=正常，琥珀=变化，红=攻击/告警，紫=真值。

### 2.4 右栏：Trace / Detail（当前）

当前只有一个事件列表 + 底部 JSON 详情：

- 事件按 seq 倒序，最多显示最近 50 条；支持选中；
- 点击事件/表格行显示原始 JSON；
- 没有 Xref 因果链、按 kind/attack/entity 过滤、抽屉/复制/语法高亮。

### 2.5 底栏：时间轴（当前）

- 横轴：仿真时间；进度条按 `t/duration_s`；
- 攻击区间和告警标记；当前 cursor 不单独显示；
- **不支持拖动 seek**；检查点跳转/回放未实现；
- “跟随最新”未实现，列表每次按快照更新。

## 3. 当前默认布局

当前无攻击时约 20 个 target（3 RSU + gNB + fleet + PC5 + DET + Core 11 + Platform 3），不折叠，全部卡片纵向排列；没有“只注册 A1 10 个 target”的收敛。A1/A5 的默认关注点可以用搜索过滤：

1. `atk:ATK...`（struct）
2. `sensor:RSU-01.objects`（table）
3. `sensor:RSU-02/03.objects`（table，对照）
4. `veh:<victim>.state`（struct）
5. `veh:fleet`（table）
6. `net:pc5`（struct）
7. `det:alerts`（event）
8. `core:amf/smf/upf`、`core:sessions/flows`（A5）
9. `platform:summary/tokens/subscriptions`（A5/A8/A9）

当前中栏是多列卡片网格；没有“RSU 三张并排”的专门布局。

## 4. 交互（当前）

| 操作 | 当前行为 |
|---|---|
| 点击左栏 | 选中并滚动到卡片 |
| 搜索 | 按 target id/label/group 过滤 |
| `冻结` | 调 pause；状态显示“已暂停” |
| `继续` | 调 resume |
| `下一步` | 调 step(checkpoint)，渲染 StepFrame |
| `tick 步` | 调 step(tick) |
| `注入 A1` / `注入 A5` | 调 `/api/attacks` |
| 点击事件 | 右栏 JSON 详情 |
| 点击表格行 | 右栏行 JSON |
| `Space` | 下一步 |
| `F` | 冻结/继续 |

未实现：pin、设为基线、跳到下一次攻击、Xref、跟随最新、复制、`B`/`Esc`/`/` 快捷键。

原则：

- 演示时默认“冻结后阅读”；
- 变化高亮只做状态点/行标记，不做 600 ms 动画；
- 不在前端做业务推断（ghost/affected/delta 都由后端给）；
- 事件列表最多 50 条 DOM，避免暂停时反复重建。

## 5. 无攻击时的页面

这是必须支持的“正常态”：

- 顶部状态：`无活动攻击`；
- 左栏 Attacks 空；没有 Truth 组；
- 中栏显示 3 RSU + gNB、fleet、PC5、DET、Core、Platform、Defense；
- 底栏没有攻击区间，只有时间轴/告警；
- 可以“冻结/继续”，但没有 checkpoint 单步；
- 文案：“当前为正常运行；注入攻击后可在此追踪注入点与下游影响。”

## 6. 渲染与性能

### 6.1 更新策略（当前）

- SSE 到达 full snapshot → `schedule()` 用 `requestAnimationFrame` 合并；
- `apply()` 用 `cursor + step_id + state + pause_reason` 做 key；key 不变只更新 header/banner；
- key 变化时整页 `renderTree/renderCards/renderEvents/renderTimeline` 重建；
- 事件列表用 `pointerdown` 容器委托 + `eventCache`，暂停时不重建；
- 还没有 dirty 卡片/按 key 更新行/虚拟滚动。

### 6.2 限流

| 场景 | 当前策略 |
|---|---|
| 10 Hz 正常 | rAF 合并，暂停且 key 不变不重绘 |
| 突发 100 帧 | 只保留最后 pending snapshot |
| 多卡片 | 全部卡片重建；无虚拟滚动 |
| 大表 | 最多 40 行（sensor 80 行原始、前端显示 40） |
| 断线重连 | 重新拉 full snapshot，不补增量 |

### 6.3 前端技术

- 原生 JS（无 React/Vue），与现有 `app.js` 风格一致；
- CSS Grid/Flex；`font-variant-numeric: tabular-nums`；
- Canvas 只用于 sparkline/时间轴；表格用 DOM；
- 不引入 CDN；离线可用；
- 复用现有 `style.css` 的色板，新增 `trace.css` 覆盖布局；
- 字体：`ui-monospace, "Cascadia Mono", "SFMono-Regular", Menlo, Consolas, "Noto Sans Mono CJK SC", monospace`；中文正文用系统 sans。

## 7. 视觉规范

| 元素 | 规则 |
|---|---|
| 背景 | `#0d1117` / 卡片 `#141b24` |
| 文本 | `#d7e0ea`；次要 `#7d8fa3` |
| 正常 | 灰蓝 |
| 变化 | 琥珀 `#f0a93b`，仅 600 ms 高亮 + 左侧色条 |
| 攻击/注入 | 红 `#e05a5a`，加 `INJECTED` 标签 |
| 告警 | 红/橙，带规则名 |
| 真值 | 紫 `#b07ae0`，默认折叠 |
| 等宽数字 | 所有 ID/坐标/指标 |
| 状态点 | running 绿、paused 琥珀、error 红 |

可访问性：

- 不只靠颜色：新增用 `NEW` 文本，变化用 `Δ`；
- 对比度 ≥ 4.5:1；
- 键盘可达；
- 动效遵循 `prefers-reduced-motion`；
- 表格有 caption/aria-label。

## 8. 空/错/慢状态

| 状态 | 展示 |
|---|---|
| 无会话 | “启动仿真后开始追踪” + 回到主控制台 |
| 无攻击 | 正常态提示，不显示空攻击卡片 |
| 断线 | 顶部黄条“连接断开，正在重连”；保留最后画面 |
| 慢客户端 | 当前无 dropped 提示；full snapshot 可能积压（规划） |
| trace 关闭 | “追踪未启用” + 开启方式 |
| probe 错误 | 当前无 ERROR 卡片（规划） |
| 回放缺数据 | 回放未实现 |

## 9. 反模式

- 把所有 30+ 条流都做成卡片；
- 每帧全量重绘表格；
- 用十六进制作为主视图；
- 只靠颜色表达变化；
- 前端自己解析 `sensing.objects` 猜 ghost；
- 在 live 模式下自动滚动到最新，导致演示时画面乱跳；
- 把真值和观测混在同一列表且不标注；
- 为了“像 IDA”加大量无意义的面板/闪烁。

## 10. 页面路由与文件

```text
isacsim/web/static/
├─ trace.html          # 独立页面
├─ trace.css           # 布局/组件样式
├─ trace.js            # SSE/REST/渲染
└─ style.css           # 复用色板/基础控件
```

FastAPI：

```text
GET /trace  → trace.html
GET /api/trace/* → TraceService
```

不引入构建步骤；`trace.js` 可用 ES modules 或 IIFE，建议 IIFE 与现有 `app.js` 一致。
