# 攻击阶段指示栏设计（/trace）

> 状态：**设计稿，未实现**。本文给出可行性与实现方案，供确认后再动手。
> 目标：在 `/trace` 中间面板顶部增加一条**攻击阶段指示栏**，实时显示当前攻击走到了哪一步、
> 每步产生了什么可观测后果；点击阶段或后果条目，直接跳到对应的监控面板。

## 1. 需求与验收

以 A2 为例，攻击跑起来后指示栏应能显示：

```text
A2 · 物理环境欺骗+控制误导        2.0–5.0 s · 进行中 · 已用 1.6/3.0 s
 S0 攻击启动   [S1 目标列表出现停止牌]   S2 制动注入   S3 PC5 干扰   S4 减速   S5 告警   END
  ✓ +0.00s       ● +0.55s→0.65s           ○             ○             ○         ○         ○
  ── 当前阶段证据 ─────────────────────────────────────────────────────────────
  [定位] +0.55→0.65s  RSU-01 +1 ghost target(s)     → 感知 / RSU-01
```

验收：

1. 攻击开始后 bar 出现，阶段状态随仿真时间实时变化（不要求单步/暂停模式）；
2. 点击 `RSU-01 +1 ghost target(s)`（或 S1 阶段），自动切到“感知”标签、
   选中 `RSU-01` 子标签、滚动到感知卡片并高亮；
3. 攻击结束后 bar 保留一段时间，所有阶段显示“完成/未发生”，可回看；
4. 无攻击、或单体原语（没有 profile）时不显示 bar；
5. 不引入新的轮询：复用现有 `/api/trace/stream` 快照。

## 2. 可行性结论

**可行，且大部分数据已经存在**：

- `TraceProfile` 已经为 A1–A10 定义了 `S0–S5/END` 的**名称 + 匹配事件 + predicate**
  （[profiles.py](../../isacsim/trace/profiles.py)），例如 A2 的 S1 就是 `ghost.added`；
- 事件已经带 `t`（仿真时间）、`summary`、`target_id`、`attack_id`
  （`ghost.added` 的 summary 正是 `RSU-01 +1 ghost target(s)`，target 是 `sensor:RSU-01.objects`）；
- 前端已经有 `focusTarget(tid)`：切标签页、切传感器子标签、滚动到卡片
  （[trace.js](../../isacsim/web/static/trace.js) `focusTarget`）；
- 缺的只有两件事：
  1. 后端在**非单步模式**下持续做阶段匹配（现在的 `_collect_evidence` 只在 checkpoint 时调用）；
  2. 前端把阶段/证据画出来并绑定点击。

## 3. 交互与视觉

### 3.1 位置

放在 `#stepBanner` 与 `#cardTabs` 之间：

```text
┌ trace-top ─────────────────────────────────────────────┐
│ 状态 / 开始暂停 / 攻击注入栏                              │
├──────────┬───────────────────────────────┬─────────────┤
│ WATCH 树 │ [Step Banner]                 │ TRACE 事件   │
│          │ [Attack Stage Bar]  ← 新增     │             │
│          │ [卡片 Tabs]                   │             │
│          │ [卡片网格]                     │             │
└──────────┴───────────────────────────────┴─────────────┘
```

- bar 常驻、高度约 72–96 px；可点“收起”折叠成一行（状态保存在 `state.stageCollapsed`）；
- `stepBanner` 继续负责“检查点暂停”的信息，bar 负责“整条攻击链的实时进度”，两者不合并。

### 3.2 状态

| 状态 | 样式 | 含义 |
|---|---|---|
| `pending` | 暗灰 `○` | 还没匹配到证据 |
| `active` | 蓝色 `●` + 呼吸点 | 当前最新匹配的阶段 |
| `done` | 绿色 `✓` | 已经匹配，且后续阶段已匹配 |
| `skipped` | 暗灰删除线 | 后续阶段已匹配、本阶段始终没出现（A1 的 S4 这类可选阶段） |
| `end` | 灰色 | 攻击结束（`attack.end` 匹配后） |

时间显示用**相对攻击起点**的偏移（`+0.55s`），hover 的 title 里给绝对仿真时间。

### 3.3 点击行为

- 点阶段 chip：跳到该阶段证据的 `target_id`；
- 点证据行：同上；
- 没有 target 的阶段（如 S0 只有 `atk:<id>`）：跳到“攻击”标签页的攻击卡片；
- 跳转后给目标卡片加 1.2 s 高亮闪烁，避免“跳过去了但不知道看哪”。

## 4. 数据契约

在 `TraceService.snapshot()` 里新增 `stage_bar` 字段（无攻击时为 `null`）：

```json
"stage_bar": {
  "attack_id": "A2-0001",
  "type": "A2",
  "label": "物理环境欺骗+控制误导",
  "t0": 2.0, "t1": 5.0, "now": 3.6,
  "state": "active",            // waiting | active | finished
  "current": "S1",
  "stages": [
    {
      "id": "S0", "title": "攻击启动", "status": "done",
      "t_enter": 0.0, "t_exit": 0.55,
      "evidence": {"kind": "attack.start", "summary": "A2 ... 启动",
                   "target_id": "atk:A2-0001", "t": 0.0}
    },
    {
      "id": "S1", "title": "目标列表出现停止牌", "status": "active",
      "t_enter": 0.55, "t_exit": null,
      "evidence": {"kind": "ghost.added", "summary": "RSU-01 +1 ghost target(s)",
                   "target_id": "sensor:RSU-01.objects", "t": 0.55}
    },
    {"id": "S2", "title": "向目标车注入制动", "status": "pending", "t_enter": null},
    {"id": "END", "title": "攻击结束", "status": "pending", "t_enter": null}
  ]
}
```

字段说明：

- `t_enter` / `t_exit`：相对 `t0` 的秒数；`t_exit` 取下一个已匹配阶段的 `t_enter`；
- `evidence` 只保留第一条匹配事件的摘要与 target（一条足够定位，也避免 bar 过长）；
- `state`：`waiting`（已注入未开始）、`active`（运行中）、`finished`（`attack.end` 已匹配）。

## 5. 后端实现

### 5.1 实时证据采集

新增一个“只向前扫描”的游标，避免每 tick 全量扫 3000 条事件：

```python
# TraceService.__init__
self._live_scan_seq = 0

def _collect_live_evidence(self) -> None:
    profile = self._profile
    if profile is None or len(self._evidence) >= len(profile.stages):
        return
    for ev in self.events:
        if ev["seq"] <= self._live_scan_seq:
            continue
        self._live_scan_seq = ev["seq"]
        if ev.get("seq", 0) <= self._evidence_floor and \
                ev.get("t", 0) < self._profile_start_t - 1e-9:
            continue
        for stage in profile.stages:
            if stage.id in self._evidence:
                continue
            if stage.matches(ev):           # 与单步模式共用 predicate
                self._evidence[stage.id] = ev
                break
```

在 `after_tick()` 里 `_update_attacks()` 之后调用；`_reset_attack_state()` 里把
`_live_scan_seq` 重置为 `self.seq`。

> 单步模式原有的 `_collect_evidence()` 保留不动；两边共用 `_evidence`，
> `_stage_done` 仍只由 checkpoint 推进，互不影响。

### 5.2 组装 payload

```python
def _stage_bar(self) -> dict | None:
    profile = self._profile
    if profile is None or not self._profile_attack_id:
        return None
    info = self._attacks.get(self._profile_attack_id) or {}
    order = [s.id for s in profile.stages]
    matched = [sid for sid in order if sid in self._evidence]
    last = order.index(matched[-1]) if matched else -1
    finished = "END" in self._evidence or bool(info.get("finished"))
    ...
```

状态判定：

- `idx < last and matched` → `done`
- `idx < last and not matched` → `skipped`
- `idx == last and not finished` → `active`
- `idx == last and finished` → `done`
- 其余 `pending`

### 5.2.1 waiting 状态

`start` 还没到、攻击尚未 `started` 时 `_profile` 仍是空的。可在 `_stage_bar()` 里回退：
找 scheduler 中第一个 `not started` 且 `profile_for(atype).stages` 非空的实例，用它建一条
全 `pending` 的 bar，`state="waiting"`。这样“注入后延迟 5 s 启动”也有指示条。

### 5.3 多攻击

v1 只展示**最近启动的那一起**（`self._profile` 本来就是单槽位）。
同时在 `stage_bar` 里带 `others: [{id,type}]`，前端在标题右侧显示
“另有 1 起攻击”，点击可切到那一起（v2 再做多 bar 并排）。

### 5.4 性能

- 事件缓冲 3000 条，扫描只对新增事件做一次，阶段匹配最多 7 个 predicate；
- 快照本身 0.1 s 推送一次，payload 只增加几百字节。

### 6.2 渲染

`renderStageBar(snap)` 在现有 `render()` 里调用：

```js
function stageTarget(ev) {
  if (!ev) return null;
  if (ev.target_id) return resolveTargetId(ev.target_id);
  const d = ev.data || {};
  if (d.sensor_id) return `sensor:${d.sensor_id}.objects`;
  if (d.entity && d.entity.startsWith("veh:")) return `${d.entity}.state`;
  return null;
}
```

`resolveTargetId` 处理现有 target 命名差异：

- `veh:<vid>` → `veh:<vid>.state`（`v2x.cpm.degraded` 用的是前者）；
- 找不到就回退到 `atk:<attack_id>`。

点击用事件委托：

```js
$("stageBar").addEventListener("click", (e) => {
  const el = e.target.closest("[data-focus]");

});
```

`focusTarget` 已经会做：切 `state.tab`、切 `sensorTab`/`coreTab`/`platformTab`、
重渲染、`scrollIntoView({block:"center"})`。新增：滚动后给卡片加 `.flash`。

```text

S1 → 感知 / RSU-01（ghost.added）
S2 → 车辆 / 受害车（control.command）
S3 → 总览 / net:pc5（pc5.rise）
S4 → 车辆 / 受害车（vehicle.speed_drop）
S5 → 总览 / det:alerts（alert）
END → 攻击卡片
```

## 8. 边界与风险

1. **阶段是最早匹配，不是“当前状态”**：证据只记第一条；同一个阶段不会重复出现。对“指示”够用，
   但不适合做统计（统计仍看 `steps` / `events`）。
2. **可选阶段**：A1 的 S4 可能永远不出现；后续阶段匹配后显示 `skipped`，不是“失败”。
3. **多攻击**：v1 只显示最近一起（见 §5.3），不阻塞后续扩展。
4. **单体原语**没有 profile：bar 隐藏；如果需要，可给 `primitives` 加最小 profile（S0/S1/END）。
5. **事件环形缓冲**：3000 条满了会丢最旧事件；阶段证据在扫描时就固化到 `_evidence`，不受影响。
6. **重放/回放**（未实现）：将来回放时按 cursor 重建 `_evidence` 即可，payload 结构不变。
