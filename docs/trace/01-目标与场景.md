# 01 目标与场景

> **当前状态（2026-10-30）**：G1–G5 的 A1/A5 部分已实现；G6（回放/导出）未实现。
> 实现差异与已知限制见 [12 当前实现状态](12-当前实现状态.md)。本文是目标/场景设计，不把未实现能力写成现状。

## 1. 问题

当前环境已经能跑 A1–A10，但演示时主要靠：

- 主控制台的地图、统计数字、攻击进度条；
- 事件日志里的几行 `A1 注入 N 个幽灵目标`；
- 运行结束后翻 `truth/events.jsonl` 和各个 `*.jsonl`。

这对“讲清楚攻击怎么实现”不够：

1. **看不到数据在哪里被改**：观众只看到“攻击中”，看不到目标列表从 3 个变成 6 个；
2. **看不到谁消费了被改的数据**：ADAS 为什么刹车、哪辆车刹车，缺少一条可见的因果链；
3. **看不到正常态**：没有攻击时页面只是统计看板，不能说明“系统本来怎么运作”；
4. **每一步都要手动暂停/翻文件**：演示节奏取决于操作者手速；
5. **每个攻击都要单独做页面**：A1 讲完，A2 又要重做一套。

## 2. 目标

### 2.1 产品目标

> 用类似调试器的方式，把“仿真运行过程”变成可观察、可暂停、可单步、可回看的数据流。

具体目标：

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | 运行过程可视化 | 即使没有攻击，也能看到传感器目标列表、车辆状态、信道指标的实时变化 |
| G2 | 攻击链追踪 | 能看到攻击在哪个目标、哪个字段、哪个 tick 改了什么 |
| G3 | 跨层因果 | 能把“感知注入 → ADAS 决策 → 制动 → 信道”串起来 |
| G4 | 单步演示 | 在每个关键步骤自动暂停，展示 before/after，讲解后继续 |
| G5 | 框架复用 | A1/A5 已通过 profile 接入；A2–A4、A6–A10 仍待补 |
| G6 | 可复盘 | 运行后能回放、导出；**当前未实现**，只有内存快照 |

### 2.2 技术目标

- trace 只观察、不改变仿真行为；
- 同 seed/参数下，trace 开关不改变记录、真值、RNG、SUMO 结果；
- 60 s 场景开销 <5% 墙钟时间；
- 10 Hz 前端更新不卡顿；
- 断线重连不丢关键事件（允许丢中间 watch 帧，不允许丢 step/alert）；
- 与现有 `/api/stream`、主控制台、CLI、批处理兼容。

## 3. 非目标

| 编号 | 不做 | 原因 |
|---|---|---|
| N1 | Python 源码级单步 | 受众看不懂行号/调用栈；且会拖慢仿真 |
| N2 | IDA Pro 仿制品 | 不需要反汇编/十六进制为主；需要的是语义化 watch |
| N3 | 逐包协议追踪 | 当前是参数化信道模型，没有真实 pcap 级数据 |
| N4 | 修改攻击/检测逻辑 | 本功能是观察层，不能变成“为了演示改行为” |
| N5 | 替代主控制台 | 主控制台负责启停/编排/统计；追踪页负责观察/单步 |
| N6 | 多人协作/权限系统 | v1 单会话、单演示者；鉴权只做最低限度 |
| N7 | 实时倒带 | 仿真不可逆；回退由回放模式提供 |
| N8 | 所有原始记录上屏 | 21 万条/60 s 不现实；按目标采样/合并 |

## 4. 用户与场景

### 4.1 演示者（主要）

**场景**：向评审/同事演示 A1。

1. 打开 `/trace`，不启动攻击，先展示正常态：3 个 RSU 的目标列表、车辆、PC5；
2. 注入 A1，页面自动停在首个检查点（目标列表被篡改；A5 才有攻击启动 S0）；
3. 点“下一步”，看到 RSU-01 的目标列表多了 3 个 `ghost:*`，其他 RSU 不变；
4. 再下一步，看到受害车 TTC 1.481、`control.command`、速度下降；
5. 再下一步，看到 PC5 的 offered/CBR 上升；
6. 再下一步，看到 `ghost_object` 告警；
7. 结束后可导出/回放（**规划中，当前未实现**）。

**关键诉求**：不用记时间点、不用翻 JSONL、每一步都能指着屏幕讲。

### 4.2 攻击开发者

**场景**：新写 A2/A3，验证注入是否真的到达目标层。

- 观察目标层字段是否变化；
- 观察下游是否消费；
- 观察 truth 的 `stages` 与实际是否一致；
- 观察是否出现“代码跑了但数据没变”。

### 4.3 检测/评估人员

**场景**：核对某条告警是否有证据。

- 从 `DET` 事件跳到对应 `sensing.objects` / `link.metrics`；
- 看告警前后 1 s 的目标列表和信道；
- 确认告警不是读真值产生的。

### 4.4 无攻击基线

**场景**：说明“正常系统怎么工作”。

- 三个 RSU 的目标列表随车辆移动；
- 车辆 CAM/GNSS/控制；
- PC5 的 CBR 随车流变化；
- 没有任何 `ghost`/`forged`/`cloned` 标记。

这个场景决定页面不能只做“攻击专用面板”，必须是通用的运行观察器。

## 5. 设计原则

1. **观察者原则**：trace 不修改 payload、不改变 RNG、不影响检测器输入。
2. **数据与视图分离**：后端给 typed watch data；前端只渲染，不解析业务流。
3. **攻击无关**：全局目标始终存在；攻击只增加语义标注/检查点。
4. **全局时间游标**：所有卡片按同一个 `seq/tick/t` 更新，避免因果错位。
5. **状态 + 事件双视角**：既看“当前值”，也看“发生了什么”。
6. **渐进披露**：总览 → 目标卡片 → 行/字段 → 原始记录。
7. **安全边界暂停**：默认 tick 末尾；S0 可在 scheduler 后；不在 `ctx.emit` 里阻塞，避免污染时延/卡死 stop。
8. **有损可观测**：允许合并/丢弃中间帧，但不能影响仿真；丢多少要可见。
9. **真值隔离**：真值单独命名空间，默认折叠，检测器不可读。
10. **复用现有栈**：FastAPI + SSE + 原生 JS/Canvas，不引入新运行时。

## 6. 成功标准

### 6.1 演示验收

- 打开 `/trace` 到看到第一张目标卡片 <3 s；
- `inject A1` 后停在 S1（目标列表）；A5 的 S0 是攻击启动；
- 从注入到告警，5–6 步讲完，单步操作不超过 10 次点击；
- 任一步都能回答四个问题：
  1. 攻击者改了什么？
  2. 哪个组件消费了它？
  3. 产生了什么物理/网络后果？
  4. 检测器看到了什么？
- 无攻击时，页面能连续展示 ≥30 s 的正常运行。

### 6.2 工程验收

- trace 关闭时，行为与当前版本逐字节一致（排除时间戳）；
- trace 开启时，60 s 场景墙钟开销 <5%；
- 10 Hz 更新下，浏览器主线程单帧 <16 ms；
- 慢客户端不拖慢仿真；断线重连后能补齐关键事件；
- 新增 A2 profile 不需要改前端（设计目标；当前只验证了 A1/A5）；
- 单步与连续运行的 `ts_ns/source/entity/payload` 与 truth 一致。

### 6.3 非功能指标

| 指标 | 目标 |
|---|---|
| trace 内存（60 s，A1） | <50 MB |
| watch 帧大小（单目标） | <64 KB |
| SSE 单条消息 | <256 KB |
| 单步响应 | <2 s（含 SUMO 一步） |
| 事件保留 | 最近 10k 条或整个 run（可配） |
| 前端卡片数 | 默认 ≤12，最多 30 |
| 表格行数 | 默认 ≤200，超出虚拟滚动 |

## 8. 术语

| 术语 | 定义 |
|---|---|
| tick | 仿真步，默认 50 ms |
| checkpoint | 攻击链上的语义检查点，不等于 tick |
| watch | 持续观察某目标的值 |
| trace | 按时间排序的事件流 |
| step | 从当前暂停点推进到下一个断点 |
| profile | 某类攻击的追踪配置 |
| baseline | 攻击前/用户选定的对比快照 |
| focus | 当前讲解/过滤的攻击实例 |
| replay | 从运行产物重建的只读回放 |
