本文件是 trace 设计文档的**状态锚点**：01–11 描述目标和契约，实际行为以本文件为准；两者冲突时，先修文档，再改代码。

## 1. 一句话结论

当前是**可演示 A1/A5 的 v1.2 原型**：

- A1：S1–S5 检查点；
- A5：S0–S5 检查点 + core/platform 层边界暂停；
- 无攻击时可见传感器/车队/PC5/检测器，以及 5G 核心网/平台节点、UE、PDU 会话、UPF 流表、token、订阅；
- 核心网/平台事件进入事件栏并做 100 ms 聚合；
- 仍然是**全量 snapshot SSE**，没有增量、回放、导出、单控制者、truth 和 A6–A10 profile。

## 5. 关键语义

### 5.1 两个 trace 不要混

- **观测追踪（watch trace）**：`/trace` 页面、`TraceService`、`StepFrame`；
- **分布式链路（span trace）**：`record.trace_id/span_id/parent_span_id/chain_id`、`SpanContext`。

`SimContext` 同时有 `trace`（TraceService）和 `span`（SpanContext）；不要把两者互相赋值。

### 5.2 暂停边界

| 边界 | 位置 | 当前用途 |
|---|---|---|
| `after_scheduler` | `scheduler.tick()` 后、各层前 | A5 S0 |
| `after_layer:core` | `core.tick()` 后、auth/platform 前 | A5 S1/S2 |
| `after_layer:platform` | `platform.tick()` 后、control 前 | A5 S3 |
| `after_tick` | 整个 tick 后 | A1 全部、A5 S4/S5/END |

`pause_at()` 用 Condition 阻塞仿真线程；`resume/step/stop` 唤醒。禁止在 `ctx.emit()` 或 SUMO 调用中阻塞。

### 5.3 A5 的已知细节

- A5 S0 只有在 `Simulation.step(mode="checkpoint")` 已进入 checkpoint 时才停；如果先连续运行、攻击已启动，再冻结，S0 可能已错过；
- A5 S1 用 `amf_overload`/首个 reject；S2 用 `core.session` reject；
- S3 会等 S1/S2（最多 1 s）；S4/S5 也会等前序阶段；
- A5 `core.nas` 洪泛按 100 ms 聚合，单窗口同 key 只出一条，`data.count` 累加。

## 6. 已知限制

1. **`affected` 仍偏宽/粘滞**：`veh:fleet.affected` 来自 `control.command` + flags；普通 ADAS 也会置位，且 `_commanded` 只在攻击启动时清空。
2. **`pc5.rise` 是阈值标记**：相邻帧 CBR +0.1 或 offered +100 即产生，不要求攻击、不带基线；不是检测结论。
3. **SSE 全量**：10–30 KB/帧；暂停时只发心跳，但恢复/变化仍全量。
4. **事件 ring 3000**：A5 聚合后压力已降低，但长时间 run 仍会淘汰旧事件。
5. **A1 无 S0**：A1 第一步仍是 S1（注入后的状态）。
6. **A5 S0 依赖先冻结/先 step**：见 §5.3。
7. **A4/A6–A10 无 profile**：只有 `attack.start/end` 等通用事件，没有专用检查点。
8. **A5 只有 core 汇总/表，不是逐 UE 因果图**：会话/流表可看，但“哪个 UE 的哪个会话被拒绝”仍需结合事件详情。
9. **没有回放**：stop 后只能看当前进程内存快照；`out/` 里有原始 JSONL，但 trace 不重建。
