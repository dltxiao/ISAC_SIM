# 12 当前实现状态与设计差异

> 基线：`feature/trace-watch`（A1–A10 profile 批次，2026-11-03）
> 代码：`isacsim/trace/`、`isacsim/core/engine.py`、`isacsim/web/`
> 测试：**97 项 pytest 通过**；主控制台与 `/trace` 页面冒烟通过。

本文件是 trace 设计文档的**状态锚点**：01–11 描述目标和契约，实际行为以本文件为准；两者冲突时，先修文档，再改代码。

## 1. 一句话结论

当前是**可演示 A1–A10 的 v1.3 原型**：

- A1：S1–S5 检查点（保持无 S0）；
- A2–A4、A6–A10：S0–S4/S5 检查点，按攻击链在 scheduler/core/platform/tick 边界暂停；
- A5：S0–S5 检查点 + core/platform 层边界暂停；
- 无攻击时可见传感器/车队/PC5/检测器，以及 5G 核心网/平台节点、UE、PDU 会话、UPF 流表、token、订阅；
- 核心网/平台事件进入事件栏并做 100 ms 聚合；
- 仍然是**全量 snapshot SSE**，没有增量、回放、导出、单控制者、truth 和多攻击 focus。

## 5. 关键语义

### 5.1 两个 trace 不要混

- **观测追踪（watch trace）**：`/trace` 页面、`TraceService`、`StepFrame`；
- **分布式链路（span trace）**：`record.trace_id/span_id/parent_span_id/chain_id`、`SpanContext`。

`SimContext` 同时有 `trace`（TraceService）和 `span`（SpanContext）；不要把两者互相赋值。

### 5.2 暂停边界

| 边界 | 位置 | 当前用途 |
|---|---|---|
| `after_scheduler` | `scheduler.tick()` 后、各层前 | A2–A10 的 S0 |
| `after_layer:core` | `core.tick()` 后、auth/platform 前 | A5 S1/S2；A6 S1；A7 S1；A8 S1；A10 S1/S2 |
| `after_layer:platform` | `platform.tick()` 后、control 前 | A5 S3；A6 S2/S3；A7 S2；A8 S2/S3；A9 S1/S2；A10 S3 |
| `after_tick` | 整个 tick 后 | A1 全部；A2–A4 全部；A5 S4/S5/END；A6–A10 的后果/告警 |

`pause_at()` 用 Condition 阻塞仿真线程；`resume/step/stop` 唤醒。禁止在 `ctx.emit()` 或 SUMO 调用中阻塞。

### 5.3 A5 的已知细节

- A5 S0 只有在 `Simulation.step(mode="checkpoint")` 已进入 checkpoint 时才停；追踪页注入会先自动冻结再提交攻击，因此可捕获 S0；如果攻击已在连续运行时启动、之后才冻结，S0 已错过；
- A5 S1 用 `amf_overload`/首个 reject；S2 用 `core.session` reject；
- S3 会等 S1/S2（最多 1 s）；S4/S5 也会等前序阶段；
- A5 `core.nas` 洪泛按 100 ms 聚合，单窗口同 key 只出一条，`data.count` 累加。

### 5.4 A1–A10 profile 的共同约束

- 每个攻击一个 `TraceProfile`，注册在 `PROFILES`；`/api/trace/capabilities.profiles` 返回全部 ID；
- A1 保持 S1 起点；其余攻击 S0 匹配 `attack.start`，在 `after_scheduler` 暂停；
- 后序阶段用 `wait_for/wait_ref/wait_s` 保证展示顺序；参考阶段尚未出现时不会绕过顺序；
- 没有命中证据的阶段不生成占位 `StepFrame`，只走 `MAX` 兜底；
- A3/A10 的 `radar.echo/track` 只在对应 profile 激活时按 tick 采样，不进入正常场景事件流；
- A4/A7 的 `v2x.cam.clone`/`v2x.cpm.forged` 只在 `cloned/forged` 标记存在时产生；
  A6 的 `v2x.cpm.degraded` 由真实 `v2x.cpm.rx`（5QI/GFBR 派生的丢包）产生。

## 6. 已知限制

1. **`affected` 仍偏宽/粘滞**：`veh:fleet.affected` 来自 `control.command` + flags；普通 ADAS 也会置位，且 `_commanded` 只在攻击启动时清空。
2. **`pc5.rise` 是阈值标记**：相邻帧 CBR +0.1 或 offered +100 即产生，不要求攻击、不带基线；不是检测结论。
3. **SSE 全量**：10–30 KB/帧；暂停时只发心跳，但恢复/变化仍全量。
4. **事件 ring 3000**：A5 聚合后压力已降低，但长时间 run 仍会淘汰旧事件。
5. **A1 无 S0**：A1 第一步仍是 S1（注入后的状态）。
6. **A5 S0 依赖先冻结/先 step**：见 §5.3。
7. **多攻击并存仍是单 profile**：`_profile` 由最后启动的攻击接管，没有 focus/每攻击独立 StepController；A1–A10 单攻击演示不受影响。
8. **A5 只有 core 汇总/表，不是逐 UE 因果图**：会话/流表可看，但“哪个 UE 的哪个会话被拒绝”仍需结合事件详情。
9. **没有回放**：stop 后只能看当前进程内存快照；`out/` 里有原始 JSONL，但 trace 不重建。
