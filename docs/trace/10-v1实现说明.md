## 3. 数据层

`TraceService` 在 `Simulation(trace=True)` 时创建：

- 全局 target：`scene:summary`、每个 `sensor:<id>.objects`、`veh:fleet`、`net:pc5`、`det:alerts`；
- 攻击 target：`atk:<attack_id>`，A1 启动后增加 `veh:<victim>.state`；
- `after_scheduler()`：先登记攻击，保证 `attack.start` 在层记录之前；
- `after_tick()`：更新传感器表、车队、PC5、检测器、场景；
- `on_record()`：采集 `control.command`、`forged DENM`、克隆事件；
- `begin_step()` / `_maybe_finish_step()`：检查点单步；
- `snapshot()`：给 `/api/trace/state` 和 SSE 的只读快照。

## 4. 检查点行为

v1 的 A1 检查点：

| 阶段 | 触发 | 说明 |
|---|---|---|
| S1 | 首次出现 `ghost.added` | RSU 目标列表增加 ghost |
| S2 | 首次 `control.command` | 仅当 victim 被目标 RSU 服务且装备 ADAS |
| S3 | `pc5.rise` | offered/CBR 上升 |
| S4 | `vehicle.speed_drop` | 仅对收到过 control.command 的车辆 |
| S5 | 首次 `alert` | 通常 `ghost_object` |

行为细节：

- 阶段按 **S1→S2→S3→S4→S5→END** 的固定顺序推进，不按事件实际发生的严格时间；
- 已经发生但尚未讲解的证据会被复用，所以 S2 可能在 S1 之后的下一步出现；
- 如果存在 S2 且 0.5 s 内还没有 S4，会先等 S4，避免“先告警后减速”的观感；超过 0.5 s 仍没有 S4 则允许 S5；
- 每个阶段只暂停一次；
- 所有阶段完成后，后续 step 会以 2 s 为上限推进（`MAX`），不会重复告警；
- S2/S4 是可选阶段：victim 未装备/未被覆盖时不会出现，页面仍能继续。

## 5. 运行方式

```bash
# 启动
.venv/bin/python -m isacsim web --host 127.0.0.1 --port 8080

# 主控制台
#   http://127.0.0.1:8080/
# 运行追踪
#   http://127.0.0.1:8080/trace
```

演示流程：

1. 主控制台开始仿真（或追踪页先打开）；
2. 追踪页点“冻结”；
3. 点“注入 A1”；
4. 点“下一步”逐检查点；
5. 观察 RSU-01 目标列表、victim 状态、PC5、Detector；
6. 结束后回到主控制台停止/复位。

## 7. 与设计的偏差 / 已知限制

1. **A1 尚未抽成独立 `TraceProfile`**：v1 的 S1–S5 逻辑在 `TraceService` 里，A2–A10 还不能只加 profile。下一版应把 `targets/checkpoints/narrative` 移到 `profiles/a1.py`。
2. **没有 S0（注入前暂停）**：v1 只在 tick 末尾暂停，第一步 S1 已包含注入后的状态；S0 需要 `after_scheduler` 的暂停挂起/恢复。
3. **SSE 是全量快照**：不是设计里的增量 cursor 协议；payload 约 10–30 KB/帧，LAN 可用，但不是最终形态。
4. **`last_step` 在 API 中裁剪了 `before/after/events`**：前端只拿摘要；完整 StepFrame 仍保存在服务端内存，暂未提供按 id 查询。
5. **没有回放/导出/truth**：P3/P4。
6. **没有 HookBus owner/origin**：ghost 事件通过目标列表差异推断；A4 直接 emit 的归因还不完整。
7. **affected 车辆来自 control.command + flags**：没有 ADAS 制动的 victim 仍会显示 `affected=true`（因为被标记），但不会产生 S4 速度事件。
8. **单控制者未强制**：多个浏览器同时点“下一步”可能产生并发 step；前端已加 busy 防连点，后端尚未做 409/owner。
9. **`after_scheduler` 只用于登记攻击**：没有在 S0 暂停；后续可扩展。
10. **没有 `trace.jsonl` 落盘**：所有数据在内存；stop 后只保留当前进程快照。

## 8. 交互修复（本轮）

本轮修了三个问题：

1. **暂停时不再重建列表**：`apply()` 用 `cursor + step_id + state + pause_reason` 做 key，key 不变只更新 header/banner；
2. **点击不再丢**：事件列表和表格行改成容器级 `pointerdown` 事件委托，不再给每个条目绑定/重建 handler；
3. **Detail 不再失效**：选中事件写入 `eventCache`（最多 300 条），即使事件被快照窗口挤掉也能显示；点击只切换 active class，不重建列表；
4. **SSE 空推送**：`/api/trace/stream` 只在 cursor/state/StepFrame 变化时发送完整 `trace`，无变化时 5 s 心跳。

实测：

- 暂停状态下连续 700 ms，`#traceEvents.innerHTML` 不变；
- 连续点击两条事件，`#eventDetail` 内容变化；
- 点击 RSU-01 表格行，Detail 显示该行 JSON；
- 暂停时 SSE 2.5 s 只收到 1 条 `trace`，无重复推送；
- 浏览器无 console error；pytest 36 项通过。

## 9. 下一步建议

优先级从高到低：

1. 抽 `TraceProfile`，把 A1 的阶段/文案/目标移出 service；
2. 加 `S0` 的 `after_scheduler` 暂停；
3. 把 SSE 改为 `since`/`event` 增量，保留 full snapshot 作为重连兜底；
4. 加 `trace.jsonl` + 回放；
5. 给 `HookBus`/`ctx.emit` 加 origin，补 A4 等直接 emit 的归因；
6. 多攻击 focus 与单控制者。
