## 3. 数据层

`TraceService` 在 `Simulation(trace=True)` 时创建：

- 全局 target：`scene:summary`、每个 `sensor:<id>.objects`、`veh:fleet`、`net:pc5`、`det:alerts`、`defense:actions`；
- provider target：`core:*`、`platform:*`（v1.2）；
- 攻击 target：`atk:<attack_id>`，victim 启动后增加 `veh:<victim>.state`；
- `after_scheduler()`：登记攻击；A5 S0 可在此暂停；
- `after_layer("core"/"platform")`：刷新 provider；A5 S1/S2/S3 可在此暂停；
- `after_tick()`：更新传感器表、车队、PC5、检测器、场景；
- `on_record()`：采集 `control.command`、forged DENM、clone、`core.*`/`app.*`/`defense.action`；
- `profiles.py`：A1/A5 阶段选择；
- `begin_step()` / `_maybe_finish_step()`：StepFrame；
- `snapshot()`：给 `/api/trace/state` 和 SSE 的只读快照。

## 4. 检查点行为

v1 的 A1 检查点：

| 阶段 | 触发 | 说明 |
|---|---|---|
| S1 | 首次出现 `ghost.added` | RSU 目标列表增加 ghost |
| S2 | 首次 `control.command` | 仅当 victim 被目标 RSU 服务且装备 ADAS |
| S3 | `pc5.rise` | offered/CBR 上升 |
| S4 | `vehicle.speed_drop` | 仅对收到过 control.command 的车辆 |
| S5 | 首次 `alert` | 通常 `ghost_object` |

行为细节：

- 阶段按 **S1→S2→S3→S4→S5→END** 的固定顺序推进，不按事件实际发生的严格时间；
- 已经发生但尚未讲解的证据会被复用，所以 S2 可能在 S1 之后的下一步出现；
- 如果存在 S2 且 0.5 s 内还没有 S4，会先等 S4，避免“先告警后减速”的观感；超过 0.5 s 仍没有 S4 则允许 S5；
- 每个阶段只暂停一次；
- 所有阶段完成后，后续 step 会以 2 s 为上限推进（`MAX`），不会重复告警；
- S2/S4 是可选阶段：victim 未装备/未被覆盖时不会出现，页面仍能继续。

### 4.1 A5（v1.2 增量）

| 阶段 | 触发 | 暂停点 |
|---|---|---|
| S0 | `attack.start` | `after_scheduler` |
| S1 | `core.nas` reject/overload | `after_layer:core` |
| S2 | `core.session` reject | `after_layer:core` |
| S3 | `app.ingest`/`app.control` | `after_layer:platform` |
| S4 | `control.command`/速度下降 | `after_tick` |
| S5 | `alert` | `after_tick` |
| END | `attack.end` | `after_tick` |

A5 S1/S2 在同一 core 边界连续暂停；S3/S4/S5 有顺序等待。A1 仍无 S0。
A5 S0 依赖已进入 checkpoint 模式：先冻结再注入 A5，或在攻击启动前点“下一步”；连续运行后冻结可能错过 S0。

## 7. 与设计的偏差 / 已知限制（v1 基线 + 后续状态）

1. ~~A1 尚未抽成独立 `TraceProfile`~~：**v1.2 已抽到 `profiles.py`**；A2–A4/A6–A10 仍未接入。
2. **A1 没有 S0**：A1 从 S1 开始；A5 已有 S0。通用 S0/armed 仍未实现。
3. **SSE 是全量快照**：不是增量 cursor 协议；payload 约 10–30 KB/帧。
4. **`last_step` 在 API 中裁剪了 `before/after/events`**：仍没有按 id 查询。
5. **没有回放/导出/truth**：仍未实现。
6. **没有 HookBus owner/origin**：A1 ghost 通过目标列表差异推断；A4/A5 直接 emit 归因不完整。
7. **affected 车辆来自 control.command + flags**：仍偏宽/粘滞。
8. **单控制者未强制**：多个浏览器同时点“下一步”仍可能并发。
9. ~~`after_scheduler` 只用于登记攻击~~：A5 已用于 S0；A1 仍未使用。
10. **没有 `trace.jsonl` 落盘**：仍未实现。
11. **`pc5.rise` 是阈值标记**：不要求攻击，不是检测结论。

## 8. 交互修复（本轮）

本轮修了三个问题：

1. **暂停时不再重建列表**：`apply()` 用 `cursor + step_id + state + pause_reason` 做 key，key 不变只更新 header/banner；
2. **点击不再丢**：事件列表和表格行改成容器级 `pointerdown` 事件委托，不再给每个条目绑定/重建 handler；
3. **Detail 不再失效**：选中事件写入 `eventCache`（最多 300 条），即使事件被快照窗口挤掉也能显示；点击只切换 active class，不重建列表；
4. **SSE 空推送**：`/api/trace/stream` 只在 cursor/state/StepFrame 变化时发送完整 `trace`，无变化时 5 s 心跳。

实测：

- 暂停状态下连续 700 ms，`#traceEvents.innerHTML` 不变；
- 连续点击两条事件，`#eventDetail` 内容变化；
- 点击 RSU-01 表格行，Detail 显示该行 JSON；
- 暂停时 SSE 2.5 s 只收到 1 条 `trace`，无重复推送；
- 浏览器无 console error；pytest 77 项通过。
