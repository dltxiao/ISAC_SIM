# 指标测量与评估口径

## 1 判据原文与拆解

> 面向跨域协同攻击的攻击链识别检测：攻击识别率 ≥99%，误检率 ≤1%；
> 算法时延 ≤100ms——从攻击行为发生（或攻击相关数据进入检测模型）到系统输出攻击识别结果或防御指令的时间。

| 项 | 本环境口径 |
|---|---|
| 一次"攻击事件" | 一个跨层剧本实例（`truth/events.jsonl` 中的一条，label=1），有明确 t0/t1 |
| 一次"正常运行" | 无任何注入的完整场景运行 |
| 识别率 | 命中事件数 / 包络内攻击事件数 |
| 误检率 | 含至少一个误报事件的正常运行数 / 正常运行数 |
| 算法时延 | 观测记录进入检测器（`t_ingest`）到输出告警（`t_decide`）的墙钟时间 |
| 攻击发生到识别 | `t_onset`→`t_decide`，含凑窗，**单列**报告 |

辅助口径：窗口级（每 1 s 窗口是否判为异常）同时披露，避免"放大分母"的质疑。

## 2 采样与统计

- 每个攻击事件一个独立场景（seed 不同），事件之间不重叠；
- 正常场景与攻击场景同分布（同路网、同车流参数、同种子范围）；
- 置信区间用 Wilson 95%；
- 结果同时给出点估计与区间。

| 样本量（0 失败） | 识别率 95% 下界 | 误检率 95% 上界 |
|---|---|---|
| 300 | 98.74% | 1.26% |
| 500 | 99.24% | 0.76% |
| 1000 | 99.62% | 0.38% |

> 若要求"区间下界也 ≥99%"，建议 ≥500 个攻击事件且 0 漏报；若要容忍 1 次失败，需约 1000 个。

## 3 匹配规则

1. 告警按时间聚类（相邻告警间隔 ≤2.5 s）；
2. 真值事件与检测事件按时间重叠匹配（前后各放宽 1 s），一对一贪心；
3. 未被匹配的检测事件计入"多余检测"，在报表中单列，不直接算作误报；
4. 合并/裂开的处理：贪心匹配只允许一对一，多余部分单列，避免"合并即漏报"的结构性惩罚。

实现：`isacsim/eval/metrics.py`。

## 4 时延测量

| 时间点 | 含义 | 来源 |
|---|---|---|
| `t_onset` | 攻击开始 | 真值 t0 |
| `t_emit` | 被篡改记录发出 | `Record.t_wall_ns` |
| `t_ingest` | 检测器读到记录 | 检测器回调入口 |
| `t_decide` | 输出告警/防御指令 | 告警创建时刻 |

- 主口径：`t_ingest → t_decide`，与判据"数据进入检测模型"一致；
- 单列：`t_onset → t_decide`（含窗口凑齐，当前参考检测器为逐条/短窗，约 0.1–0.6 s）；
- 单列：事件级（Campaign 聚合）时延，不纳入本指标；
- 报表给出 P50/P95/P99 与样本数。

## 5 可检出包络

| 剧本 | 判据 | 默认包络 |
|---|---|---|
| A1 | 附加负载 ≥250 msg/s | 是 |
| A2 | 链路干扰 ≥0.05 | 是 |
| A3 | 回波偏置 ≥1.0 m | 是 |
| A4 | 伪造速率 ≥2 Hz | 是 |

包络外事件单列，不计入识别率分母；这样"极其隐蔽、任何方法都不可检"的样本不会污染指标，同时保留"能检出到多弱"的诚实曲线。

## 6 实测结果（本机，参考检测器）

### 6.1 主结果：500 攻击 + 500 正常（15 s/场景）

| 指标 | 结果 |
|---|---|
| 识别率 | **100.00%**（300/300 时为 100%；500/500 时 95% CI **99.24%–100%**） |
| 误检率 | **0.20%**（1/500，95% CI 0.04%–1.12%） |
| 检测时延 | P50 **0.08 ms** / P95 **0.204 ms** / P99 **0.258 ms**（n=3923） |

分类型（各 125 个事件）：

| 类型 | 事件 | 命中 | 识别率 |
|---|---|---|---|
| A1 感知篡改→拥塞 | 125 | 125 | 100% |
| A2 物理欺骗+控制误导 | 125 | 125 | 100% |
| A3 跨层隐蔽 | 125 | 125 | 100% |
| A4 双因素仿冒 | 125 | 125 | 100% |

复现：

```bash
.venv/bin/python -m isacsim batch --out out/ds_final --attacks 500 --normal 500 \
    --duration 15 --workers 18 --no-streams
.venv/bin/python -m isacsim eval --runs out/ds_final
```

### 6.2 难度曲线：A3 的"雷达证据"随幅度上升

A3 同时注入"回波渐偏"和"小幅制动"。若只看雷达规则：

| amplitude | 最大偏置 | 含雷达告警的运行数 |
|---|---|---|
| 0.15 | 1.13 m | 7/40（17.5%） |
| 0.30 | 1.46 m | 28/40（70%） |
| 0.50 | 1.90 m | 40/40（100%） |
| 0.75 | 2.45 m | 40/40（100%） |
| 1.00 | 3.00 m | 40/40（100%） |

而"控制指令无 TTC 依据"规则在**所有幅度**下都能命中（40/40）。这说明：

- 单靠雷达层，隐蔽攻击在低幅度下确实检不出；
- 跨层关联（雷达 + 控制 + 遥测）是达标的关键，而不是靠单层阈值。

### 6.3 早期版本对照（证明不是"构造出来的 100%"）

第一轮 300+300 批量中，A4 仅 86.67%（65/75）：原因是剧本选中了未装备 OBU 的车辆，导致不存在可对照的真实 CAM。修正生成器（A4 只挑已装备车辆，符合现实）后 A4 达到 100%。这条记录说明：

- 指标对生成器缺陷敏感，而不是对检测器"放水"；
- 修正的是**世界设定**，不是检测阈值。

### 6.4 链级结果（v0.3.0，M4）

`ReferenceDetector` 在 `alerts.jsonl` 之外输出 `chains.json`；`eval/chain_metrics.py` 对每条 truth 事件选择时间重叠最大的链，计算：

| 指标 | 定义 |
|---|---|
| 节点召回 | 预测链节点 ∩ truth 节点 / truth 节点 |
| 节点精确率 | 预测链节点 ∩ truth 节点 / 预测节点 |
| 根因 top-1 | 预测 `root_cause` 等于 truth 根因（无 chain 时用 `nodes[0]`） |
| 阶段覆盖 | 预测阶段数 / truth 阶段数（上限 1） |

20 攻击 + 20 正常（A1–A10 各 2 个）实测：

- 事件级：识别率 **100%**，误检率 **0%**，P99 **0.294 ms**；
- 链级：节点召回 **55.28%**、精确率 **100%**、根因 top-1 **70%**、阶段覆盖 **100%**。

节点召回偏低是当前链构建器的已知边界：它只从告警实体提取节点，不会推断未直接告警的 `attacker:`/`tenant:` 节点；后续可由正式链模型替换，不应把 55% 当作最终指标。

## 7 局限与披露

1. 参考检测器是环境验证基线，不是最终交付模型；其 100% 不代表正式系统指标。
2. 正常集当前覆盖遮挡、切换、GNSS 峡谷、真实急刹、丢帧等，但尚未覆盖全部 8 类设备故障（列入后续）。
3. 误检率的区间上界（1.12%）略高于 1%，是 500 个正常样本、1 次误报的统计结果；点估计 0.2% 满足要求，若需区间也达标需 ≥1000 个正常样本且 ≤2 次误报。
4. 时延为检测器内部计算时间，不含网络传输与 UI；实时演示中的端到端时延单列。
