# 指标测量与评估口径

## 1 判据原文与拆解

> 面向跨域协同攻击的攻击链识别检测：攻击识别率 ≥99%，误检率 ≤1%；
> 算法时延 ≤100ms——从攻击行为发生（或攻击相关数据进入检测模型）到系统输出攻击识别结果或防御指令的时间。

| 项 | 本环境口径 |
|---|---|
| 一次"攻击事件" | 一个跨层剧本实例（`truth/events.jsonl` 中的一条，label=1），有明确 t0/t1 |
| 一次"正常运行" | 无任何注入的完整场景运行 |
| 识别率 | 命中事件数 / 包络内攻击事件数 |
| 误检率 | 含至少一个误报事件的正常运行数 / 正常运行数 |
| 算法时延 | 观测记录进入检测器（`t_ingest`）到输出告警（`t_decide`）的墙钟时间 |
| 攻击发生到识别 | `t_onset`→`t_decide`，含凑窗，**单列**报告 |

辅助口径：窗口级（每 1 s 窗口是否判为异常）同时披露，避免"放大分母"的质疑。

## 2 采样与统计

- 每个攻击事件一个独立场景（seed 不同），事件之间不重叠；
- 正常场景与攻击场景同分布（同路网、同车流参数、同种子范围）；
- 置信区间用 Wilson 95%；
- 结果同时给出点估计与区间。

| 样本量（0 失败） | 识别率 95% 下界 | 误检率 95% 上界 |
|---|---|---|
| 300 | 98.74% | 1.26% |
| 500 | 99.24% | 0.76% |
| 1000 | 99.62% | 0.38% |

> 若要求"区间下界也 ≥99%"，建议 ≥500 个攻击事件且 0 漏报；若要容忍 1 次失败，需约 1000 个。

## 3 匹配规则

1. 告警按时间聚类（相邻告警间隔 ≤2.5 s）；
2. 真值事件与检测事件按时间重叠匹配（前后各放宽 1 s），一对一贪心；
3. 未被匹配的检测事件计入"多余检测"，在报表中单列，不直接算作误报；
4. 合并/裂开的处理：贪心匹配只允许一对一，多余部分单列，避免"合并即漏报"的结构性惩罚。

实现：`isacsim/eval/metrics.py`。

## 4 时延测量

| 时间点 | 含义 | 来源 |
|---|---|---|
| `t_onset` | 攻击开始 | 真值 t0 |
| `t_emit` | 被篡改记录发出 | `Record.t_wall_ns` |
| `t_ingest` | 检测器读到记录 | 检测器回调入口 |
| `t_decide` | 输出告警/防御指令 | 告警创建时刻 |

- 主口径：`t_ingest → t_decide`，与判据"数据进入检测模型"一致；
- 单列：`t_onset → t_decide`（含窗口凑齐，当前参考检测器为逐条/短窗，约 0.1–0.6 s）；
- 单列：事件级（Campaign 聚合）时延，不纳入本指标；
- 报表给出 P50/P95/P99 与样本数。

## 5 可检出包络

| 剧本 | 判据 | 默认包络 |
|---|---|---|
| A1 | 伪造 DENM 速率 ≥250 条/s（`denm_rate`，等价 a≥0.27） | 是 |
| A2 | 链路干扰 ≥0.05 | 是 |
| A3 | 回波位移 ≥3.0 m（且表观 TTC 被压到 2.5 s 以下） | 是 |
| A4 | 位置偏移 ≥30 m 且**实测**伪造速率 ≥8 Hz（旧判据 `spoof_rate≥2` 恒真） | 是 |
| A5 | **实测**到达速率 ≥ AMF 容量（场景标定 800/s） | 是 |
| A6 | GFBR ≤400 kbps 且平台 ingest 延迟 ≥100 ms | 是 |
| A7 | 伪造 CPM 注入速率 ≥3 Hz 且路由至少保持 1 s | 是 |
| A8 | 被摘掉的订阅事件类型 ≥2（只退 denm 属包络外） | 是 |
| A9 | 多车（≥5）且注入减速度 ≥3.5 m/s²（旧判据 `vehicles>=3` 恒真） | 是 |
| A10 | 雷达偏置 ≥3 m 且信令 ≥15/s（雷达规则本身要 >6 m 才会命中） | 是 |

A4–A10 的判据都用**实测值**（`actual_rate`、`gfbr_to`、实际注入的 `ingest_delay`、被摘掉的事件类型数），
不再用标称参数——旧实现里 A5 用 `rate>=1000/s` 判包络、实际只有 ~350/s，
A4 的 `spoof_rate>=2` 则恒真（见审核 R6/R10/R11）。

包络外事件单列，不计入识别率分母；这样"极其隐蔽、任何方法都不可检"的样本不会污染指标，同时保留"能检出到多弱"的诚实曲线。

### 6.2 难度曲线：A3 的实际影响随幅度上升

A3 的表观目标 TTC = `3.2 − 2.0a`；当它高于 ADAS 门限（2.45 s）时**不做任何篡改**（包络外）。
实测（`start=8`、`duration=6`、`duration_s=16`、每档 **20 个 seed**，并与同 seed 的**无攻击对照**
逐车比较）：

| amplitude | 表观 TTC | 出现 `radar_range_bias` | 诱导 ADAS 误刹（对照差） | 伪指令 `injected` | 包络 |
|---:|---:|---:|---:|---:|---|
| 0.20 | 2.8 s | 0/20 | 0/20 | 20/20 | 外 |
| 0.35 | 2.5 s | 0/20 | 0/20 | 20/20 | 外 |
| 0.45 | 2.3 s | 18/20 | 14/20 | 20/20 | 内 |
| 0.60 | 2.0 s | 18/20 | 14/20 | 20/20 | 内 |
| 0.80 | 1.6 s | 18/20 | 14/20 | 20/20 | 内 |
| 1.00 | 1.2 s | 18/20 | 14/20 | 20/20 | 内 |

读法（比上一版 3 个 seed 的结论更保守）：

- **雷达规则 18/20**：`radar_range_bias` 要求同一目标被 ≥2 个站看到；2 个 seed 里 victim 只被
  单站覆盖，规则抓不到，只能靠控制面证据。
- **诱导 ADAS 误刹 14/20**：这是“攻击窗口内 victim 的 `reason=ttc` 制动次数 > 同 seed 对照”的
  严格口径。其余 6 个 seed 要么该窗口本来就有自然制动、要么几何上不构成 AEB 触发条件；
  旧表里的 3/3 是小样本，不应再引用。
- **伪指令 `injected` 20/20**：`reason=injected` 是攻击者直接下发的，恒定存在，区分不了强度。
- 包络外（≤0.35）不是“检不出”，而是**攻击本来就没发生**：真值 `bias_max_m=0`、
  攻击窗口内与对照无差异。

`brake_without_hazard`（`ttc_s≥10`）在**所有**幅度下都命中（伪指令恒定存在），同样区分不了强度。

### 6.3 早期版本对照（证明不是"构造出来的 100%"）

第一轮 300+300 批量中，A4 仅 86.67%（65/75）：原因是剧本选中了未装备 OBU 的车辆，导致不存在可对照的真实 CAM。修正生成器（A4 只挑已装备车辆，符合现实）后 A4 达到 100%。这条记录说明：

- 指标对生成器缺陷敏感，而不是对检测器"放水"；
- 修正的是**世界设定**，不是检测阈值。

### 6.4 链级结果（v0.3.0，M4）

`ReferenceDetector` 在 `alerts.jsonl` 之外输出 `chains.json`；`eval/chain_metrics.py` 对每条 truth 事件选择时间重叠最大的链，计算：

| 指标 | 定义 | 口径 |
|---|---|---|
| 节点召回 | 预测链节点 ∩ truth 节点 / truth 节点 | 告警实体级 |
| 节点精确率 | 预测链节点 ∩ truth 节点 / 预测节点 | 告警实体级 |
| 根因 top-1 | 预测 `root_cause` 等于 truth 根因（无 chain 时用 `nodes[0]`） | **首个告警实体**，不是因果推理 |
| 阶段覆盖 | 预测阶段数 / truth 阶段数（上限 1） | **告警条数骨架**，不比对阶段名称/顺序 |

> ⚠️ `ChainBuilder` 是“每条告警一个 stage、首个告警实体当根因”的**告警级骨架**，
> 输出里带 `"model": "alert_skeleton"`；`chain_metrics` 也带
> `stage_ratio_kind=alert_count_skeleton` / `root_cause_kind=first_alert_entity`。
> 这两个数值不能读成“阶段级/因果级识别能力”。

500 攻击事件实测（与 §6.1 同一批）：

- 链级：节点召回 **58.77%**、精确率 **96.70%**、根因 top-1 **60.00%**、阶段骨架覆盖 **98.00%**。

节点召回偏低是同一原因：链构建器只从告警实体提取节点，不推断未直接告警的
`attacker:`/`tenant:` 节点；根因 top-1 也受“首个告警实体”口径限制（A5/A9 的首个告警
常常是后果而非入口）。这两项都应随正式链模型替换后重算，不应写成“因果识别率”。

### 6.5 与 v0.3.0 旧基线的差异（为什么数字变了）

旧基线（`out/m6_500_500`，2026-11-02）是 **100% / 0.20%**，与新基线 **100% / 0.00%** 不可直接比较：

| 变化 | 对指标的影响 |
|---|---|
| A5 改为真实注册风暴（`core.nas` 走 AMF 队列） | 旧基线靠伪造拒绝记录，识别容易；新基线仍 50/50，但证据变成协议级 |
| A7 的 ingest provenance 改为从 `upf.route_override` 派生 | 不再依赖 `forged` 标记；`upf_route_drift`/`ingest_provenance_mismatch` 走白名单 |
| A9/A10 重写节奏与幅度 | A9 的 `cloud_control_burst` 改按“2 s 内 ≥3 批”，A10 雷达腿只偏一个站 |
| 正常集加入 9 类合法运维动作 | 旧基线没有这些样本，0.20% 是“没见过合法操作”的下界 |
| `cpm_degraded` 改为 24 帧窗口、丢包 ≥14 | 合法 QoS 调整（p≈0.15）不再误报；A6 仍稳定命中 |
| `qos_downgrade`/`subscription_tamper`/`upf_route_drift` 收紧 | 单类型退订、800 kbps 调整、DN-02 割接均不报 |

旧基线保留作对照，不再引用其点估计；新基线的 95% CI 上界 **0.76%**，已满足“区间也 ≤1%”。

## 7 局限与披露

1. 参考检测器是环境验证基线，不是最终交付模型；其 100% 不代表正式系统指标。
2. 正常集现在覆盖遮挡、切换、GNSS 峡谷、丢帧，以及 9 类合法运维动作（QoS 调整、N6 割接、
   单类型退订、token 轮换、单批车队控制、真实急刹等）；仍缺注册风暴、切换乒乓、授时漂移、
   消息重传 4 类，误检率仍应按下界解读。
3. 误检率 **0/500**，Wilson 95% 上界 **0.76%**，区间已 ≤1%；但 0 次误报不代表真实误报率为 0，
   只代表它低于当前样本量能分辨的水平。
4. 时延为检测器内部计算时间，不含网络传输与 UI；实时演示中的端到端时延单列。
5. `nef_subscription_tamper` 仍按“任何 NEF 退订”报警，正常集没有合法 NEF 运维样本，
   其误报率**未测**；A8 的 NEF 腿本身也没有下游投递，只能当 API 滥用证据。
